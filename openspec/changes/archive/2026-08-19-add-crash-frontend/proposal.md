## Why

当前服务已经具备 JVM Crash 的查询接口、统计口径和 Grafana 资源，但仓库还没有面向产品用户的前端页面。新增一个聚焦 Crash 的 Vue 页面，可以先打通“总览 → 问题 → 事件 → 堆栈详情”的可用闭环，验证现有查询 API 的用户体验和数据表达。

## What Changes

- 新增独立的前端工程，使用 Vue 3、TypeScript 和 Vite。
- 新增项目 Crash 总览页面，展示统计卡片、趋势图和问题排行。
- 支持时间范围、版本、渠道、环境、Android 版本、设备型号和问题指纹筛选。
- 支持从问题排行下钻到事件列表，再进入单事件详情和脱敏堆栈。
- 为查询接口增加前端 API 客户端、类型定义、加载态、空数据态、分母不足态、错误态和分页处理。
- 为本地开发配置前端到 Spring Boot 的 `/api` 代理，并发送当前开发期所需的 `X-Project-Id` 请求头。
- 增加前端构建、类型检查和关键页面交互验证。
- 不新增登录、项目管理、ANR、网络分析、版本对比 API 或正式多租户认证；这些不属于本次变更范围。

## Capabilities

### New Capabilities

- `crash-frontend`: 提供 JVM Crash 总览、问题列表、事件列表和事件堆栈详情的产品前端页面。

### Modified Capabilities

- 无

## Impact

- 新增 `frontend/` 前端工程及其构建、依赖和页面代码。
- 消费现有 Crash 查询接口：总览、趋势、问题排行、问题事件列表和单事件详情。
- 本地开发依赖 Spring Boot 服务运行在 `http://localhost:8080`，通过 Vite 代理避免跨域配置。
- 后端业务接口、数据模型和现有 Grafana Dashboard 不在本次变更中修改。
- 前端必须遵循现有统计语义：比例字段为 `null` 时展示“分母不足”，没有事件时展示“无数据”，不能把不可计算结果显示为零。
