# 符号表管理还原联动增量规范

## MODIFIED Requirements

### Requirement: 管理员确认替换及并发一致性
不同内容的同身份上传 MUST 报告冲突，不得静默覆盖；网页 MUST 展示摘要并要求确认，替换及删除 MUST 携带期望身份和修订号并原子校验。系统 MUST 保留操作者、时间、动作及来源审计。已取得旧 mapping 的子批可完成并记录旧来源，新子批 MUST 重新按专用优先、版本默认其次选取，单个子批不能混用文件。默认与专用登记 MUST 独立修订，管理操作 MUST NOT 重算已成功 JVM Crash；Jank 仍在上传时解析，既存事件不回算。SO 管理 MUST 只可靠唤醒该版本 Native 工作，不唤醒 JVM 主异常；mapping 管理 MUST 在 JVM 工作之外唤醒 Native 内 Java 栈。Native 已成功帧或 Java 栈不得因文件管理操作被重算。

#### Scenario: 确认替换
- **WHEN** 管理员确认替换 mapping 且期望身份与修订号仍有效
- **THEN** 该默认或专用 mapping 原子生效、修订号递增、记录审计并唤醒本应用版本尚未成功事件，已有成功结果不变

#### Scenario: 并发替换
- **WHEN** 确认期间另一操作已改变修订号或删除记录
- **THEN** 拒绝旧请求，返回冲突或资源不存在，不能覆盖新修订或误删重新上传的文件

#### Scenario: 存储故障
- **WHEN** 文件发布、元数据或适用的后台工作登记失败
- **THEN** 不报告不完整的成功操作，既有可用记录保持一致，失败产物按已确认引用关系回收

#### Scenario: 删除有读取租约的文件
- **WHEN** 管理员删除仍被在途批次读取的 mapping 或 SO
- **THEN** 新批次不能再获取该文件，在途读取可完成，最后释放后回收文件，历史处理来源与审计保留


#### Scenario: SO 在途替换
- **WHEN** 某批 Native 帧已固定旧 SO，而管理员确认替换同身份文件
- **THEN** 在途批次可使用旧文件并记录旧来源；后续未成功帧读取新修订，已经成功帧不改变

### Requirement: 上传完成与后台进展分别呈现
mapping 或 SO 上传、替换成功 MUST 只表示文件和适用工作已可靠登记，不表示历史还原完成。进度 MUST 按应用版本和 Crash 类型独立表达排队、执行、等待、退避与空闲；mapping 保持 JVM 本轮计数，SO 返回 Native 本轮已确认状态更新次数和新失败单元次数，同版本 SO 共享，不能称为该文件独有或历史完成事件数。旧无版本登记仍不适用。进度 MUST 受查看权限保护且有界，不扫描全量遥测，网页仍最多每 5 秒轮询并最多持续 5 分钟。

#### Scenario: 大数据量上传响应
- **WHEN** 有大量待还原 JVM/Native Crash 的应用上传 mapping 或 SO
- **THEN** 文件校验、保存和工作登记完成即可返回，不等待历史数量相关计算，页面区分上传结果和后台进度

#### Scenario: 显示失败或新到数据
- **WHEN** 部分事件失败或一轮完成后出现迟到事件
- **THEN** 进度说明失败和后续执行，空闲不代表全部完成；mapping 的 JVM 计数不能解释为 Native Java 栈完成数

#### Scenario: 查看 SO 上传结果
- **WHEN** SO 批次保存成功或用户查询该 SO 的后台进度
- **THEN** 页面说明已登记 Native 后台工作，返回同版本 Native 的类型、状态、发布次数和失败单元次数，不再返回 SO 不适用错误，不宣称当前事件已还原

#### Scenario: 同一事件多次增量更新
- **WHEN** 某 Native 事件在本轮因不同模块分批到达而发布多个增量
- **THEN** 发布次数可增加多次，页面明确它是状态更新次数，不冒充唯一事件数或已全部完成数

### Requirement: SO 批次全量校验与原子确认
SO ZIP 批次 MUST 使用同一 appVersion，不接收应用 buildId，完整校验候选后原子提交元数据、审计及同版本 Native 工作通知。相同模块身份与摘要 MUST 幂等，并保证适用工作可恢复，不重置扫描游标或创建无限任务；不同摘要 MUST 返回整批快照且不修改记录。确认 MUST 携带每项预期的 symbolId/revision 或不存在，任一并发变化 MUST 拒绝整批。批内同身份同内容可合并，不同内容 MUST 拒绝。提交确认未知 MUST 可重试并保留可能被引用文件，允许普通原批次重传对账。

#### Scenario: 混合新文件与冲突文件
- **WHEN** 一个 ZIP 同时包含新 SO、相同内容 SO 和不同内容的现有 SO
- **THEN** 首次请求返回完整有界冲突快照，既不新增也不替换；管理员确认后才统一创建或替换并审计

#### Scenario: 确认时新身份已被占用
- **WHEN** 用户确认快照认为某条目不存在，但另一请求已创建该身份
- **THEN** 即使其他条目修订号未变，也拒绝整批确认并返回最新冲突，不发生部分覆盖

#### Scenario: 提交响应丢失后重试
- **WHEN** 批次已提交但响应丢失，客户端用相同应用版本和 ZIP 重新执行普通上传，不提供应用 buildId
- **THEN** 按各文件当前身份与摘要返回幂等成功，不重复增加修订号或审计，也不要求客户端猜测提交结果

#### Scenario: 工作登记或提交确认失败
- **WHEN** SO 文件已暂存，但元数据、审计、Native 工作登记任一步失败，或提交确认未知
- **THEN** 不报告只完成部分步骤的成功；确认回滚不生效，确认未知保留可能引用文件，相同原包普通重传可幂等对账并恢复工作

## ADDED Requirements

### Requirement: AGP Native 调试符号包直接上传
系统 MUST 通过现有 SO ZIP 管理入口接收合法的 AGP `native-debug-symbols.zip`，支持 ABI 子目录中的 `.so.sym`、`.so.dbg` ELF 候选以及既有 `.so`，不要求用户解压、改名或重新打包，也不要求归档采用固定文件名。MUST 沿用同一应用版本、现有授权及目标模块校验，ABI 和完整 GNU Build ID MUST 来自实际 ELF，文件名、目录和后缀不得决定模块身份或证明源码信息存在。每个候选 MUST 通过现有 ELF 及符号材料校验；同身份同原始字节摘要 MUST 合并，不同摘要 MUST 按现有批内冲突或活动文件确认规则处理。全部候选 MUST 通过校验后才原子提交元数据、审计和 Native 工作通知，失败不得部分登记。符号包支持 MUST NOT 改变首次成功固定规则或扩大 LLVM 文件访问范围。

#### Scenario: 直接上传多 ABI 的 AGP 产物
- **WHEN** 管理员为明确应用版本上传包含四种受支持 ABI 子目录及合法 `.so.sym` 的原始 AGP ZIP
- **THEN** 无需改名或重新打包，逐文件从 ELF 取得实际身份，统一登记可用文件和同版本 Native 工作；上传成功不代表事件已还原

#### Scenario: 后缀和目录不决定内容身份
- **WHEN** ZIP 内 `.so.sym` 的目录名与实际 ABI 不同，或某候选不是合法 ELF、没有可靠 Build ID 或没有可接受符号材料
- **THEN** 对合法 ELF 以实际内容识别身份并执行既有目标核对；对不合法候选拒绝整批，不凭目录或后缀补造身份，不跳过坏文件报告部分成功

#### Scenario: 混合后缀与同身份文件
- **WHEN** ZIP 同时包含 `.so`、`.so.sym` 或 `.so.dbg`，其中多个文件具有相同 ABI 和完整 ELF Build ID
- **THEN** 原始字节摘要相同则合并为同一候选，摘要不同则拒绝整批；显示名称不改变身份或绕过冲突规则

#### Scenario: 与现有活动符号冲突或重复上传
- **WHEN** 原始 AGP ZIP 中的候选与该版本活动文件身份一致，且内容相同或不同
- **THEN** 同内容按既有规则幂等成功，不增加修订；不同内容返回完整批次冲突快照，只有期望身份和修订仍有效的明确确认才可整批替换

#### Scenario: 仅函数符号与更丰富调试材料
- **WHEN** 匹配 `.so.sym` 仅提供函数符号，或文件实际包含 LLVM 可用的源码信息
- **THEN** 分别只保存真实取得的函数结果或函数与源码位置，不按后缀承诺行号；之后上传更丰富材料不升级已成功帧

#### Scenario: FULL 等级包含调试文件
- **WHEN** 管理员上传 AGP `FULL` 级别生成的 `.so.dbg`，且文件通过 ELF 身份和调试材料校验
- **THEN** 直接登记并可用于后台还原实际可取得的函数及源码位置，遵守同身份冲突确认与首次成功固定

### Requirement: AGP 符号包安全与显示名称
系统 MUST 保留安全原始显示名并使用服务端受控存储键；每个候选文件名最多 255 个 Unicode 码点，超限 MUST 明确拒绝整批，不得静默截断。MUST 沿用当前压缩、实际解压、条目、路径、时间、并发及磁盘预算，继续拒绝穿越、链接、嵌套归档、重复路径、CRC/长度错误及其他不支持归档格式。

#### Scenario: AGP 符号包非法或超过预算
- **WHEN** 上传名为 `native-debug-symbols.zip` 的包包含非法路径、伪装候选或超出当前任一资源预算
- **THEN** 按现有格式或资源错误拒绝整批，清理暂存并保留既有活动记录，不因文件名或构建工具来源放宽限制

#### Scenario: 显示文件名超过数据库限制
- **WHEN** 某个候选的原始文件名超过 255 个 Unicode 码点
- **THEN** 明确报告归档不合法并拒绝整批，不能将名称或 `.so.sym`、`.so.dbg` 后缀静默截断；符合现有路径等其他预算时允许 255 个码点且不得拆开 Unicode 字符

### Requirement: Native 文件读取固定精确身份与修订
系统 MUST 只为同应用、版本、ABI 和完整 ELF Build ID 获取活动 SO 的固定读取来源，并提供身份、修订及摘要。读取期间替换或删除不得使该文件提前失效；最后释放后才可回收。没有精确身份 MUST 明确无匹配；有身份但文件不可读 MUST 表达存储故障，不回退同名库、其他版本或其他来源。管理文件仍须遵守现有授权、条件操作、审计及上传预算。

#### Scenario: 文件被删除时已有租约
- **WHEN** 管理员删除正在由后台读取的 SO
- **THEN** 在途读取可完成并记录旧来源，新读取不能再取得该活动文件，已发布成功帧不变

#### Scenario: 精确文件缺失或不可读
- **WHEN** 没有完整匹配身份，或已登记的精确 SO 文件不可读
- **THEN** 分别表达等待与可重试存储故障，不以同名 SO 或其他版本掩盖问题

### Requirement: 符号管理按处理类型可靠唤醒
有版本 mapping 创建、替换、删除或同内容重试 MUST 合并唤醒同版本 JVM 与 Native 工作；SO 对应操作 MUST 仅合并唤醒 Native。唤醒 MUST 与管理元数据可靠关联，同版本同类型通知去重，不依赖一次内存事件。旧无版本登记仍不参与。成功操作不得重算既有 JVM 成功事件、Native 成功帧或成功 Java 栈。

#### Scenario: 迟到 mapping
- **WHEN** Native 地址已经成功，但 Java 栈仍等待 mapping，管理员上传适用 mapping
- **THEN** 可靠触发该版本未成功 Java 栈处理，不要求再次上传 SO 或事件

#### Scenario: 符号删除及重新上传
- **WHEN** 某 Native 未成功单元的来源被删除后重新上传
- **THEN** 无来源期间等待，新来源可使未成功单元重试，已经成功单元及历史来源保持原值
