# Native Crash 后台符号还原设计

## Context

动机与用户确认的范围见 [提案](proposal.md)。本设计必须同时维护原始采集身份、逐帧首次成功固定和多轮状态可恢复发布，不能直接把 JVM 的整事件成功终态套到 Native。

原始符号还原实施前检查的实现与约束如下；AGP 符号包增量的实施前边界单独记录在本节末尾：

- `CrashEventProcessor` 保存 `raw_native/pending/native_symbolication_deferred`，不唤醒工作；`CrashBackgroundProcessor` 和候选 SQL 显式排除 Native。
- `CrashState`、ClickHouse 011、详情解析、网页及 MCP 只接受上述 Native 原始组合；成功态当前只允许 JVM `retrace_text`、正式归组和一份 mapping 来源。
- `CrashSymbolicationJobs` 已按应用版本合并，具备稳定 jobId、代次门禁和扫描游标；`CrashSymbolicationPublications` 以应用和事件为唯一键，固定一次 JVM 首次成功。可复用租约和重放机制，但必须扩展 Native 多轮发布。
- SO 已按 `(appId,appVersion,abi,elfBuildId)` 登记。`SymbolRegistry` 只有 mapping 选择器；SO 发布与删除不登记后台工作。当前文件租约只支持单实例。
- Native 的 `javaStack` 仅在可靠关联时采集；诊断里的 Java 线程按 Java ID 区分，Native 线程按系统 TID 区分。二者都不能因还原改变原关联事实。
- 源端 xCrash 回溯已计入 ELF load bias 和返回地址修正，传给服务端的 `relativePc` 不应再次减一或当作文件偏移。需用真实 ELF 验证四 ABI。
- 本次探索已在现有 arm64 未剥离示例 SO 上用本机 LLVM 19.0.1 将 `0x8f4` 定位到函数及源码第 7 行；剥离与未剥离产物 Build ID 相同。这里只证明本地工具与该产物，不证明设备到服务闭环或其他 ABI。

正式规范目前明确禁止 SO 唤醒、Native 发布及 Native 内 Java 栈执行 R8。本变更通过五份增量规范显式修改这些边界；JVM 既有成功与恢复语义不改变。平台路线图仍把 SO 上传列为未完成，已与当前代码及状态页不符，实施文档同步时应纠正，不修改或扩大既有验收结论。

AGP 符号包增量实施前核查：当时的 `NativeArchiveReader` 仅允许 `.so` 候选，拒绝 `.so.sym`。本地示例 AGP 产物的 `.so.sym` 后来已通过隔离上传和 LLVM 验收；复核发现 `FULL` 级别使用 `--only-keep-debug` 生成 `.so.dbg`，需要在保持安全和资源预算的前提下支持其真实 ELF 格式。文件内容和数量随构建变化，不作为固定验收期望。

## Goals / Non-Goals

目标是在现有单进程后端内完成独立、可重启的 Native/Java 还原，进度能表达部分完成，任何更新均保留已成功单元和原采集摘要，查询继续只读取有界材料。

本次不增加跨构建归组、远程符号下载、系统符号自动发现、SDK 回溯补采、内存转储、Native 源码分析/修复任务、多实例协调或自动部署。未知模块身份不能靠文件名补猜；仅有函数名的成功帧以后不升级行号。

## Decisions

### 1. 使用受控 LLVM 地址还原，继续复用 R8 处理 Java

在 `symbol.api` 提供 Native 精确身份读取租约和批量地址还原结果；文件选择、LLVM 和 ELF 细节留在 `symbol.internal`，Crash 不跨模块访问 internal 包。选择同应用、版本、ABI 和完整 ELF Build ID，不以模块名、应用 buildId、最近文件或其他版本回退。身份存在但文件不可读属于存储故障。

采用固定主版本 LLVM 19 的 `llvm-symbolizer`，使用 JSON、C++ 名称解码和内联输出，明确关闭 debuginfod；使用受控不可变文件路径，通过参数数组启动，标准输入只传规范十六进制地址，不拼接 shell。每个模块把本次尚未成功的地址去重后批量输入，不能每帧启动一个进程。禁止源码上下文读取和不受控外部调试文件路径；调试段的文件引用只能指向受控符号目录，越界引用拒绝，不访问任意宿主文件。

成功必须取得非空且非 `??` 的真实函数名；输出全部未知不算成功。存在多个内联项时作为原物理帧的一个有序结果整体保存，不能把内联项当作新增采集帧。函数名、源码文件名、有效行号和列号分别表达，行号零表示未知。源码路径只发布文件名，移除编译机绝对目录；成功/失败日志只含阶段、原因、计数、字节和耗时。

Java 使用现有 mapping 选择规则和 R8：同版本专用存在时不因不可读而回退默认。主关联 Java 栈与每个 Java 快照分别处理完整栈，保留内联、多候选和完整输出；采用现有 R8 完整输出成功语义，不把“输出未变化”当成失败。替代方案是自行实现 DWARF 或拼装 tombstone 再调用 ndk-stack，前者维护范围过大，后者丢失已有结构化身份并引入无用文本解析。

参考：[LLVM 工具文档](https://llvm.org/docs/CommandGuide/llvm-symbolizer.html)、[Android 未剥离库说明](https://developer.android.com/ndk/guides/ndk-stack)。发行修订与校验摘要已固定于后端镜像构建文件，不能使用运行时自动下载或浮动版本。

### 1.1 AGP 调试符号 ZIP 复用现有上传链路

继续使用现有 SO ZIP 上传接口和 `NATIVE_SO` 类型，由用户明确填写同一应用版本；不接收应用 buildId，也不从 ZIP 名称或目录猜测版本。支持 ABI 子目录中的 `.so.sym`、`.so.dbg` 及既有 `.so`，允许混合，不要求归档固定名为 `native-debug-symbols.zip`，也不要求用户改写构建产物。其他文件后缀仍遵守既有拒绝规则和明确的辅助文件忽略清单，不将任意 `.sym`、`.dbg` 或任意归档文件自动视为符号候选。

后缀仅决定是否进入候选校验，每个候选继续交给 `ElfInspector`，从实际内容提取支持的 Android ABI、完整 GNU Build ID、函数符号和调试信息。目录及显示文件名不决定身份；没有可靠 Build ID、仅动态导出表且无可接受符号/调试材料、非 ELF、越界或截断均拒绝整批。显示名使用原始文件名，按 Unicode 码点最多 255 个；超限明确拒绝整批，不截断或破坏字符。实际保存使用服务端受控键，不能使用归档路径。LLVM 使用租约给出的实际文件路径，不依赖显示后缀，也不执行上传文件。

批内身份仍为 `(appId,appVersion,abi,elfBuildId)`，摘要基于候选原始字节。无论后缀为 `.so`、`.so.sym` 或 `.so.dbg`，同身份同摘要合并，不同摘要拒绝整批；与活动文件内容不同时走既有完整快照与修订确认，不因改名或符号信息更丰富静默覆盖。目标 ABI/Build ID 仍成对校验；全部候选合法后才统一发布文件、提交元数据和审计，并可靠唤醒同版本 Native 工作。原 ZIP 不长期保存，任一校验失败不产生部分登记。

沿用当前全部预算：压缩 ZIP 256 MiB、multipart 260 MiB、候选单文件 128 MiB、实际解压总量 512 MiB、归档条目 256、模块身份 128、中央目录 1 MiB、路径 1024 字节/8 层、单实例上传并发 1 和统一 60 秒期限。继续拒绝 ZIP64、多卷、加密、穿越、链接、嵌套归档、重复路径、CRC 与长度不符；不因 Android 官方构建产物而绕过校验或放宽预算。

上传页面明确可直接选择 `native-debug-symbols.zip`，保留版本、权限、目标预填、整批冲突确认和上传/后台进度分离。`.so.sym` 后缀本身不证明有源码信息：只有函数符号的文件可成功还原函数名，行号继续为未知；只有文件实际含可用调试信息并由 LLVM 得到位置时才显示源码行列。页面在上传前说明优先提供包含所需调试信息的同构建产物，第三方已剥离材料不能补回。首次函数成功仍固定，后来替换为更丰富文件不升级旧成功帧。

验收使用可复现真实 ELF、AGP `.so.sym` 与 `--only-keep-debug` 生成的 `.so.dbg`，覆盖四 ABI、精确地址、仅函数符号、可用源码信息、伪装 ELF、目标不匹配、误标 ABI 目录、255/256 码点文件名、混合后缀去重/冲突、批量原子性与资源拒绝；在隔离服务内从 ZIP 上传推进未成功帧，并核对成功来源、指纹和计数不变。提供真实 AGP `FULL` 产物时另外直接验证，未提供则明确其边界。生产代码、固定夹具和证据中不提交本地生成二进制或真实设备现场。此增量不新增数据迁移、接口或运行依赖。

### 2. 处理单元与成功固定规则

| 单元 | 稳定定位 | 首次成功后固定 |
|---|---|---|
| Native 主帧 | 主栈分区、原 index | 函数/源码位置/完整内联链、SO 身份/修订/摘要、处理时间 |
| 其他 Native 帧 | 系统 TID、原 index | 同上 |
| 关联 Java 栈 | 主 Java 分区 | 完整 R8 文本、mapping 身份/修订/摘要、处理时间 |
| Java 线程快照 | Java ID | 同上 |

Native 单元还必须绑定不可变模块引用和相对 PC，防止同 index 被错配。只有函数符号也可成功；后续同 ELF 身份替换成更丰富 DWARF 不改该成功帧。采集时已有函数名不能冒充服务端还原成功。

未成功单元记录安全原因、实际尝试来源及可选 retryAt；没有匹配文件为等待，没有模块身份/相对 PC 的帧为 `not_applicable` 并说明原因，空栈也不生成虚假成功。确定性失败在同一来源不重复计算，来源身份/修订/摘要变化可再试；临时故障退避至少 30 秒。成功单元永久排除，不因原来源删除而退回原始态。

Native、Java 主关联栈和其他线程独立推进，不能要求 Native 主栈先成功才能调用 R8。一个线程预算耗尽不阻止其他可处理单元在后续轮次继续；与 JVM 辅助栈随主异常一次固定的现有规则分开。

事件内优先处理从未尝试的单元，再按最早尝试时间轮转已到重试期的单元；Native 与 Java 使用独立阶段预算，单个慢模块不能消耗 Java 阶段预算。预算耗尽而未开始的单元不冒充已尝试失败，下一轮优先获得处理机会，避免同事件靠后的模块或线程长期饥饿。

### 3. 结构化结果与摘要三态

查询使用明确的 `native_stack` 格式，保留信号、寄存器、模块、采集状态和主 backtrace。输入 DTO 和接收 schema 不扩展为接收还原字段。Native 帧保留 index、模块引用、相对 PC 和已有采集函数信息，增加 `resolution`，其状态为 `pending/failed/symbolicated/not_applicable`；成功带完整内联结果和实际 SO 来源，失败带安全原因、尝试来源及 retryAt。

关联 Java 栈与 Java 快照使用当前唯一 `stack`：未成功为原始帧，成功为完整 `retrace_text`，携带各自处理状态与 mapping 来源，不新增原始/还原双份切换。模块字典仍由主 Native 内容统一提供，其他 Native 线程按同一字典校验引用。采集时的截断和可用性与还原状态分开，不用后者掩盖前者。

事件摘要继续只用现有三态，含义限定为 Native 主栈：

- 主栈非空且每个物理帧均成功为 `symbolicated`。
- 有等待符号或临时延期帧为 `pending`。
- 没有等待帧但尚有确定性失败或不可还原帧为 `failed`；主栈为空为 `pending/capture_stack_unavailable`，没有可自动补采的任务。

详情提供主栈逐状态帧数；部分成功可与 pending/failed 共存，不新增第四个摘要枚举。Java 与其他 Native 线程不决定主栈三态。Native 顶层单份 `symbolFileId/revision/sha256` 为空，来源只归实际单元；顶层 processedAt 表示最近一次已发布实际处理时间，不伪造某一个 SO 代表整事件。

Native 始终保存原 fingerprint、`native-tmp-v1` 和 `groupingKind=temporary`；即使主栈三态为 symbolicated 也不是跨构建正式问题。列表和排行需要修改“temporary 一定未还原”的展示假设。

### 4. 按应用版本和类型复用工作，公平推进未完成单元

现有工作增加 `crash_kind`，唯一活动身份为 `(appId,appVersion,crashKind)`，继承稳定 jobId、租约代次、通知代次和游标。JVM 与 Native 分开进度和领取，单实例总体仍最多一个正在处理的版本工作，避免引入第二套队列。

SO 批次创建/替换/同内容确认和删除在元数据事务内合并唤醒 Native；mapping 管理在现有 JVM 唤醒外合并唤醒 Native。事件接收持久化成功后通知相应类型，跨库通知失败由持久轮转对账补偿。活动索引枚举 SO 和版本化 mapping，SO 唤醒 Native，mapping 唤醒两种；既有 SO 也由轮转建立工作。不查询所有应用历史事件来创建任务。

Native 工作只要求该版本存在任一活动 SO 或 mapping，缺一种不能拦住另一种。扩展任务等待态为 `waiting_symbols`，JVM 的 `waiting_mapping` 保留。选择器无精确匹配时跳过并推进，不因本版本有某一个不相关 SO 而反复处理第一页。

在 ClickHouse 最新逻辑状态维护轻量 `native_work_remaining`：只要存在有可靠输入但未成功的 Native 帧或非空 Java 栈即为真。Native 候选不能只筛 pending/failed，因为主栈成功后辅助线程可能还待处理。数据库先限定应用、版本、Native fatal、30 天保留期、最新状态及工作标记，再按持久游标取最多 100 个轻量身份；仅为这页有限事件加载主辅栈。每条按模块、构建及各单元上次来源判断是否适用，不在应用内读取全部事件后筛选。

保留当前响应预算失败减半、连续完成前缀推进、轮末回头及迟到事件发现机制。无适用来源或只有同来源确定性失败时等待，不热循环；后页能处理时继续轮转。有临时失败则带原因退避。全部单元结束或不可适用时标记没有剩余工作，原事件仍可查询。

### 5. Native 采用单调快照发布，JVM 保留一次成功终态

复用 publication 表和状态序列，新增类型、Native 基础版本和允许空单份来源的条件约束。JVM 的 `(appId,eventId)` 首次成功行保持不可替换。Native 同一事件只保留最近一代发布账本：已确认后才能以更高 stateVersion 替换；未确认时只能先重放原载荷。

每次 Native 处理从最新完整状态开始，验证所有成功单元字节、来源和原采集摘要不变，只合并未成功单元的增量。在短事务内检查当前类型/版本租约、基础 stateVersion 与已确认账本一致，分配新序列并固定整份主辅栈结果、指纹和来源。基础版本过期则重新读取再合并，不能用旧快照覆盖新成功帧。首次扩展现存 raw_native 状态以版本 0 为基础；已有增量必须按账本比较。

```text
load latest state --> resolve unfinished units --> check lease + base version
                                                    |
                                                    v
  replay exact bytes <-- pending publication <-- persist complete snapshot
          |
          v
  ClickHouse write --> read back same version + digest --> confirm
                                                          |
                                                          v
                                                next incremental snapshot
```

Native 成功、失败和延期状态都通过这一发布路径；不能沿用 JVM 的独立失败写入来产生覆盖成功的迟到快照。没有实际变化不登记新版本。确认丢失、重启或过期执行者恢复时先读账本，同版本同字节重放，不重选 SO/mapping。对账确认和本轮进度增加在同一事务内按版本/摘要条件执行，重复确认不重复计数。事件超出 30 天不重放恢复。

复用单份 4 MiB、全局未确认 100 条/16 MiB 背压；替换已确认 Native 账本前不得存在该事件未确认载荷。历史 SO/mapping 来源以原身份、修订和摘要保留；软删除不破坏成功来源。PostgreSQL 账本不长期保存所有轮次的完整栈。

### 6. 运行、输出与查询预算

以下是实施默认上限，需自动化和隔离环境验证，不作为已通过的容量承诺：

| 资源 | 默认上限与超限行为 |
|---|---|
| 后台 | 每次最多 100 个候选；一次版本工作开始新任务的总期限 30 秒 |
| LLVM | 单实例最多 1 个进程、不排队；每模块调用至多 2 秒，每事件 Native 总期限 10 秒且不超过本轮剩余时间 |
| Linux 工具进程 | 用资源限制启动器限制地址空间 512 MiB、CPU 3 秒；墙钟超时终止、强制回收并确认退出后才复用许可 |
| 进程管道 | stdout/stderr 并发消费，stdout 每次最多 512 KiB、stderr 最多 16 KiB；触限终止，不保存或输出原始 stderr |
| Native 输出 | 每物理帧完整结果最多 32 个内联项、16 KiB JSON；主辅 Native 新结果合计最多 512 KiB；超限保留原始帧并记录失败 |
| Java 输出 | 每条完整栈 32 KiB，关联 Java 栈与快照总计 256 KiB；沿用 R8 有界许可和等待，不截断输出伪造成功 |
| 发布 | 整份主辅快照 4 MiB；全局未确认 100 条/16 MiB，触限退避 |
| 文件 | 租约内只读不可变 SO/mapping；沿用上传和解压预算，不因还原放宽输入 |
| 查询 | 沿用前台时间窗、行数、扫描/内存/响应预算；列表、概览、趋势、Issue 不读主辅栈或诊断 |

已有成功单元不能因下一轮预算回退为原始帧；如果完整新快照超限，减少本轮新增成功单元后发布，或保留旧快照并标记本轮失败，不丢已确认成功。应避免内存中构造超过预算的完整进程输出。

后端镜像固定 LLVM 与 Linux 资源限制启动器；开发环境显式配置工具绝对路径。工具不存在、版本不支持或资源限制不可用时只延期 Native 地址还原，Java 和事件接收继续可用，不伪造成功。macOS 本机试跑只用于结果格式验证，资源隔离以 Linux 后端镜像测试为准。

### 7. 进度、网页与 MCP 契约

沿用 `GET /api/v1/apps/{appId}/symbols/{symbolId}/crash-symbolication`：版本化 mapping 返回既有 JVM 进度；SO 返回同应用版本 Native 工作的 `crashKind=native`、state、publishedCount、failedUnitCount、updatedAt、errorCategory。publishedCount 是本轮已确认的状态更新次数，同一事件分轮可多次，不命名为已完成事件数；failedUnitCount 是本轮已确认的新失败处理单元次数，不是当前失败存量。同版本 SO 共用进度，轮询仍不超过每 5 秒一次、持续 5 分钟。旧无版本登记仍不适用。

mapping 上传也会唤醒 Native Java 处理，但 mapping 页的 JVM 计数不代表 Native 已完成。Native 详情以已保存的逐单元状态为准，SO 上传响应只说明文件及工作登记成功。

网页分别展示 Native 主栈、关联 Java 栈、其他 Native 线程、Java 快照的采集和还原事实，提供按实际缺失来源进入 SO/mapping 的入口。Java 关系未知仍为未知；Native 事件不因此显示 JVM 分析任务按钮。成功来源删除后仍可读，不查当前活动文件来替代历史来源。

Agent HTTP/MCP 保留工具名称和 stack/diagnostics section，新增严格解析 `native_stack` 与逐单元来源，继续 contentDigest 续读；任一增量改变相应 section 内容后，旧摘要续读明确失败并要求重读，不拼接两轮证据。鉴权、资源隐藏和大小预算不放宽。

## Risks / Trade-offs

- 符号文件同 Build ID 但内容不可信，或 DWARF 解析消耗异常：匹配只证明身份；使用受限子进程、不可执行的只读文件、禁用外部发现、限制输出和失败退避，成功仅表达取得了函数信息。
- 只还原函数名后无法升级行号：这是已确认的首次成功固定语义，页面明确源码位置缺失，不把上传更丰富文件暗示为修正历史成功。
- 不同单元最终来自不同修订：来源归单元而不是事件，整份快照固定本轮全部来源，避免误标全栈同一文件。
- 主栈成功而辅助未完：后台用独立剩余工作标记选取，页面分开展示，不能仅用摘要 symbolicated 判定整事件终态。
- 多轮状态写放大：只发布真实变化、每事件最多一份未确认载荷，不重复处理成功/同来源确定性失败，测试有限规模和混合查询的资源边界。
- 分页与迟到事件：持久游标轮转而非不断重置第一页，独立验证不相关符号占据前页、重启和早于游标的迟到事件。
- 跨库确认未知：保留原字节及代次门禁；未确认账本不能被下一轮覆盖，迁移前排空。

## Migration Plan

1. 在隔离库验证新增 Flyway/ClickHouse 迁移，保持旧 JVM 状态、publication 字节/来源、文件身份和遥测计数。不能改写 V15～V19 或 ClickHouse 011，不能清库。
2. 停止新上传与接收、排空在途 publication，停止旧后端并等待有效租约释放/过期；备份同一时点 PostgreSQL、ClickHouse 和符号卷。迁移前置检查发现有效租约或未确认结果时明确阻止切换。
3. 新迁移为现有版本工作补 JVM 类型并按类型建立唯一约束；扩展 Native 发布/状态格式约束和轻量工作字段。旧 raw_native 只在读取与后台首次处理时转成新模型，保留原捕获摘要、地址、线程身份和 `native-tmp-v1`，不适配更旧 raw_only 数据。
4. 协调后端、网页、MCP 及带工具的镜像切换。新查询统一输出 native_stack；已有原始 Native 可无需重传 SO、mapping 或事件，由活动索引轮转恢复。保留部署开关，使新版本可暂停地址处理而继续接收和读取已存结果。
5. 用隔离真实 ELF 与合成事件验证 SO 先到/后到、mapping 先到/后到、辅助独立补齐、同内容重试、删除/替换、确认丢失和应用隔离；复核问题指纹和总览计数完全不变，再决定是否执行用户另行授权的环境部署。
6. 回退不能仅替换旧二进制。出现 Native 新格式后，旧代码不认识该状态；回退应停止新流量并恢复同一备份点的管理库、遥测库、符号卷和匹配应用版本。备份后新增数据的无损回退不在本次保证内，必须明确演练结果。
