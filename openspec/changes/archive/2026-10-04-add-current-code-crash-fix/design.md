# 当前工作区崩溃分析与本地修复设计

## Context

动机与删除范围见 [提案](proposal.md)。用户在 2026-10-03 选择新建此变更，并采用当前工作区、包含未提交修改的方案。

已核对的实现基线：

- 后端 AnalysisTaskService/AnalysisEvidence 依赖 BuildMapping，未登记时阻断，证据包含提交 SHA；AnalysisRunService 按该 SHA 核验结果。
- V6～V13 已建立构建登记、任务、Worker、Run 与停止审计；任务及 Worker 的仓库外键使删除配置不能仅靠隐藏表单完成。
- Python host.prepare 从仓库映射校验 origin 并导出指定提交，state 保存私有恢复事实；read/search/submit 已有边界与实际读取核验，尚无编辑入口。
- 前端 AnalysisAdminPanel 保留构建登记及固定 performance/DeepSeek 文案，CrashAnalysisPanel 提供单事件任务与宿主指引。
- Skill 已内置 Worker、锁定依赖和启动脚本；打包明确列出 repositories.example.json，需要随本变更删除。

原 [add-local-crash-analysis](../2026-10-04-add-local-crash-analysis/tasks.md) 为 46/46 的历史交付记录，本变更不改写它。本设计是待实施目标，现有接口与数据仍以当前代码和正式 API 为准。

## Goals / Non-Goals

目标：只保留当前代码模式；省去构建/提交/远端登记与仓库映射；允许有限本地修复；保护工作区已有改动；保留真实证据、引用、变更及失败恢复。

首版边界：单事件、单任务、单本地项目、一次有限补丁；继续复用 Java 控制面与 Python 工具，不新增任务服务或执行器框架。修复工具只修改普通文本源码/测试文件和创建必要测试文件，不支持删除、移动、重命名文件或任意 Shell。

非目标：还原崩溃时的完整源码历史、自动确认历史根因、分支管理、提交/推送、MR、发布、云端执行、模型管理、整个宿主进程的权限沙箱。

## Decisions

### 1. 以工作区为唯一源码来源

默认根据宿主命令当前目录，用只读 Git 根目录查询确定项目；只用 Git 定位与列举文件，不读取 HEAD、提交或 origin，也不 fetch。项目有新建且未提交代码时同样可用。项目外执行必须明确 `--project <绝对路径>`；宿主可通过当前工作目录或用户明确项目位置提供此参数，不以 Skill 所在目录作为项目默认值。

已跟踪文件按磁盘当前内容采集，包括用户未提交修改；追加 Git 未忽略的普通源码/测试文件。尊重项目忽略规则，并显式排除 .git、.agents、Skill 内置 Worker/.venv、构建产物、秘密与私有状态。路径限制、签名/凭据识别及脱敏复用现有策略。

替代方案：只读取当前分支提交会丢失用户正在处理的代码，也重新引入提交依赖；从 Skill 位置推断无法适用于全局安装。仓库 JSON 映射则保留了用户明确要求删除的配置。

### 2. 源码快照与必要摘要

prepare 将实际工作区复制为私有、受限的本次材料，生成 snapshotId。保留内部文件清单、内容摘要及只读原文，用于引用重建和修改前检查；向平台只提交必要身份与报告信息，不上传仓库或本机绝对路径。snapshotId 与稳定 requestId 在领取前保存；领取把 snapshotId 固定到 Run，同请求不同快照拒绝。

采集前后核对文件清单及内容；发现读取期间变化则拒绝本次准备，不能发布部分快照。上限保留 120 秒、五万候选文本文件、256 MiB 普通文本、单文件 16 MiB；常见二进制附件在读取前按扩展名排除，Git 清单另限 32 MiB。完整排除清单私有保存，宿主仅收到最多 100 条/16 KiB 示例、总数及截断标记；超限诊断只包含资源类别、至少观察到的数量和上限；不读取越界链接、未支持子模块/LFS 或排除材料。read 保持 200 行/8192 字节，search 保持 100 条/五秒，累计材料 512 KiB。实际 read 才能证明源码引用。

修复前核对待修改文件以及本次实际读取的相关文件仍与快照原文一致，分析后项目变化明确报冲突。只要求人工解决或显式开始新尝试，不自动刷新材料继续套用旧结论。

替代方案：不固定材料而直接反复读取实时文件更省一次复制，但会使行号和内容在同 Run 漂移，无法可靠保护修改。保留 snapshotId 与内容摘要是文件正确性所需，不是把 commitSha 改名继续要求配置。

### 3. 精简平台输入与源码登记

新任务仍由已授权 eventId 创建。后端直接使用 crash.api 的单事件快照准备有界证据，不访问 BuildMapping；异常链完整冻结，现有 mapping 可用时附还原文本和符号版本，不可用时附真实原因。保留原事件 buildId 是为了既有采集、详情和 mapping 服务，但不在任务上重复保存构建源码绑定。

删除 analysis-builds API、登记服务/模型/UI 与本地 repositories 配置。新的 Worker 身份只限定应用，不保留 repositoryId/analysisType 这种本模式可固定推导的字段；不引入云端或其他修复类型枚举。凭据仍仅存摘要、30 天到期、可撤销，Session/CSRF、应用访问控制及旧停止门禁复用。

任务直接固定当前模式，无需网页 modelConfig 管理；新证据 schemaVersion=2，新结果 schemaVersion=3。Run 只增加必要 snapshotId，用于领取幂等及结果归属。提交结果移除 commitSha 与仓库字段，保留 evidenceId、snapshotId、分析语义、源码引用、执行来源与用量未知；结果 schema 的新旧差异必须被后端严格识别。

替代方案：只删除表单仍会被任务前提和外键阻断；自动将 APK 绑定最新 SHA 则会伪造历史源码身份。仅原始符号不清不能成为虚假根因或自动修复依据。

### 4. 明确修复授权并通过有限工具写入

Skill 对“分析”只执行只读流程；“分析并修复/修复此任务”等明确用户指令才启用本次本地编辑权限。prepare 的本地 `--repair` 开关表示宿主已取得该授权，不是平台证明用户指令的机制；可信宿主须遵守 Skill。Worker 凭据只是平台材料身份，不能自行授予本机源码写入权。

宿主使用当前模型分析，并生成有限结构化补丁。Python 增加 apply 命令，只接收相对路径、读取过的修改区间、预期原文及替换内容；前置摘要和引用事实由 Python 从私有快照核验。补丁最多 20 个文件、合计 1 MiB；新文件只允许必要源码/测试，并确认原先不存在。含秘密脱敏位置的修改、二进制、排除路径、链接和目录越界拒绝。

宿主本任务源码读取及编辑均通过材料/修改工具，不使用其他编辑器绕过一致性检查。已读原文与替换区间须精确匹配，不接受模型提供的整文件覆盖来抹去未读取内容。工具检查原文件、权限与当前租约，保留文件权限并逐文件原子替换，不修改 Git 暂存区。

替代方案：让宿主直接用任意文件工具写入更省接口，但无法复用读取事实、取消和冲突保护；增加网页审批服务则多出首版不需要的授权链路。用户明确修复后直接完成相关修改和验证，不再次要求例行确认。

### 5. 本地修改日志和部分失败

写入前在现有私有状态目录保存补丁摘要、必要原文及写后摘要，逐文件记录状态；使用同任务锁并拒绝同项目的并行工具写入。文件锁只能协调本工具，不能锁住所有编辑器，因此写入前仍必须重新核对原文与路径。

不宣称多文件修改为一个文件系统事务。发生错误或中断时恢复检查实际内容：与原文一致为未写入，与工具写后摘要一致为已写入，否则为外部变化/冲突。同一补丁重试只对账，不能再次修改；不同补丁或未知部分完成不在同 Run 自动继续。仅在内容仍能证明完全属于本次工具写入时可安全撤回该文件；无法证明时保留并明确要求人工处理，不执行 git reset/clean 或整体覆盖。

租约、取消或撤销发生后拒绝新的写入；已发生修改保留真实记录，不能因取消静默重置工作区。材料清理和宿主停止不等同于撤销修改。补丁确认、平台回传各自独立，平台响应丢失沿用原结果摘要，不重新分析或应用。

替代方案：无日志恢复容易重复编辑；自动整体回滚会覆盖用户随后修改。日志直接扩展 RunState，不引入事件总线或通用事务层。

### 6. 修复验证与报告

宿主按当前项目 AGENTS 和明确修复请求，使用其已有终端能力执行必要编译/测试。Python 不新增任意命令执行接口；项目文档和源码是材料，不可授权读秘密、运行无关脚本或发布。报告记录实际命令、退出码、有限脱敏摘要，命令中的本机绝对路径用项目相对位置或占位符表示，敏感参数不回传；宿主报告的验证标为 HOST_REPORTED，不伪装为服务端或独立 CI 验证。验证针对补丁写后的代码；提交前核对本次已修改及实际读取文件，若验证期间它们再次变化，保留命令真实结果并标明该结果不能证明当前工作区通过。

报告中的 repair 分开记录 NOT_REQUESTED、NOT_APPLICABLE、APPLIED、PARTIAL、CONFLICT、FAILED；验证独立为 PASSED、FAILED、NOT_RUN，并给出未执行原因。修改事实、文件相对路径及前后内容摘要由工具日志生成，不能由模型补造。源码引用仍绑定修改前的分析快照；新代码差异作为修改事实展示。

只分析没有修改；证据不足或问题在当前版本已不存在可为 NOT_APPLICABLE，但不能据此声称历史 APK 的问题已修复。report SUCCEEDED 仅代表合法报告已保存。验证失败允许保存事实；断网后本地修复事实不能消失，即使平台回传仍未知。

维持原九十秒租约、二十秒心跳、十分钟期限。耗时验证可因期限未完成，此时如实报告本地已修改及验证中断，不接受迟到提交。宿主模型/验证进程无法由 Python 强制控制，必须遵守当前任务停止要求并保留未知；不通过延长或移除门禁掩盖这一边界。

替代方案：新增 CI 服务会扩大首版范围；仅输出“修复成功”则无法区分未修改、改动完成及测试通过。

### 7. 网页与自包含 Skill

移除 AnalysisAdminPanel 的构建表单、列表、版本与更正分页，保留应用 Worker 凭据管理。事件页面仅提供当前代码任务、分析/修复自然语言示例及真实结果，明确网页不自动启动本地修复。报告展示源码快照、局限、修复文件、验证与停止事实，不出现新的提交输入。

Skill 和 launcher 继续从自身定位 Python，项目从宿主当前目录/显式位置定位，两者独立。移除 repositories.example.json、映射变量和旧执行器示例；生产包按当前模块清单更新。保留平台 URL、环境 Worker 凭据及默认私有状态目录；不增加网页模型选择或宿主注册。

替代方案：保留两个执行模式和两套配置会增加分支及学习成本，与用户只保留当前代码的选择冲突。

## Risks / Trade-offs

- 当前工作区无法证明崩溃历史源码 → 报告明确 CURRENT_WORKSPACE 语义、符号局限及未知项，不使用原堆栈行号冒充当前引用。
- 快照采集或写入时用户编辑 → 前后校验、已读文件核对、逐文件原子写入、部分修改日志与冲突拒绝；不承诺全项目或多文件原子性。
- 用户指令和整个宿主进程不能由 Python 独立鉴证 → 只接受可信宿主明确修复调用，标注能力边界；不把本地工具关闭当进程已停止。
- 测试读取项目脚本可能有副作用 → 遵循项目规则及已授权必要验证，保留脱敏结果；不把源码建议当执行授权。
- 当前质量仍可能不足 → 证据不足不写入，进行真实分析/修复和人工差异核验；旧五例质量结论及限度保留。

## Migration Plan

1. 原变更作为已实施基线，本变更为后续唯一执行模式；不同时归档/同步两份相互冲突的分析能力。实施记录明确替代关系，旧任务清单不重置。
2. 先停止创建新任务，结束原活动 Run，并完成必要停止核验；不能给未知停止伪造确认，也不能用新凭据绕过门禁。旧冻结任务不能转换到当前工作区执行，终态报告和审计保留。
3. 追加未使用编号的 Flyway 迁移，解除任务与凭据对构建/仓库的外键，删除新流程不再使用的分析 build_id/mapping_revision、凭据 repository_id/analysis_type 等列及构建登记表；原证据/结果 JSON 原样保留。不得修改 V6～V13 或删除原 Crash/符号服务的 buildId。
4. 后端、Python/Skill、前端同步切换新证据/结果契约，旧执行 API/CLI 删除，不建设旧模式运行兼容层。旧终态报告可作为历史数据只读查看，不能重新执行或改写来源。
5. 通过必要 PostgreSQL 迁移/门禁测试、工作区/补丁恢复测试、前端和独立包检查，再完成 Performance 当前代码的实际宿主有限验收。部署仍默认功能关闭，试点明确启用；本轮规划不部署云端。
6. 若需要回退，先关闭新任务与写入，保存本地补丁及恢复记录、结束 Run 并核验停止。此迁移删除旧登记结构，旧二进制不可直接回滚复用当前数据库；恢复旧方案必须使用经过核验的迁移前备份，另行处理切换后的新报告，禁止直接覆盖生产数据。

## 2026-10-03 本地配置增量

按用户新增要求，Skill 根目录 config.local.json 是固定本地配置入口，仅平台根地址及应用 Worker 凭据。Python 有界读取并在任何任务副作用前校验，秘密不交付宿主，含凭据文件要求当前用户所有且权限 600。原环境入口成对整组覆盖文件，防止混合不同平台身份；后台看护只接收前台同次已解析配置，不重新读取文件。Git 忽略和源码排除覆盖该配置；打包脚本不读取实际配置，固定生成空模板。更新通过排除本地配置的解压命令保留用户内容，不能承诺任意解压软件不会覆盖。功能与 HTTP 契约、修复/停止模型无关，现有质量边界保持有效。

## 宿主直接读取与修改（2026-10-04）

用户已授权实施：宿主自行搜索、读取当前项目，明确修复时自行修改并验证；Python 仅维护受保护本地配置、项目定位、单任务领取、冻结 Crash 证据、租约、结构化结果核验与幂等回传。移除全仓库采集、源码总量/文件数量门禁及 search/read/apply/revert 入口，不把宿主置于统一操作系统沙箱。

新 claim 仅 requestId；新报告 schemaVersion=4 绑定 evidenceId/runId，不创建 snapshotId。数据库旧 snapshot_id 及版本 1～3 的历史报告保持原值和只读展示，不增加迁移。新报告源码片段由宿主提供，Python 核验安全相对路径、范围、片段格式和脱敏摘要，并只对引用位置做提交时当前文件匹配检查；CURRENT_MATCH/CURRENT_DIFFERENT/UNAVAILABLE 不能作为宿主实际读取证明。

修改文件和测试命令明确 HOST_REPORTED，不再补造 Python 写前日志、修改前摘要或 workspaceUnchanged。只读准备拒绝提交已修改事实；--repair 仅记录用户明确修复意图，不能限制宿主其他工具。失联/取消/到期阻止 Python 继续获取证据或回传，宿主须自行停止本任务读写/验证；UNKNOWN 停止仍需管理员真实核验。

保留配置、网络响应、引用/报告及本地状态大小限制；这些用于有界协议处理，不限制宿主源码读取或模型预算。更新安装包并保留 config.local.json，Python 版本 0.4.0；旧活动/待回传记录不升级执行，须旧工具先完成或停止核验。通过真实 Git、受控 HTTP、后端 PostgreSQL 和前端测试分别验证，不重跑已完成真实任务或擅自修复 Android 业务。
