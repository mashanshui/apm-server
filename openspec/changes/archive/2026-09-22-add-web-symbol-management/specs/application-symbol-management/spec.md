## Purpose

为应用成员提供网页符号表管理能力，通过构建标识精确关联单份 Android mapping，允许管理员安全纠正错误文件，同时保障应用隔离、上传幂等、并发替换一致性及解析期间的文件可用性。

## ADDED Requirements

### Requirement: 网页管理应用构建符号表

系统 MUST 提供当前应用的符号表分页列表、精确构建筛选、单文件上传和替换入口。列表 MUST 展示构建标识、原始文件名、大小、摘要、当前版本、上传人及更新时间。系统 MUST 仅接受单个文本 mapping，不接受 ZIP、SO 或多文件合并；以 `appId + buildId` 唯一定位记录，不按应用版本模糊匹配。

#### Scenario: 首次注册构建
- **WHEN** 管理员上传合法 mapping 并提供当前应用内尚未注册的有效 buildId
- **THEN** 系统保存并返回可用记录，后续解析能够精确取得该文件

#### Scenario: 同内容重试
- **WHEN** 同一应用构建再次上传相同字节的文件
- **THEN** 返回当前记录且不增加版本或重复文件

### Requirement: 上传和替换必须授权并校验

系统 MUST 使用 Session、CSRF 和应用成员授权；成员可查看元数据，仅 OWNER/ADMIN 可上传或替换。系统 MUST 校验实际文件大小、内容格式、完整 mapping 可解析性及受支持格式版本，不得仅凭扩展名或延迟加载对象创建成功接受文件。失败 MUST 不改变当前可用版本。请求与日志 MUST NOT 泄漏完整 mapping、堆栈、凭据或内部路径。

#### Scenario: 越权上传
- **WHEN** 普通成员、其他应用用户或仅持有事件 App Key 的调用者尝试上传
- **THEN** 系统拒绝写入且不暴露其他应用的符号表内容

#### Scenario: 文件不合法或超限
- **WHEN** 上传空文件、非法 mapping、不受支持版本或实际大小超过配置上限
- **THEN** 返回明确错误，旧版本仍可用，临时文件被清理

### Requirement: 管理员确认替换及并发一致性

不同内容的同构建上传 MUST 首先报告冲突，不得静默覆盖。网页 MUST 展示新旧摘要并要求确认；确认请求 MUST 携带期望版本。系统 MUST 原子切换当前版本并记录操作者、时间及新旧摘要。已取得旧版本的解析可完成，替换成功后开始的解析 MUST 使用新版本；单次解析不得混用版本。

#### Scenario: 确认替换
- **WHEN** 管理员确认替换且期望版本仍为当前版本
- **THEN** 新版本原子生效，返回新版本号并保留操作记录

#### Scenario: 并发替换
- **WHEN** 管理员确认期间另一请求已经切换当前版本
- **THEN** 返回版本冲突且不覆盖新版本，页面要求刷新后重新确认

#### Scenario: 存储故障
- **WHEN** 文件写入或元数据事务失败
- **THEN** 不发布不完整文件，既有版本不受影响，失败产物能够回收
