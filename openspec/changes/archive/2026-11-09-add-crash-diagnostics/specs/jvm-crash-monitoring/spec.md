# JVM Crash 诊断上下文规范增量

## ADDED Requirements

### Requirement: JVM Crash 携带有界诊断上下文
系统 MUST 在现有 JSON v2 的 `crash.diagnostics` 接收诊断上下文，覆盖崩溃线程、其他 JVM 线程和堆栈、当前进程可读的 logcat、内存快照、文件描述符、进程与设备环境。诊断 MUST 只附属于 JVM fatal Crash，不成为新的事件类型或统计事件。诊断缺失 MUST 不影响满足现有契约的核心 Crash 接收；`app_start` MUST 不携带诊断。

每个诊断分区 MUST 区分成功、部分成功、不可用和跳过，使用安全原因类别表示超时、权限限制、资源不足及读取失败，并标记截断；成功得到的空结果 MUST 与采集失败区分。快照 MUST 保留原采集时间，跨启动补传 MUST NOT 重新采集现场或修改原事件身份。

#### Scenario: 接收完整诊断
- **WHEN** 合法 Crash 携带符合大小、字段和身份约束的全部诊断分区
- **THEN** 主异常和诊断作为同一事件接收，accepted 数和 Crash 统计只增加一个逻辑事件

#### Scenario: 只有核心异常
- **WHEN** 合法 Crash 没有 diagnostics，或因资源不足仅保留核心异常
- **THEN** 继续接收主异常，详情明确表示诊断未采集，不伪造空快照

#### Scenario: 部分日志缓冲区不可读
- **WHEN** 某个 logcat 缓冲区因权限或系统限制无法读取，其他分区成功
- **THEN** 保留已采集内容和各分区真实状态，不将不可读内容表示为成功的空日志

#### Scenario: 新进程补传旧事件
- **WHEN** 新进程恢复上一次 Crash 并上传或重试
- **THEN** 保留原 eventId、发生时间、sessionId、UUID processId、数值 PID、线程身份、采集时间和原诊断内容

### Requirement: 崩溃线程与其他线程准确区分
Android SDK MUST 记录崩溃线程的名称、Java 线程标识、状态、主线程标记和可获得的系统 TID；其他 JVM 线程 MUST 包含名称、Java 线程标识、状态、优先级、daemon 标记和可取得的 Java 帧。Java 线程标识 MUST 与系统 TID、进程 PID 和 UUID `processId` 分开表达。系统 MUST 按线程对象身份排除崩溃线程，MUST NOT 按线程名称去重或排除同名线程。

其他线程数量、单线程帧数和总编码字节 MUST 有界，存在可取得的主线程快照时 MUST 优先保留。未取得帧的线程 MUST 保留空帧事实，MUST NOT 生成虚假的调用帧或将其认定为没有运行。线程状态和堆栈 MUST 表述为崩溃处理期间的近似快照，不承诺跨线程原子一致。

#### Scenario: 后台线程崩溃
- **WHEN** 命名后台线程抛出未捕获异常，主线程仍存在
- **THEN** 正确标记崩溃线程并优先保留其他线程中的主线程快照，不把执行采集工作的线程当作崩溃线程

#### Scenario: 线程名称重复
- **WHEN** 崩溃线程与另一个活线程同名
- **THEN** 仅排除崩溃线程对象，另一个线程仍可按其 Java 线程标识独立保存与展示

#### Scenario: Java 堆栈为空或达到数量上限
- **WHEN** 部分线程没有可取得的 Java 帧，或快照超过数量、帧数、字节上限
- **THEN** 空堆栈如实保留；超限部分有明确截断标记，已知总数和未知总数不混用

### Requirement: 诊断补充不破坏 Crash 本地可靠保存
SDK MUST 在补充采集前先将有固定身份的核心异常可靠写入可恢复的本地记录；补充结束后才允许上传冻结的最终记录。补充期间进程终止，下一次启动 MUST 能恢复已保存核心异常，并将未完成分区表示为中断或未采集。SDK MUST NOT 先上传核心事件，再使用相同 eventId 通过重复上报追加诊断。

异常处理线程等待诊断 MUST 有明确总预算，外部日志进程 MUST 有超时、字节限制和清理边界。超时后的迟到结果 MUST NOT 修改已冻结、已入队或已确认的事件。辅助采集异常和受控内存不足 MUST 尽力降级，不阻止已有核心记录的恢复和原异常处理器的委托；MUST NOT 声称所有虚拟机损坏或真实 OOM 均可可靠保存。

#### Scenario: 采集中断后恢复
- **WHEN** 核心异常已保存，诊断完成前应用进程被终止
- **THEN** 下次启动用原身份恢复并补传核心记录，不使用新进程现场补写旧事件

#### Scenario: logcat 超时
- **WHEN** 日志读取未在预算内结束
- **THEN** 异常处理线程结束等待，关闭本次日志子进程资源并记录超时，不无限等待后再委托原异常处理器

#### Scenario: 上传与补充采集竞争
- **WHEN** 周期上传恰好发生在诊断补充期间
- **THEN** 上传器不能读取尚未冻结的记录；最终记录或中断恢复记录只形成一个逻辑事件

#### Scenario: 采集结果迟到或内存不足
- **WHEN** 辅助采集在记录冻结后返回，或在受控测试中抛出内存不足错误
- **THEN** 迟到内容被丢弃，已保存核心记录保持有效，不能产生第二份事件或覆盖已确认内容

### Requirement: 诊断内容遵守大小和隐私约束
SDK MUST 对完整事件序列化后的 UTF-8 JSON 执行单事件和可装入批次的字节预算，并优先保留核心异常及安全状态说明；线程、日志、内存原文和 FD 均 MUST 有独立资源上限。服务端默认单事件上限 MUST 保持 256 KiB，MUST NOT 因新增诊断无界扩大批次、查询或后台输出预算。服务端 MUST 按既有解析和事件校验边界拒绝非法诊断或超限输入，MUST NOT 通过静默丢弃已提交诊断来返回 accepted。

日志、线程名称、路径及其他文本 MUST 在客户端持久化前和服务端存储前按规则脱敏，至少处理可识别凭据、邮箱、手机号、URL 与用户私有路径；结构化数值和构建身份 MUST NOT 作为自然语言误脱敏。完整事件及原始诊断 MUST NOT 进入排障日志；必要成功/失败日志只记录安全类别、数量、字节和耗时。未知、不可读与零值 MUST 分开表达，内存数值 MUST 明确单位及采集口径。

#### Scenario: 含中文长日志的完整事件超限
- **WHEN** 原诊断内容使完整 UTF-8 事件超过预算
- **THEN** SDK 在冻结前有标记地裁剪可选内容并重新验证字节数，不能只按字符数或 gzip 大小判定，也不能直接丢弃整个核心 Crash

#### Scenario: 非法客户端直接提交超限诊断
- **WHEN** 请求绕过 SDK，包含超限或结构非法的诊断
- **THEN** 服务端按既有永久错误语义拒绝相应输入，不静默裁剪后确认成功

#### Scenario: 诊断包含凭据和私有路径
- **WHEN** logcat、线程名或 FD 路径包含令牌、邮箱、URL 或用户私有文件名
- **THEN** 本地持久记录和服务端可见材料均不保留测试中约定的敏感原值，排障日志不输出诊断原文

#### Scenario: 内存读取失败与合法零值
- **WHEN** 一项内存值读取失败，而另一项合法值为零
- **THEN** 前者表示缺失及原因，后者保留零值，Java 堆已用量与 Java 堆 PSS 不被混为同一指标

### Requirement: 诊断持久化和详情查询不改变主异常语义
系统 MUST 将诊断非堆栈上下文与主异常可变还原材料分开保存；同一事件重试 MUST 保留首次已确认上下文，不通过重复上传替换或追加诊断。首次接收 MUST 可靠保存该次已提交的核心异常、其他线程材料和上下文后才确认 accepted，部分写入恢复 MUST 保持同一定位和原始采集内容。对于本变更新接收且已保存内容摘要的事件，同 eventId、构建和时间却提交不同核心异常或诊断的请求 MUST 返回永久事件错误 `CRASH_CONTENT_CONFLICT`，MUST NOT 将新内容拼接到原初始状态；同内容正常重试继续遵守既有幂等和部分接受规则。

现有按 eventId 的授权详情 MUST 返回诊断及其他线程的当前堆栈和实际处理状态，主异常仍只提供当前单份 `stack`。概览、趋势、Issue 和事件摘要 MUST NOT 返回或读取完整诊断载荷；诊断和其他线程 MUST NOT 参与主异常指纹或增加统计事件。详情请求 MUST NOT 采集设备现场或执行实时还原；历史无诊断记录 MUST 明确缺失，不重建或读取旧表补齐。

#### Scenario: 诊断内容不同但主异常相同
- **WHEN** 两次 Crash 主异常归组特征相同，其他线程、日志、内存或 FD 不同
- **THEN** 沿用既有指纹规则归组，并分别保留各事件诊断，不按诊断内容拆分问题

#### Scenario: 后台还原和重复上传
- **WHEN** 主异常完成还原后相同 eventId 再次上传，或 mapping 被替换
- **THEN** 首次确认的诊断保持不变，不恢复已替换的主异常原始副本，也不增加统计

#### Scenario: 列表与授权详情
- **WHEN** 查询概览或事件列表，或无权限用户尝试读取某事件诊断
- **THEN** 列表查询保持轻量投影，无权限详情与资源不存在保持一致，不泄露诊断

#### Scenario: 部分写入后更换诊断内容
- **WHEN** 初始状态已保存而事实未确认，同一定位重试却更改核心异常或诊断
- **THEN** 返回可定位的永久内容冲突，保留原材料；随后原内容重试仍可完成缺失写入并只确认一个事件
