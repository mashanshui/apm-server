## MODIFIED Requirements

### Requirement: 单事件任务与最小平台身份
系统 MUST 允许 OWNER、ADMIN、DEVELOPER 按所属应用单个 JVM fatal eventId 创建任务，VIEWER 只读；校验 Session、CSRF、成员关系和幂等键。事件必须有可读取的当前堆栈，pending、failed、symbolicated 均允许创建任务，不再要求成功事件保留原始异常链，也不在创建请求内调用 Retrace。新任务 MUST 仅支持当前工作区模式，不要求 APK 源码登记、提交 SHA、远端或混淆声明。Worker 凭据 MUST 按应用授权、有限期、可撤销且仅存摘要，不接受查询 Token、App Key 或 Cookie 替代。

#### Scenario: 无登记创建任务
- **WHEN** 合法成员为没有源码登记或 mapping 的待处理事件创建任务
- **THEN** 冻结当前原始材料并记录符号局限，不以缺少 mapping 阻断任务

#### Scenario: 权限与幂等
- **WHEN** VIEWER 创建、Worker 跨应用访问、凭据撤销或相同幂等键关联不同事件
- **THEN** 拒绝不合法操作，不泄漏数据，不新增重复任务

#### Scenario: 使用已还原材料
- **WHEN** 事件成功后仅保留完整还原输出，mapping 文件已删除
- **THEN** 仍能创建分析任务，使用已存输出及实际来源，不要求恢复原始副本或重新还原

### Requirement: 冻结单事件证据与当前代码语义
系统 MUST 冻结单事件当前已发布堆栈及其格式、持久化状态、当前指纹、实际处理来源、片段 ID 和摘要，并限制大小、脱敏和保持不可变。当前证据 schemaVersion MUST 为 3，报告 MUST 仅采用版本 4，原始与还原材料 MUST 显式区分；不得把还原内容标作原始异常链。MUST 保留完整原因链及内联/多候选，不通过截断满足大小限制。同一当前契约内，后续后台还原或 mapping 管理操作 MUST NOT 改写已冻结证据。证据和结果 MUST NOT 含源码登记、commitSha、repositoryId、origin 或登记绑定；buildId 仅为事件事实，报告必须说明当前工作区与历史 APK 可能不一致。任务从创建时 MUST 标明当前契约，服务端、网页及 Worker MUST 删除旧证据/报告版本的解析、只读展示、自动升级和执行适配；旧版本记录不接入当前任务接口，也不因此被自动重写或清空。

#### Scenario: 当前代码已经改变
- **WHEN** 当前文件行号或逻辑与冻结堆栈不一致
- **THEN** 根据当前代码记录差异和未知，不把历史行号当成当前精确位置

#### Scenario: 不完整材料
- **WHEN** 证据超限、待还原或无法对应当前源码
- **THEN** 超限明确失败，其他可用材料携带局限继续分析；不能形成可靠修改时不修复

#### Scenario: 冻结后后台完成
- **WHEN** 任务冻结 pending 原始材料后该事件还原成功
- **THEN** 原任务仍使用原证据，新建任务可以冻结固定还原输出，两者分别保留摘要和来源

#### Scenario: 只接受当前证据与报告格式
- **WHEN** 工具或页面收到非版本 3 的证据，或非版本 4 的报告
- **THEN** 明确拒绝不支持的格式，不执行旧版解析、展示或转换；当前版本租约与停止门禁保持生效

#### Scenario: 旧任务不接入当前接口
- **WHEN** 存储中仍有不属于当前契约的任务，用户或旧工具通过当前接口请求其内容或执行
- **THEN** 当前列表和领取不包含该任务，直接访问返回任务不存在语义，不返回旧只读内容，不升级或删除旧记录
