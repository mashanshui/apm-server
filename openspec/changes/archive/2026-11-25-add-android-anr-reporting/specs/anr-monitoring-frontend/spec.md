# ANR 网页增量规格

## Purpose

在应用工作区提供独立的 ANR 查询入口，支持按时间、版本与判定来源查看事件数量和受影响设备，并在授权详情中呈现同次 ANR 的堆栈与诊断现场。

## ADDED Requirements

### Requirement: 在应用工作区查看 ANR 列表与统计

Web MUST 在应用侧栏提供 ANR，使用共享控制台和应用身份。列表 MUST 支持时间、版本和判定来源筛选及有界分页，并展示相同筛选下的 ANR 事件数和影响设备数。列表 MUST 明确显示消息超时判定与系统错误状态判定两个来源。

#### Scenario: 按版本和来源查看统计

- **WHEN** 用户调整时间、版本或判定来源
- **THEN** 统计与列表重新查询同一筛选，列表从首页开始，并按实际返回呈现加载、空数据、结果或错误状态

#### Scenario: 应用切换与过期响应

- **WHEN** 用户从 ANR 列表或详情切换应用，旧请求之后才完成
- **THEN** 页面进入目标应用 ANR 列表，清空旧应用筛选、事件和分页状态，旧响应不能覆盖新应用页面

### Requirement: 展示单次 ANR 原始诊断

Web MUST 在授权详情展示发生时间、版本、判定来源、主线程 Java 栈、消息与延迟、`ANR_INFO`、系统 trace、内存、Logcat、文件描述符、进程和设备信息。trace MUST 标为「系统 trace（采集片段）」，单独展示。已有内容、部分采集、截断和缺失 MUST 按分区可区分，诊断文本 MUST 以纯文本呈现。

#### Scenario: 有 trace 且系统说明缺失

- **WHEN** 事件有主线程栈、部分系统 trace 和内存信息，且 `ANR_INFO` 未获取到
- **THEN** 主线程栈和 trace 分别可阅读，trace 显示实际来源及已知截断，`ANR_INFO` 显示未获取到，合法内存零值照常展示

#### Scenario: 各诊断分区独立失败

- **WHEN** 部分 Logcat 缓冲区、FD 或其他分区因权限、超时或中断而不可用
- **THEN** 对应分区展示实际状态，其他分区和事件基本信息仍可查看

#### Scenario: 直接访问单事件

- **WHEN** 用户从列表打开或通过地址直接进入自己的应用 ANR 事件
- **THEN** 页面单独请求该事件详情，并展示可复制的原始设备、启动和进程 ID

#### Scenario: 详情文本带有网页标记

- **WHEN** 日志、系统说明或 trace 有看起来像 HTML 的文本
- **THEN** 控制台显示文本内容且不执行其中的标记或脚本

### Requirement: 查看 ANR Java 还原状态并切换原文

事件详情 MUST 分别显示主线程 Java 栈和系统 trace 的 Java 还原状态、可用的原因及实际 mapping 来源。分区有还原结果时 MUST 可切换原文与还原视图，两者均按纯文本展示。系统 trace 的还原视图 MUST 标明还原范围是 Java 帧，并保留原有采集片段及截断说明。

#### Scenario: 有 Java 还原结果及部分原始内容

- **WHEN** 主线程栈已经还原，系统 trace 只有部分 Java 帧还原成功
- **THEN** 两分区显示各自状态和实际 mapping 来源，可分别切回原文，trace 还原视图保留线程、锁记录和 Native 帧

#### Scenario: 等待 mapping、失败或不适用

- **WHEN** 分区没有匹配 mapping、还原失败或没有可处理 Java 帧
- **THEN** 页面继续显示原始内容和对应状态，有可用结果的其他分区仍可切换
