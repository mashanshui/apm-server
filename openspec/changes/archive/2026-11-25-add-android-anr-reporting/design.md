# 技术设计

## 当前实现

外部 SIGQUIT 由 `AnrDumper` 先交给 Java 采样和 Matrix 判定，再转交 ART Signal Catcher。消息超时可立即发出 `SIGNAL_ANR`，进程错误状态判定在后台轮询，因此 trace 与 ANR 判定能以任一顺序到达。目前 `AnrComponent` 为每份结果单独生成 ID，后台读取的活动文件可能被后一次捕获覆盖。Crash 已有有界诊断采集和脱敏规则，Android 聚合层已有传输会话，服务端批次已有按事件分派和部分接受语义。

## 设计目标与范围

- 可确认归属时，把主线程 Java 栈和 ART 系统 trace 片段呈现在一条事件下。ANR 成立的依据仍是 Matrix 原有两条判定路径。
- 在原进程取得尽可能多的诊断，允许部分成功，保证重启补传和查询看到一致的原始身份和冻结现场。
- 首版覆盖现有主进程、API 23+、arm64-v8a 采集边界。详情包含系统 trace 采集片段，以及主线程栈和 trace 中可识别 Java 帧的还原结果。完整转储、应用退出记录采集、额外的全量 Java 线程快照、Web 锁链解析、问题聚类、Native 地址符号还原和 ANR 率留待独立需求。

## 设计决策

### 一次采集对应一个事件

1. 在外部信号的工作路径创建本次采集标识并记录发生时间，由 Java 采样、错误状态轮询及 Native trace 发布共用。Matrix 判定所用的主线程栈、前后台、队首消息和时间差按本次尝试冻结，异步回调携带该次标识及数据。确认为 `SIGNAL_ANR` 时，用该标识作为报告 ID 和上传 `eventId`。
2. 保持 Signal Catcher 转交顺序和 Matrix 首次写入截取口径。截取结果按本次采集发布到应用私有的独立文件，后台接收一个已经封存的路径，而非重新打开公共活动文件。Native 侧只有在本次转交与截取结果的归属可证实时才发布关联，重叠信号无法区分时将受影响的 trace 标记为不可用，继续向 ART 转交信号。手动 trace 使用独立来源。
3. trace 先到时按采集标识有界暂存，覆盖 Matrix 原有最多 40 次、间隔 500ms 的错误状态查询窗口。只有收到 `onAnrDetected` 才建立待上报事件。核心报告先持久化，相关材料随后按采集标识补齐。单独 trace 继续作为本地报告，未获确认的关联候选随原窗口和容量策略释放。

采集标识贯穿回调可避免按近似时间和文件名猜测归属。关闭期间对已落盘的核心报告按中断规则恢复。保留已有手动报告、锁解析和 debugger 结果供本地使用。

### 现场采集与上传冻结

- 系统错误状态判定从本次匹配的记录提取 `longMsg`，保留 Matrix 对其他 UID 的原有处理。消息超时判定立即保存核心事件，由独立后台任务限时补查。补查只接受同 UID、同 PID 的 `NOT_RESPONDING`。重叠捕获无法确认归属、无记录或文本为空时，记录不可用。补查结果只填充 `anrInfo`，判定来源使用原回调值。
- 从 Crash 共享内存、Logcat、FD、进程和设备采集规则、受限读取与脱敏。ANR 采集器使用自身任务与超时资源，从后台尽早发起采集，不等待 trace 就绪，避免拉长现场采样间隔。共享实现放在两个能力都可用的基础层，保持 Crash 既有采集行为和 JSON 契约。ANR 详情中的线程内容由主线程 Java 栈与 ART trace 提供。
- 以核心报告持久化完成后最多 5 秒作为首版补充现场窗口，磁盘、进程退出及生命周期提前结束按实际取得的数据冻结。每个完成分区可独立提交，截止后忽略迟到结果。恢复时读取原进程已经提交的材料，未完成分区记录 `interrupted`。采集进度及已冻结字节原子持久化，恢复和重试可重复执行。
- ANR 检测默认关闭，上传另设显式开关。全量接入使用共享 `TransportSession`，独立接入可沿用本地模式或提供传输配置。待上传项按规范化服务地址和凭据摘要绑定目标，磁盘不记录凭据原文。未配置可识别目标时仍可本地采集。关闭上传保留已登记项，恢复相同配置后在保留期内继续重试。旧版纯本地报告继续提供本地读取。
- 后台上传只读取有界待确认集合，沿用公共确认、永久拒绝及退避。成功或重复确认更新上传状态，本地报告保留期继续由现有报告策略管理。客户端项目升级、进程退出或全量关闭不重写原版本、会话、进程身份或已冻结载荷。

### 公共批次信封与大小约束

- 使用 Schema v2 的 `eventType=anr` 和 `anr` 对象。判定来源以单值 `message_timeout` 或 `process_error_state` 表示，由 SDK 原 `fromProcessErrorState` 映射。主线程 Java 栈、队首消息、原消息时间差及 cgroup 沿用当前实际采集语义。队首消息和时间差归属不明时按缺失处理。
- `anrInfo` 和 `trace` 携带受限 UTF-8 文本及状态。trace 的来源固定为现有 ART 首次命中写入片段，`truncated` 表示已知裁剪，片段未被裁剪时仍按片段展示。上传使用单份文本表示。日志、内存、文件描述符、进程、设备分区沿用 Crash 的单位和状态语义，分别返回 `capturedAt`、`status` 与适用的 `reason`、`truncated`。
- SDK 以未压缩且实际转义后的 UTF-8 计算大小，拟定单事件 240 KiB、服务端 256 KiB。首版上传预算为主线程栈 24 KiB、`ANR_INFO` 8 KiB、系统 trace 96 KiB、通用诊断合计 96 KiB，队首消息和 cgroup 各 4 KiB，并在最终序列化后再次验证总大小。超限先裁剪辅助内容，保留事件身份、判定来源、状态和可用核心栈。服务端未知结构按现有批次语义处理，合法结构中的字段或分区越界按事件拒绝。gzip 继续使用现有线上和解压上限。
- 客户端上传材料持久化前与服务端写入前沿用 Crash 可识别规则，清理消息、`ANR_INFO`、trace、日志中匹配到的凭据及敏感路径，FD 保存安全类别。采集、关联、冻结、接收及失败日志只记录状态、受控原因及计数。

### 接收、存储与 Web 查询

- 扩充现有 `EventEnvelope` 与批次分派。使用独立 ANR 模块处理结构验证、诊断校验和持久化。将摘要字段及详情字段保存在同一逻辑事件行，写入前以 `appId + eventId` 校验已有事件并串行裁决同应用的同 ID 写入，沿用单实例接收边界。同步写入使用稳定去重身份，首次有效内容固定，遇到结果未知按公共可重试响应处理。读路径在数据库中也保证按该身份去重，避免写入确认丢失或数据库合并前导致重复统计。
- 使用 ClickHouse 版本化迁移和现有查询资源预算，首版按发生时间保留 30 天。按应用、时间、版本和来源下推查询并只投影所需列。概览分别统计事件和匿名设备。列表按 `occurredAt DESC, eventId DESC` 游标分页，游标绑定应用和归一化筛选条件。详情通过应用和事件 ID 定位一条，仅此接口读取诊断正文。应用和时间条件进入列表与概览的存储访问路径，按 ID 的查询在保留期内受现有资源限制。
- Web 路由采用 `/apps/:appId/anrs` 与 `/apps/:appId/anrs/events/:eventId`。查询接口为 `/api/v1/apps/{appId}/anrs/overview`、`/api/v1/apps/{appId}/anrs/events`、`/api/v1/apps/{appId}/anrs/events/{eventId}`。概览与列表共享时间、应用版本和判定来源条件，默认最近 24 小时，最长 30 天，时间区间采用包含起点、不含终点。复用现有 HTTP 会话、应用查看权限、请求取消及鉴权错误处理。诊断视图复用 Crash 的通用分区展示，事件切换时重置各分区状态。

### 后台 Java 符号还原

- 接收先持久化脱敏后的原始栈和 trace，再按现有规则确认。ANR 后台任务按事件的 `appId`、`appVersion`、`buildId` 通过 `SymbolRegistry.acquireVersioned` 取得固定 mapping 租约。同版本专用优先，仅在专用登记不存在时使用版本默认。文件缺失、不可读或明确无匹配时，保留原文和受控原因。还原使用同一次尝试取得的固定修订，避免中途替换引起混用。
- 主线程栈来自 Matrix 的 `StackTraceElement.toString()`，适配成 Retrace 可识别的帧格式。系统 trace 按线程识别有完整边界的 Java 帧，仅对有把握的连续帧段执行 Retrace。保留 R8 返回的内联帧和多候选，按原帧段位置呈现。其余输入行，包括线程头、ID、锁记录、Native 帧、截断残行及未知行，通过原文保留。帧段边界不可靠时，使用该段原文。
- 使用独立于上传和详情请求的有界后台处理，复用符号服务的限并发和输出限制。ANR 通过事件落库后的唤醒和有界轮转对账发现候选，覆盖 mapping 晚上传、发布确认丢失与服务重启。候选按应用、版本和保留期过滤并分批读取，忙或临时失败按退避重试。Crash 的任务、进度与发布仍使用既有领域记录。
- 单次 Retrace 输入按线程和连续帧段切分，考虑辅助 Retrace 单次最多 32 KiB 的输出限制。对单线程、单分区和整次处理另设总字节、帧数及时间预算，防止内联或多候选累积使结果膨胀。确定归属的帧段可发布部分结果，未完成段沿用原文。无可辨识 Java 帧时返回不适用，只有未变化输出时保留原文，避免将整份 trace 显示为已还原。
- 主线程栈和 trace 分别持久化状态、受控原因及实际使用的 mapping 文件标识、修订号和摘要。可用的还原视图作为派生结果单独保存，确认后的结果和来源保持固定，重复执行可按事件和分区对账。事件详情查询返回原文和各自可用的 Java 还原视图，列表、计数、事件发生时间和身份仍以原始事件记录为准。

## 风险与取舍

- 原进程可能在保存第一份材料前退出 → 验收区分已持久化核心可恢复与尚未持久化无报告，禁止补造。
- 系统错误列表反映查询当时的状态，trace 也可能只有部分内容 → 分区上报真实状态和采集时间。按同次标识关联并在无法证实归属时放弃可疑附加信息。
- 同次捕获可能并发叠加，诊断内容较大 → 采样、文件、大小与查询分别设预算，连续和反序回调通过设备或注入覆盖。列表和概览验证数据库扫描及投影范围。
- 混合 trace 的格式随 Android 版本变化，mapping 选错也可能产生合理外观的错误结果 → 只处理能识别的 Java 帧，保留原文和实际 mapping 来源，用混淆 Release APK 验证同版本、同构建匹配和还原后锁行归属。

## 上线与回退

先准备 ClickHouse 迁移并部署可接收 ANR 的后端，再部署 Web 入口，最后由宿主发布并显式启用 SDK 上报。需要回退时先关闭 ANR 上报开关，保留本地待确认项和服务端数据，确认旧客户端及现有批次流量正常后按现有发布流程回退服务与网页。
