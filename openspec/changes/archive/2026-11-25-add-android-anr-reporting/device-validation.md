# ANR 跨端验收记录

## 系统输入 ANR

- 环境：Android 15、arm64-v8a 的 Pixel 6 模拟器，以只读方式启动；示例应用使用独立测试包名和临时凭据。
- 服务：本地隔离的后端、PostgreSQL 16 和 ClickHouse 26.7；数据库使用临时容器，完成相应迁移。
- 系统证据：点击受控阻塞入口后再次发送输入，系统记录输入分发超时约 5 秒，并确认应用无响应。
- 采集结果：消息超时分支生成一条 `SIGNAL_ANR`；主线程栈和 ART trace 均包含示例测试入口。`ANR_INFO`、trace、Logcat、内存、进程和设备分区采集成功，文件描述符分区部分采集。
- 一致性：客户端已冻结记录、ClickHouse 和授权 HTTP 详情中的事件 ID、发生时间、应用版本、构建、会话、进程身份及判定来源一致；trace 原文与本地同次记录一致。统计为 1 个事件、1 台设备。
- 网页：通过真实后端与隔离浏览器会话检查列表和详情，确认目标事件、发生时间、版本、构建、判定来源、测试入口及各诊断分区可见。页面截图另见 `screenshots/`，其中截图使用虚构接口数据。
- 手动 trace：先于上述系统 ANR 触发手动 trace，本地报告保存成功，服务端 ANR 事件数保持为 0。

## 断网重启与补传

- 断网：关闭模拟器 Wi-Fi 和移动数据，并确认没有默认网络；再次触发系统输入分发超时后，事件及诊断现场冻结在待上传队列，服务端计数保持为 1。
- 重启：离线强制停止并重新启动示例应用，进程 PID 发生变化，原事件仍在队列中；重启前后冻结的事件载荷完全一致。
- 响应丢失：重新联网后，经隔离故障代理转发实际上传；真实后端确认写入一条后，代理主动断开连接并丢弃响应。客户端保留待确认事件，随后按退避策略重试；后端报告接受 0 条、重复 1 条，客户端收到确认后清空队列。此处响应丢失由代理模拟，不代表已覆盖自然网络故障的全部情况。
- 一致性与去重：数据库和授权详情中，事件 ID、原发生时间、版本、构建、会话、进程身份、判定来源及完整载荷与离线冻结事件一致。列表和统计由 1 条增加到 2 条，新增事件只出现一次，设备数保持为 1。
- 授权：另一应用的有效成员可以查询其所属应用的概览，访问本事件详情返回 HTTP 404，未取得诊断数据。

系统超时、进程重启、设备队列、HTTP、数据库和授权查询均来自上述模拟器与隔离部署的实际操作；响应丢失由故障代理注入，不能替代其他网络条件和设备环境的验证。

## 上传生命周期回归

- 主机 JVM：ANR、Crash 和 SDK 模块测试通过；真实本机 HTTP 测试覆盖 gzip、503 退避和 403 死信，队列测试覆盖无效确认、重复错误项、响应丢失、目标凭据变化、默认不上传与历史纯本地报告不回灌。
- 模拟器：ANR 模块仪器测试 4 项通过、1 项按 API 条件跳过，覆盖主次进程判断、Java 采样、手动 trace 及采集器关闭重开；借用传输会话在 ANR 关闭后仍可用。
- 示例应用：隔离 runner 下的 3 项仪器测试通过，验证独立 ANR 使用自有会话上传、全量 SDK 遇 503 后显式刷新重发相同事件，以及连续手动 trace 不串档。上传测试使用受控 Matrix 判定回调，真实系统触发另见前述跨端验收。
- 遗留写入：会话关闭后，即使旧 trace 尚未产生预期写入，采集器也可重新启动；旧写入与后续写入在无法区分时不关联。主机 C++ 状态机测试覆盖迟到和缺失写入；缺失写入导致未消化计数持续存在时，后续 trace 仍可能因归属不明确而无法关联，ANR 核心采集不受此限制。

## 混淆 Release 与 mapping

- 构建：使用独立包名和临时签名构建启用 R8 的 Release APK；设备确认该应用不可调试。APK、mapping 和构建标识来自同一次构建，受控测试方法的类名和方法名均已混淆。
- 真实触发：在 Android 15、arm64-v8a 的 Pixel 6 模拟器启动该 APK，通过具名工作线程持锁并发送第二次输入；系统确认约 5 秒的输入分发超时。事件由真实 SDK 上传至隔离后端和 ClickHouse。
- 上传前：授权接口与实际网页均显示主线程栈和 ART trace 中的同一次混淆测试方法，两个分区处于等待 mapping 状态；trace 包含主线程等待锁和具名持锁线程。
- 晚上传：上传该 APK 对应的 mapping，服务端保存文件的 SHA-256 与构建产物一致。主线程分区还原成功，trace 分区还原出测试源码方法并因存在未识别输入标记为部分还原；两个分区均指向同一符号文件、修订 1 和相同摘要。
- 原文与布局：还原前后原事件和身份完全一致，线程头、锁记录及其所属线程逐行一致；真实 trace 中 98 行 Native 记录的原文和顺序均未改变。实际网页可分别切换两个分区的 Java 还原和原文，回切后的完整文本与原始接口内容一致；事件数和设备数均保持为 1。
- 补充样本：[后端真实 R8 测试](../../../../backend/src/test/java/com/shanshui/apmserver/anr/internal/application/AnrJavaRetraceTests.java)还覆盖内联、多候选、跨线程边界、锁与 Native 行、截断残行和预算限制。设备覆盖仅限上述模拟器与本次 trace 片段。

本记录不包含应用凭据、设备标识、日志正文或堆栈原文。模拟器结果不代表其他 Android 版本、ROM 或真实设备均已验证。
