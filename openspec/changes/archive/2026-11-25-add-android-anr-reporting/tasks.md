# 实施任务

## 1. 后端批次与应用查询

- [x] 1.1 在 Schema v2 信封和批次分派中加入 ANR 载荷，校验两类判定来源、原身份、互斥字段、分区状态及 UTF-8 JSON 限额，复用应用鉴权和存储前脱敏。用真实 Servlet 或接口集成测试验证 gzip 与普通 JSON、混合批次部分接受、应用凭据与包名不匹配、错误身份、限额、脱敏及无回显。
- [x] 1.2 新增 ClickHouse 版本化迁移和独立 ANR 写入，成功后确认持久化，固定首次有效内容。用真实 ClickHouse 验证迁移、同应用并发重复、相同 ID 不同应用、同 ID 后续不同内容、响应丢失及失败恢复，检查每个应用内的逻辑事件只落一份且原内容可读。
- [x] 1.3 实现按应用授权的概览、列表、详情查询和筛选绑定游标。用真实数据库验证时间边界、版本及来源筛选、去重设备数、同时间分页、越权、游标误用与详情单条读取。提供代表性数据量的查询计划和资源结果，检查列表与概览的过滤、排序、聚合及分页均下推，列表投影不读入诊断正文。
- [x] 1.4 适配 Matrix 主线程栈和 ART trace 的 Java 帧，复用 R8 Retrace 并限定帧段、线程及整份结果的预算。用实际 R8 和混合 trace 样本验证无 `at` 前缀的主线程栈、跨线程边界、内联与多候选、锁记录、Native 帧、截断残行、格式不明与输出超限。
- [x] 1.5 接入 ANR 后台还原、版本化 mapping 租约、有限候选扫描和派生视图幂等发布。用集成测试验证接收与查询不等待还原、同版本专用优先、同版本默认回退、其他应用或版本隔离、mapping 晚上传和服务重启恢复、确认丢失、修订来源固定及部分失败。验证事件原文、计数和应用授权语义。

## 2. Android 采集、冻结与补传

- [x] 2.1 将同次采集标识传递给 ANR 判定和 trace 发布，归档独立文件并隔离手动来源。用 ANR JVM 或仪器测试验证原有前后台阈值及轮询、两个回调先后交换、相邻捕获和延迟归档不串档、归属不明时丢弃关联、只有 trace 时不产生上传事件。
- [x] 2.2 在系统状态判定与消息超时后台补查中提取 `ANR_INFO`，从 Crash 复用内存、Logcat、FD、进程和设备采集与脱敏。用受控输入覆盖匹配的 `longMsg`、延时可见、其他 UID 或 PID、空值与并发歧义，验证分区超时、权限失败及零值，同时检查 ANR 不调用全量 Java 线程采集且 Crash 原有测试通过。
- [x] 2.3 实现核心先落盘、诊断限时补齐和原子冻结，限制 UTF-8 JSON 大小并记录截断状态。用队列测试覆盖核心提交前后退出、带部分分区重启、预算耗尽、迟到回调及重试不改原版本、身份和载荷。
- [x] 2.4 接入公共批次会话、上传开关、刷新、退避和有效确认，保护原目标归属。用 SDK 装配、HTTP 与队列测试验证按需本地模式、按需与全量上传、有效和无效确认、403 或永久拒绝、503、响应丢失、关闭重开和凭据变更。验证借用资源所有权、默认无上传和历史纯本地报告不回灌。

## 3. Web 列表与事件详情

- [x] 3.1 新增应用侧栏 ANR、统计和分页列表，接入时间、版本及判定来源筛选。用路由和组件测试验证加载、空结果、失败、上一请求迟到、分页和切换应用回到目标 ANR 列表。
- [x] 3.2 新增可直达的 ANR 详情，展示主线程栈、系统 trace 采集片段、`ANR_INFO`、Logcat、内存、FD、进程及设备状态，提供原始身份复制。用组件测试验证截断、缺失、独立分区失败、有效零值、纯文本渲染和复制反馈。执行前端测试、类型检查和生产构建，在标准 PC 视口留存列表及详情截图。
- [x] 3.3 在主线程栈和系统 trace 中显示各自的 Java 还原状态及 mapping 来源，并支持原文和还原视图切换。用组件测试验证部分还原、等待、失败、不适用、切回原文、事件切换重置和纯文本渲染。在详情截图中检查范围提示与原始内容可达。

## 4. 三端联合验收

- [x] 4.1 在支持平台用示例实际触发系统输入 ANR，并以 Android 系统记录确认触发。在隔离的真实后端与 ClickHouse 上核对 SDK、HTTP、数据库与 Web 的事件 ID、发生时间、版本、判定来源、主线程栈和诊断分区。实际取得系统 trace 的样本须验证原始测试线程标记与本次事件对应，实际未取得的分区按真实状态留证。
- [x] 4.2 使用设备上已落盘的真实 ANR 验证断网重启、原身份补传、服务端写入后响应丢失和重复确认。核对重新联网后列表与统计只新增一条，并验证手动 trace 无上传事件、无权应用无法查看诊断。记录设备、系统版本、自动化与真实系统证据各自的覆盖范围。
- [x] 4.3 使用真实启用 R8 混淆的 Release APK 触发受控系统输入 ANR，在隔离部署先查看原始堆栈，再上传该 APK 对应构建的 mapping。核对服务端和 Web 的主线程栈及 trace Java 帧还原为测试源码的方法，线程和锁记录仍对应原位置。检查来源修订、原文回切及事件统计保持一致，对设备未输出的 Native 帧等格式用 1.4 的样本证据补充。
