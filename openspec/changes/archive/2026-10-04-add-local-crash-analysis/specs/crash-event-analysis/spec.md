## Purpose

为应用开发者提供基于单次 JVM 崩溃事件、固定源码版本和不可变证据的分析任务能力，使分析结论可核对、权限可隔离、失败可恢复，并为后续云端执行保留不依赖本地目录的输入输出契约。

## ADDED Requirements

### Requirement: 按事件授权创建分析
系统 MUST 允许应用 OWNER、ADMIN、DEVELOPER 以单个 eventId 创建分析任务，应用成员可查看，VIEWER 不得创建。网页写操作 MUST 校验 Session、CSRF 和当前角色；服务端 MUST 推导事件构建和指纹，不接受跨应用关联。任务 MUST 关联原 Issue 但只声明解释该事件。创建 MUST 支持幂等键，同键不同输入冲突。

#### Scenario: 开发者创建单事件任务
- **WHEN** DEVELOPER 对所属应用的 JVM 事件提交合法请求
- **THEN** 创建或返回同一幂等任务，不查询同组其他事件，不把单事件结论扩展为整个 Issue 根因

#### Scenario: 越权和重复请求
- **WHEN** VIEWER 创建、非成员访问、CSRF 缺失或相同幂等键携带不同事件
- **THEN** 分别拒绝操作；非成员响应不泄露资源存在，重复同内容请求不新增任务

### Requirement: 核验构建与分析前提
系统 MUST 仅允许 OWNER/ADMIN 登记已核验的应用构建、仓库标识、完整提交 SHA、混淆状态和核验依据。更正 MUST 校验期望版本且保留历史。任务 MUST 固定登记版本；本地源码不存在、提交不匹配或混淆状态未知时不得调用模型。已混淆构建 MUST 取得对应 mapping 的成功还原文本；未混淆构建不强制 mapping。缺失前提 MUST 显示阻断原因并支持补齐后显式重新检查，不自动降级为仅堆栈分析。

#### Scenario: 混淆构建缺少 mapping
- **WHEN** 事件构建已登记为混淆但 mapping 缺失或还原失败
- **THEN** 任务处于阻断状态且无模型调用，原 Crash 详情仍可查看

#### Scenario: 未混淆与源码版本检查
- **WHEN** 未混淆构建有核验映射且本地对应提交可读取
- **THEN** 无 mapping 也可开始分析；本地只有其他提交时明确阻断

#### Scenario: 并发更正映射
- **WHEN** 管理员使用过期期望版本修改映射
- **THEN** 返回冲突，不覆盖当前映射或已有任务输入

### Requirement: 冻结有界单事件证据
系统 MUST 冻结选中事件的必要元数据、异常链、可用还原文本、符号表版本及摘要、构建登记版本和完整源码提交，并赋予证据 ID、版本和内容摘要。证据 MUST 脱敏且限制大小，不包含模型密钥和不必要设备身份。超限 MUST 明确失败，不静默截断。证据准备期间的取消和输入版本变化 MUST 防止旧结果发布为可执行。

#### Scenario: mapping 后续替换
- **WHEN** 分析证据生成后同构建 mapping 被替换
- **THEN** 原分析继续引用原证据，新的分析使用新快照，日常详情使用当前 mapping

#### Scenario: 大小超限或准备取消
- **WHEN** 完整证据超过配置限制或任务在准备期间被取消
- **THEN** 不发布部分证据的可执行任务，不调用模型

### Requirement: 结构化分析与可追溯历史
系统 MUST 保存候选根因、证据引用、指定提交下的源码位置、未知项、风险和验证建议。系统 MUST 区分执行失败与分析完成但证据不足，不以置信度判定修复成功。结果 MUST 验证引用归属与结构；源码引用必须经过受信执行器核验。重新分析 MUST 追加记录，历史查询 MUST 有界分页。到期内容 MUST 显示已过期，不伪造空结果成功。

#### Scenario: 无法唯一定位
- **WHEN** 分析正常结束但多候选堆栈或代码信息不足以确认根因
- **THEN** 保存证据不足结论及缺失项，执行状态可为成功，不制造唯一根因

#### Scenario: 非法引用
- **WHEN** 回传引用其他任务证据、越界源码路径或不存在的证据片段
- **THEN** 拒绝结果并保留可诊断错误，不显示为有效定位

### Requirement: 分层验收
系统 MUST 分别记录真实链路验收与独立质量评估。可控崩溃测试只能证明链路和已知样本行为，不能作为线上定位率证明。质量评估 MUST 包括未用于调试的根因样本与证据不足样本，并记录人工核对结果及用量。

#### Scenario: Performance 测试入口
- **WHEN** 使用明确写出测试异常的崩溃按钮完成分析
- **THEN** 记录构建、提交、eventId 和实际结果，标记为闭环验收，不计作独立质量能力证明

### Requirement: 宿主执行来源与停止事实
新宿主任务 MUST 使用 HOST_AGENT 策略，结果 MUST 使用新版本并记录执行来源；旧配置及旧结果 MUST 仅保留历史真实事实。模型、版本和用量不可核验 MUST 标为未知或自报，不强制冒充固定 DeepSeek/OpenCode。有效分析结果完成与本地工具关闭、宿主停止 MUST 独立记录；宿主停止未知 MUST 保持原重试和身份门禁，管理员确认须保存实际核验审计。

#### Scenario: 新任务与历史
- **WHEN** 新建宿主任务或查看旧 OpenCode 结果
- **THEN** 新任务记录宿主策略，旧结果保留原来源，不改写固定证据或模型事实

#### Scenario: 正常报告与未知停止
- **WHEN** 合法宿主报告完成但宿主停止不可核验
- **THEN** 报告可为成功且可读，停止显示未知，不能自动新尝试
