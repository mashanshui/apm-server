## Purpose

为已登录用户提供按项目成员关系隔离的项目工作区，使其能够发现自己可访问的项目、创建新项目并在权限允许时维护项目基础信息。

## ADDED Requirements

### Requirement: 用户只能列出有成员关系的项目

系统 MUST 只返回当前登录用户拥有有效成员关系的项目，并为每个项目返回项目标识、名称、描述、当前用户角色和更新时间。项目列表 MUST 支持按项目名称或项目标识搜索，并明确区分加载中、有结果、无搜索结果、没有任何项目和请求失败状态。

#### Scenario: 查看有权限的项目列表

- **WHEN** 已登录用户打开项目列表
- **THEN** 页面展示该用户有成员关系的项目及其角色，不包含其他项目

#### Scenario: 首次使用且没有项目

- **WHEN** 已登录用户没有任何项目成员关系
- **THEN** 页面显示创建首个项目的空状态和明确的创建入口

#### Scenario: 搜索项目

- **WHEN** 用户输入项目名称或项目标识的部分文本
- **THEN** 页面只展示当前用户可访问且与搜索条件匹配的项目，并在无匹配项时保留清除搜索的入口

### Requirement: 已登录用户创建项目

系统 MUST 允许已登录用户使用项目名称、项目标识和可选描述创建项目。项目标识 MUST 在平台内唯一、创建后不可修改，并只允许 3 至 40 位小写字母、数字和连字符；项目名称 MUST 去除首尾空白且长度为 1 至 100 个字符。创建成功后，系统 MUST 将创建者设为该项目的 `Owner`。

#### Scenario: 成功创建项目

- **WHEN** 用户提交合法且唯一的项目名称与项目标识
- **THEN** 系统创建项目及 `Owner` 成员关系，并将用户引导到新项目的管理页面

#### Scenario: 项目标识重复

- **WHEN** 用户提交已存在的项目标识
- **THEN** 系统拒绝创建，在项目标识字段显示冲突提示，并保留其余输入内容

#### Scenario: 创建表单校验失败

- **WHEN** 用户提交空项目名称或格式不合法的项目标识
- **THEN** 页面在对应字段显示可理解的校验信息，不发起无效创建或生成半成品项目

#### Scenario: 创建请求失败

- **WHEN** 合法的创建请求因临时服务错误失败
- **THEN** 页面保留用户输入、显示可重试错误，并防止不明确成功状态下的重复创建

### Requirement: 按角色查看和修改项目基础信息

系统 MUST 允许所有项目成员查看项目标识、名称、描述、当前用户角色、创建时间和更新时间。只有 `Owner` 与 `Admin` MUST 能修改项目名称和描述；`Developer` 与 `Viewer` MUST 看到只读状态，且服务端必须独立拒绝其修改请求。

#### Scenario: Owner 修改项目

- **WHEN** 项目 `Owner` 提交合法的新名称或描述
- **THEN** 系统保存变更、更新修改时间并向页面返回明确的成功反馈

#### Scenario: Viewer 尝试修改项目

- **WHEN** `Viewer` 绕过前端只读状态直接提交修改请求
- **THEN** 系统拒绝修改且项目数据保持不变

#### Scenario: 表单存在未保存修改

- **WHEN** 用户修改了可编辑字段但尚未保存并尝试离开页面
- **THEN** 页面提示存在未保存内容，允许用户继续编辑或确认放弃修改

### Requirement: 项目资源访问不得泄露其他租户信息

系统 MUST 在服务端依据当前登录用户的项目成员关系和角色校验所有项目读取与修改请求。未认证请求 MUST 返回未认证响应；已认证但无成员关系的请求 MUST 使用与项目不存在一致的响应，不得泄露目标项目是否存在。

#### Scenario: 跨项目读取

- **WHEN** 已登录用户请求一个没有成员关系的项目
- **THEN** 系统返回与项目不存在一致的响应且不返回项目元数据

#### Scenario: 伪造项目请求头

- **WHEN** 用户为无权访问的项目添加 `X-Project-Id` 或 `X-User-Project-Ids` 请求头
- **THEN** 系统忽略这些请求头作为身份或成员关系证明，并按当前服务端会话拒绝访问
