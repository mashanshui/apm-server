## Purpose

为登录、项目管理和 Crash 分析提供一致的浅色 PC 控制台信息架构，使桌面浏览器用户能够清楚识别当前用户、当前项目和可执行操作。

## ADDED Requirements

### Requirement: 控制台采用统一浅色 PC 视觉

网页控制台 MUST 使用统一的浅色视觉变量和组件状态，页面背景、侧栏、面板、表单、表格、提示与交互反馈 MUST 在浅色背景下保持清晰层级和可读对比度。设计与验收范围 MUST 面向宽度不小于 1280 像素的 PC 浏览器，不要求为移动端或窄屏提供折叠导航、卡片重排或触控专用交互。

#### Scenario: 在标准 PC 视口访问

- **WHEN** 用户在 1280、1440 或 1920 像素宽的桌面视口打开登录页或控制台页面
- **THEN** 页面保持稳定的浅色布局，主要导航、标题、表单和主要操作无需横向滚动即可使用

#### Scenario: 在窄屏访问

- **WHEN** 用户在小于 1280 像素宽的视口打开控制台
- **THEN** 系统不承诺移动端重排或折叠菜单，但不得因为隐藏主要操作而形成看似支持移动端的错误体验

### Requirement: 控制台明确展示用户和项目上下文

受保护页面 MUST 使用共享控制台布局，展示产品标识、当前用户入口、项目切换器和项目级导航。项目上下文页 MUST 明确展示当前项目名称或标识；项目列表和创建项目页 MUST 使用不依赖当前项目的工作区导航。

#### Scenario: 查看项目内页面

- **WHEN** 用户打开项目设置或 Crash 页面
- **THEN** 共享布局显示当前用户、当前项目以及可用的项目分析和项目设置导航

#### Scenario: 查看项目工作区页面

- **WHEN** 用户打开项目列表或创建项目页面
- **THEN** 页面保持产品与用户上下文，但不伪造当前项目或显示只适用于某个项目的选中导航

### Requirement: 项目切换不会串用旧项目数据

项目切换器 MUST 只列出当前用户有权限的项目。切换项目后，系统 MUST 进入目标项目的稳定入口并清理或重新校验旧项目的数据、筛选和写入状态，不得把旧项目内容显示在新项目上下文中。

#### Scenario: 从 Crash 详情切换项目

- **WHEN** 用户在某项目的 Crash 详情页选择另一个项目
- **THEN** 页面进入目标项目的 Crash 总览并重新加载数据，不复用原项目的事件详情或问题指纹

#### Scenario: 用户只有一个项目

- **WHEN** 当前用户只有一个可访问项目
- **THEN** 项目切换器仍明确显示该项目，并提供返回项目列表的入口而不展示虚假的其他选项

### Requirement: 路由回退使用真实工作区

系统 MUST 为未知路由显示明确的未找到页面或引导到项目列表，且 MUST NOT 自动进入硬编码的演示项目。登录后若用户没有可访问项目，默认入口 MUST 为项目空状态；若用户有项目，项目列表仍 MUST 可作为稳定入口。

#### Scenario: 打开未知路由

- **WHEN** 已登录用户访问未匹配的网页地址
- **THEN** 页面显示未找到状态并提供返回项目列表的操作，不跳转到 `demo-project`

#### Scenario: 登录后没有项目

- **WHEN** 登录成功且当前用户没有任何可访问项目
- **THEN** 页面进入项目列表的空状态并提供创建项目入口

### Requirement: 页面操作状态可识别且可操作

登录、项目列表、项目创建和项目设置页面 MUST 为加载、空结果、校验失败、权限只读、请求失败、保存中和保存成功提供明确反馈。所有输入 MUST 有可关联的可见标签，键盘焦点 MUST 可见，主要操作 MUST 能通过键盘完成。

#### Scenario: 保存项目设置

- **WHEN** 有编辑权限的用户提交项目设置
- **THEN** 页面在请求期间阻止重复提交，并在成功或失败后显示对应反馈

#### Scenario: 使用键盘操作表单

- **WHEN** 用户仅使用键盘访问登录或项目表单
- **THEN** 用户能够按合理顺序定位输入与按钮、识别焦点并提交表单
