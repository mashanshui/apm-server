# application-symbol-management Specification

## Purpose

为应用成员提供网页符号表管理能力，通过构建标识精确关联单份 Android mapping，允许管理员安全纠正错误文件，同时保障应用隔离、上传幂等、并发替换一致性及解析期间的文件可用性。

## Requirements

### Requirement: 网页管理应用构建符号表
系统 MUST 提供当前应用符号表分页列表、类型与版本筛选、mapping 单文件上传、SO ZIP 上传及条件管理。每个应用版本 MUST 最多有一份默认 mapping，并可为每个非空 buildId 登记一份专用文本 mapping；MUST NOT 合并多份 mapping。列表 MUST 展示所属版本、mapping 默认/专用范围及可选构建、文件元数据与修订号；SO 展示 ABI、完整 ELF Build ID 及实际符号信息，不接收或展示应用 buildId。SO 管理登记 MUST 在应用版本内以 ABI + ELF Build ID 区分，文件名不决定身份。过滤、排序及分页 MUST 在数据库完成。删除重传 MUST 新建身份并保留历史来源和审计。

#### Scenario: 首次注册构建
- **WHEN** 管理员上传合法 mapping、非空且最多 128 字符的 appVersion 及选填的有效 buildId，且对应默认或专用身份尚无活动文件
- **THEN** 保存相应范围的记录，同时可靠登记该应用版本的 JVM 后台工作，不等待历史还原

#### Scenario: 同内容重试
- **WHEN** 同一活动应用版本构建再次上传相同 mapping 字节
- **THEN** 返回当前记录，不增加修订号或重复文件，重复触发不会创建无限后台任务

#### Scenario: 删除后重新上传
- **WHEN** 当前 mapping 已删除，管理员再次为相同 appVersion 和 buildId 上传合法文件
- **THEN** 新活动记录可被后续处理获取，身份与旧记录区分，历史已成功 Crash 保持旧结果和来源

#### Scenario: 同名构建属于不同版本
- **WHEN** 同一应用分别为版本 1.0 和 2.0 的相同 buildId 上传 mapping
- **THEN** 两份记录独立存在，按完整版本构建匹配，不互相冲突、覆盖或作为缺失时的回退

#### Scenario: 精确筛选与有界列表
- **WHEN** 用户按符号类型、应用版本、mapping 默认/专用范围及构建，或 SO 模块身份筛选并分页
- **THEN** 只返回当前应用和完整筛选中的活动记录，默认 50 条且单页最多 200 条，非法或不属于该筛选的游标明确失败

### Requirement: 上传和替换必须授权并校验
系统 MUST 使用 Session、CSRF 和应用成员授权；成员可查看元数据及适用进展，仅 OWNER/ADMIN 可写入。系统 MUST 校验必填应用版本、存在时的应用构建、实际大小及类型适用的文件完整格式，mapping 仍须完整可解析。缺失构建 MUST 按版本默认登记，不报必填错误；非空构建 MUST 保持原值、最多 256 字符且无首尾空白和控制字符。失败 MUST 不改变已有文件；日志和响应 MUST NOT 泄漏文件内容、堆栈、凭据或内部路径。App Key MUST NOT 获得管理权限；版本 MUST 不从文件名、buildId 或遥测猜测。

#### Scenario: 越权上传
- **WHEN** 普通成员、其他应用用户或仅持事件 App Key 的调用者尝试上传、替换或删除任一类型符号文件
- **THEN** 拒绝操作并遵守应用资源隐藏规则，不暴露其他应用内容

#### Scenario: 文件不合法或超限
- **WHEN** 上传空文件、非法 mapping、不支持版本、非法 SO 或超限文件
- **THEN** 返回明确错误，旧文件保持可用，临时产物可回收，不登记虚假的成功任务

#### Scenario: 应用版本缺失或无效
- **WHEN** 新上传请求缺少 appVersion、值为空、超过 128 字符或包含首尾空白和控制字符
- **THEN** 拒绝请求，不按 buildId 单独匹配，也不自动生成版本或替换为空版本

### Requirement: 管理员确认替换及并发一致性
不同内容的同身份上传 MUST 报告冲突，不得静默覆盖；网页 MUST 展示摘要并要求确认，替换及删除 MUST 携带期望身份和修订号并原子校验。系统 MUST 保留操作者、时间、动作及来源审计。已取得旧 mapping 的子批可完成并记录旧来源，新子批 MUST 重新按专用优先、版本默认其次选取，单个子批不能混用文件。默认与专用登记 MUST 独立修订，管理操作 MUST NOT 重算已成功 JVM Crash；Jank 仍在上传时解析，既存事件不回算。SO 管理 MUST NOT 唤醒任何还原工作。

#### Scenario: 确认替换
- **WHEN** 管理员确认替换 mapping 且期望身份与修订号仍有效
- **THEN** 该默认或专用 mapping 原子生效、修订号递增、记录审计并唤醒本应用版本尚未成功事件，已有成功结果不变

#### Scenario: 并发替换
- **WHEN** 确认期间另一操作已改变修订号或删除记录
- **THEN** 拒绝旧请求，返回冲突或资源不存在，不能覆盖新修订或误删重新上传的文件

#### Scenario: 存储故障
- **WHEN** 文件发布、元数据或适用的后台工作登记失败
- **THEN** 不报告不完整的成功操作，既有可用记录保持一致，失败产物按已确认引用关系回收

#### Scenario: 删除有读取租约的文件
- **WHEN** 管理员删除仍被在途批次读取的 mapping
- **THEN** 新批次不能再获取该文件，在途读取可完成，最后释放后回收文件，历史处理来源与审计保留


### Requirement: 上传完成与后台进展分别呈现
mapping 上传或替换成功 MUST 只表示文件及对应应用版本工作已可靠登记。系统 MUST 提供受查看权限保护的有界进展，区分排队、执行、等待文件、退避和空闲；计数 MUST 明确属于本应用版本本轮，涵盖默认及专用文件所处理的事件，不冒充某一文件或全量历史统计。查询 MUST NOT 加载全量事件或堆栈。SO 保存成功 MUST 明示未执行 Native 还原；SO 和无版本旧记录的 JVM 进度 MUST 返回不适用错误。

#### Scenario: 大数据量上传响应
- **WHEN** 有大量待还原 JVM Crash 的应用上传 mapping
- **THEN** 文件校验和保存完成后即可返回，后台独立处理，网页明确展示上传成功和后台进展的区别

#### Scenario: 显示失败或新到数据
- **WHEN** 部分事件失败或一轮完成后出现迟到事件
- **THEN** 进展能够说明失败和后续执行，不把当前空闲或一次成功计数解释成永久无积压

#### Scenario: 查看 SO 上传结果
- **WHEN** SO 批次保存成功或用户尝试查询 SO 的 JVM 后台进度
- **THEN** 页面显示保存数量与管理结果，进度接口返回不适用错误，Native 事件保持原始状态

### Requirement: SO 身份与符号信息来自文件内容
系统 MUST 只接受支持的 Android ELF32/ELF64 小端共享库，根据文件头识别 armeabi-v7a、arm64-v8a、x86 或 x86_64，从 GNU Build ID note 提取完整标识并规范为小写十六进制。系统 MUST 拒绝缺少或冲突的 Build ID、ABI 不一致、截断或越界 ELF，以及缺少可识别函数符号和调试信息的文件。MUST NOT 用文件名或目录名猜测身份、截短 Build ID、加载或执行 SO。符号信息存在性 MUST 与实际还原成功区分。

#### Scenario: 多 ABI 同名库
- **WHEN** ZIP 包含不同 ABI 的同名 SO，且各文件内容合法
- **THEN** 从 ELF 识别各自 ABI 和完整 Build ID，保存独立记录，并展示实际符号信息而不承诺所有地址可还原

#### Scenario: 无 Build ID 或只有已剥离导出表
- **WHEN** 文件没有可靠 GNU Build ID，或只有动态导出表且无可识别的完整函数符号或调试信息
- **THEN** 返回明确的不可重试校验错误，不按同名库或文件哈希冒充模块 Build ID

#### Scenario: 校验事件目标模块
- **WHEN** 从 Native 模块入口指定目标 ABI 和 ELF Build ID，而 ZIP 中没有该完整身份
- **THEN** 拒绝整批上传并提示目标不匹配，不将其他同名库登记为该模块的符号文件

### Requirement: SO 批次全量校验与原子确认
SO ZIP 批次 MUST 使用同一 appVersion，不接收应用 buildId，完整校验候选后原子提交元数据及审计。相同模块身份与摘要 MUST 幂等；不同摘要 MUST 返回整批快照且不修改记录。确认 MUST 携带每项预期的 symbolId/revision 或不存在，任一并发变化 MUST 拒绝整批。批内同身份同内容可合并，不同内容 MUST 拒绝。提交确认未知 MUST 可重试并保留可能被引用文件，允许普通原批次重传对账。

#### Scenario: 混合新文件与冲突文件
- **WHEN** 一个 ZIP 同时包含新 SO、相同内容 SO 和不同内容的现有 SO
- **THEN** 首次请求返回完整有界冲突快照，既不新增也不替换；管理员确认后才统一创建或替换并审计

#### Scenario: 确认时新身份已被占用
- **WHEN** 用户确认快照认为某条目不存在，但另一请求已创建该身份
- **THEN** 即使其他条目修订号未变，也拒绝整批确认并返回最新冲突，不发生部分覆盖

#### Scenario: 提交响应丢失后重试
- **WHEN** 批次已提交但响应丢失，客户端用相同应用版本和 ZIP 重新执行普通上传，不提供应用 buildId
- **THEN** 按各文件当前身份与摘要返回幂等成功，不重复增加修订号或审计，也不要求客户端猜测提交结果

### Requirement: SO 压缩包处理有界且不采用归档路径存储
系统 MUST 对压缩请求、实际解压总量、单文件、归档条目数、目录深度、校验时间、并发和临时磁盘用量设限并及时中止。MUST 拒绝绝对路径、父目录穿越、重复归档路径、符号链接、特殊文件、嵌套压缩包和伪装 SO；目录及明确列出的打包辅助文件可忽略。文件 MUST 保存到服务端生成的受控键，原 ZIP 不长期保存。无可接受 SO 或任何候选校验失败 MUST 拒绝整批，旧记录不变。

#### Scenario: ZIP 声明长度伪造与压缩炸弹
- **WHEN** 条目实际解压字节超出预算，即使其声明大小很小
- **THEN** 按实际读取字节中止并返回大小错误，释放本次暂存，不发布部分记录

#### Scenario: 带 ABI 子目录的符号包
- **WHEN** ZIP 使用合法的多级 ABI 目录并仅包含 SO、目录和允许忽略的辅助文件
- **THEN** 有界遍历候选，最终存储路径不使用归档目录，实际 ABI 仍以 ELF 内容为准

### Requirement: 无应用版本的旧登记隔离
旧 mapping 缺少 appVersion 时，系统 MUST 保留其原 symbolId、文件引用和审计，在管理列表明确显示未登记应用版本。该记录 MUST NOT 参与新版租约、后台对账、Jank 匹配或进度查询，也不得根据 buildId、文件名或遥测反推版本。管理员 MUST 通过带明确版本的重新上传建立新身份，旧记录仍可条件删除。既有成功 Crash 的来源和固定结果 MUST 保留。

#### Scenario: 升级后只有旧 mapping
- **WHEN** 某应用版本只有一份缺少 appVersion 的旧登记，没有合法专用或默认 mapping
- **THEN** JVM 等待 mapping，Jank 按无 mapping 规则继续，页面提示重新上传；旧记录不能被当成版本默认文件

#### Scenario: 同内容按版本重新上传
- **WHEN** 管理员为旧 mapping 的相同字节指定明确 appVersion，并选填 buildId 重新上传
- **THEN** 建立新的版本化 symbolId，旧身份与历史成功结果不变，新身份只影响尚未成功和后续事件

### Requirement: mapping 版本默认与构建优先
系统 MUST 对有构建事件先选择同应用版本的构建专用 mapping，专用登记不存在才选择该版本默认 mapping；事件 MUST 保留原上报构建，只在专用不存在时选择版本默认。默认不存在 MUST 明确无匹配，不选其他构建或其他版本。专用文件不可读或查询失败 MUST 作为存储失败，不回退默认。每个应用版本 MUST 最多有一份活动默认文件，默认和专用 MUST 分别管理修订与审计，实际来源 MUST 可追溯。

#### Scenario: 只填写版本上传
- **WHEN** 管理员省略 buildId 上传 mapping
- **THEN** 建立该版本默认登记，没有专用登记的同版本有构建事件可选择它

#### Scenario: 默认和专用同时存在
- **WHEN** 版本有默认 mapping 且 build-A 有专用 mapping，分别收到 build-A 和 build-B 事件
- **THEN** build-A 使用专用文件，build-B 使用默认文件，来源及修订号各自记录

#### Scenario: 专用文件损坏
- **WHEN** 精确专用登记存在但对应文件不可读，即使同版本有合法默认文件
- **THEN** 返回或登记可重试存储失败，不能静默用默认文件产生首次成功结果

#### Scenario: 版本只有一个其他专用文件
- **WHEN** 事件所在版本只有另一构建的专用 mapping，没有自身专用或默认登记
- **THEN** 仍为无匹配，不因只有一个候选而自动将其当作版本默认

#### Scenario: SO 请求仍携带应用构建
- **WHEN** SO 上传或明确的 SO 类型列表请求提交应用 buildId
- **THEN** 返回字段不适用错误，不将其存入 SO 身份、覆盖确认条件或事件匹配条件
