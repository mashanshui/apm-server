# application-symbol-management Specification

## Purpose

为应用成员提供网页符号表管理能力，通过构建标识精确关联单份 Android mapping，允许管理员安全纠正错误文件，同时保障应用隔离、上传幂等、并发替换一致性及解析期间的文件可用性。

## Requirements

### Requirement: 网页管理应用构建符号表
系统 MUST 提供当前应用符号表分页列表、精确构建筛选、单文件上传、条件替换和删除入口。列表 MUST 展示构建标识、原始文件名、大小、摘要、当前版本、上传人及更新时间，仅列出活动记录。系统 MUST 仅接受单个文本 mapping，不接受 ZIP、SO 或多文件合并，以 appId + buildId 唯一定位一份活动 mapping，不按应用版本模糊匹配。删除后重新上传 MUST 产生新的符号表唯一身份，旧事件的来源元数据和操作审计 MUST 保留。

#### Scenario: 首次注册构建
- **WHEN** 管理员上传合法 mapping 及尚无活动记录的有效 buildId
- **THEN** 保存并返回活动记录，同时可靠登记 JVM Crash 后台工作，不等待历史事件还原

#### Scenario: 同内容重试
- **WHEN** 同一活动构建再次上传相同字节
- **THEN** 返回当前记录，不增加版本或重复文件，重复触发不会创建无限后台任务

#### Scenario: 删除后重新上传
- **WHEN** 当前 mapping 已删除，管理员再次为同一 buildId 上传合法文件
- **THEN** 新活动记录可被后续处理获取，身份与旧记录区分，历史已成功 Crash 保持旧结果和来源

### Requirement: 上传和替换必须授权并校验
系统 MUST 使用 Session、CSRF 和应用成员授权；成员可查看元数据及处理进展，仅 OWNER/ADMIN 可上传、替换或删除。系统 MUST 校验实际大小、完整 mapping 可解析性及受支持格式，不能仅依赖扩展名或延迟读取对象。失败 MUST 不改变当前可用 mapping。请求与日志 MUST NOT 泄漏完整 mapping、堆栈、凭据或内部路径。Android App Key MUST NOT 获得符号表管理权限。

#### Scenario: 越权上传
- **WHEN** 普通成员、其他应用用户或仅持事件 App Key 的调用者尝试上传、替换或删除
- **THEN** 拒绝操作并遵守应用资源隐藏规则，不暴露其他应用内容

#### Scenario: 文件不合法或超限
- **WHEN** 上传空文件、非法 mapping、不支持版本或超限文件
- **THEN** 返回明确错误，旧 mapping 保持可用，临时产物可回收，不登记虚假的成功任务

### Requirement: 管理员确认替换及并发一致性
不同内容的同构建上传 MUST 报告冲突，不得静默覆盖；网页 MUST 展示摘要并要求确认，替换及删除 MUST 携带期望版本并进行原子条件校验。系统 MUST 保留操作者、时间、动作及来源摘要审计。已经取得旧 mapping 的一批解析允许完成并记录旧身份；变更生效后新领取的批次 MUST 使用当前活动 mapping 或进入等待，单批不能混用文件。已成功 JVM Crash MUST NOT 因任何 mapping 管理操作被重算；Jank 保持既有上传时解析和既存事件不回算规则。

#### Scenario: 确认替换
- **WHEN** 管理员确认替换且期望版本仍有效
- **THEN** 新 mapping 原子生效、版本递增、记录审计并唤醒尚未成功的 Crash，已有成功结果不变

#### Scenario: 并发替换
- **WHEN** 确认期间另一操作已改变版本或删除记录
- **THEN** 拒绝旧请求，返回冲突或资源不存在，不能覆盖新版本或误删重新上传的文件

#### Scenario: 存储故障
- **WHEN** 文件发布、元数据或后台工作登记失败
- **THEN** 不报告不完整的成功操作，既有可用记录保持一致，失败产物可回收

#### Scenario: 删除有读取租约的文件
- **WHEN** 管理员删除仍被在途批次读取的 mapping
- **THEN** 新批次不能再获取该文件，在途读取可完成，最后释放后回收文件，历史处理来源与审计保留


### Requirement: 上传完成与后台进展分别呈现
符号表上传或替换成功 MUST 仅表示合法文件已经持久化且对应后台工作已可靠登记，不表示历史 Crash 已还原。系统 MUST 提供受应用查看权限保护的有界后台进展查询，区分排队、执行、等待 mapping、等待重试及当前空闲，并提供有范围说明的处理数量和更新时间。查询 MUST NOT 为轮询加载全量事件或堆栈。

#### Scenario: 大数据量上传响应
- **WHEN** 有大量待还原 Crash 的应用上传 mapping
- **THEN** 文件校验和保存完成后即可返回，后台独立处理，网页明确展示上传成功和后台进展的区别

#### Scenario: 显示失败或新到数据
- **WHEN** 部分事件失败或一轮完成后出现迟到事件
- **THEN** 进展能够说明失败和后续执行，不把当前空闲或一次成功计数解释成永久无积压
