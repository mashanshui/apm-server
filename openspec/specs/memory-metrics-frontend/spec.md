# memory-metrics-frontend Specification

## Purpose

为应用成员提供与现有控制台一致的内存指标分析页面，通过 PSS、VSS、Java 堆三个指标的统计卡片和分位数趋势观察内存变化，并清楚区分查询失败、无样本与真实零值，避免用户误读数据。

## Requirements

### Requirement: 提供三个内存指标页签

控制台 MUST 在应用上下文提供 `/apps/:appId/memory-metrics` 及内存指标导航，沿用浅色PC布局，仅提供PSS、VSS、Java堆页签，默认PSS。页面 MUST 标明“运行期观测峰值”，解释每轮仅统计SDK有效采集期间观察并保存的最大值、下次启动补报后可见；不得将它表述成连续真实峰值或当前在线内存。MUST 不展示FD触顶率、多维下钻、对比列表或导出。

#### Scenario: 打开内存指标页面
- **WHEN** 授权应用成员进入页面
- **THEN** 显示当前应用、三个页签、筛选、概览与趋势，以及运行峰值和延迟补报说明

### Requirement: 筛选和地址状态一致

页面 MUST 提供时间范围、小时/日粒度、应用版本、系统版本、机型、进程、峰值时Activity（scene）及峰值时前后台筛选，不显示32/64位筛选。前后台支持全部/前台/后台；MUST 说明scene/foreground分别匹配各指标自己的峰值上下文，时间按运行记录最后持久化采样时间归属而非精确退出或上传时间。筛选、指标、粒度 MUST 在URL可恢复，非法URL参数提示修正；切应用清空旧数据与筛选并忽略旧请求。

#### Scenario: 刷新筛选结果
- **WHEN** 用户设置版本和后台筛选后刷新地址
- **THEN** 恢复相同筛选，查询各指标在后台发生的峰值，不按整轮统一前后台判断

#### Scenario: 切换应用时旧请求返回
- **WHEN** 切到另一应用后原请求完成
- **THEN** 只显示新应用数据，旧响应不得覆盖

### Requirement: 展示概览和分位数趋势

页面 MUST 展示所选指标运行峰值的平均值、P50/P90/P95/P99五张卡片，数量读取runCount并标为“有效运行数”，不得继续读取sampleCount或称采样次数。趋势支持P50/P90/P95/P99，默认P50，使用服务端桶统计；字节除以1048576显示MiB且保留两位小数，明确时区。MUST 不在浏览器重算总体统计，不连接空桶，不混入普通样本或将较长运行重复展开。

#### Scenario: 切换趋势分位数
- **WHEN** 用户从P50切到P95
- **THEN** 使用服务端P95，概览仍为相同筛选的运行峰值分布

#### Scenario: 区分零值和无数据
- **WHEN** 某桶真实峰值为零而另一桶无运行
- **THEN** 前者为0.00 MiB，后者断点；空概览为暂无数据，不是0.00

#### Scenario: 不同指标运行数不同
- **WHEN** 同一筛选的PSS与Java堆runCount不同
- **THEN** 切页签显示各自有效运行数，不复用其他指标数量或样本数

### Requirement: 独立呈现查询状态

概览和趋势 MUST 分别处理加载、无数据、失败及重试；未登录和无权限 MUST 遵循控制台既有处理，不能将错误呈现为成功空数据。页面 MUST 在 1280、1440、1920 像素宽 PC 视口保持主要操作可见。

#### Scenario: 趋势失败但概览成功
- **WHEN** 概览请求成功而趋势请求失败
- **THEN** 保留有效概览，趋势显示错误和重试入口，不伪造曲线
