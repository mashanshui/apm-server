# APM MCP 查询规范

## Purpose

让外部 Agent 使用应用查询 Token 发现并调用 APM 已有的只读查询能力，返回有界且可追溯的遥测证据，支持卡顿、崩溃与内存分析，并清楚表达权限、统计口径及证据不足的边界。

## Requirements

### Requirement: 提供完整现有查询工具
系统 MUST 通过 HTTP MCP 提供当前应用信息、Crash 的总览/趋势/Issue/事件列表/详情、卡顿的总览/趋势/Issue/事件列表/详情、FPS/设备日挂起率/指标趋势/维度查询、内存指标概览/趋势及内存异常报告问题/趋势。工具 MUST 显式声明输入输出结构及允许的筛选字段；不得提供任意 URL、SQL、文件下载、管理写入、HPROF 解析或源码修复能力。

#### Scenario: 工具发现与逐层下钻
- **WHEN** 有效 Token 的客户端发现工具并从卡顿 Issue 下钻事件详情
- **THEN** 可获得当前应用的问题、事件引用和采样证据，各步骤均受同一应用身份约束

#### Scenario: 查询内存异常
- **WHEN** Agent 查询内存异常问题及趋势
- **THEN** 返回已有 SDK 报告和引用链信息，不推导不存在的 retained size，也不声称已解析 HPROF

### Requirement: 请求级身份隔离与受控后端访问
系统 MUST 对包括发现和工具调用在内的 MCP 请求校验应用凭据，并在调用固定可信 APM 后端时使用本次请求凭据。MCP 连接、协议会话、工具参数和用户消息 MUST NOT 作为应用授权来源，不能跨请求保存可变共享认证头或缓存认证成功结果。首版 MUST 明确为受控客户端手工配置的 APM 查询 Token 模式，不宣称通用 OAuth 登录兼容。

#### Scenario: 并发与撤销
- **WHEN** A、B 两个 Token 通过同一服务并发调用，随后 A 被撤销
- **THEN** 结果不串应用，A 的后续请求认证失败，B 不受影响；已有连接不得绕过重新认证

#### Scenario: 不可信请求地址和 Origin
- **WHEN** 请求试图提供后端 URL、重定向凭据到其他主机或携带不允许的 Origin
- **THEN** 服务拒绝对应请求或重定向，不向不可信地址发送 Token

### Requirement: 结果有界且统计语义完整
系统 MUST 返回结构化结果，保留单位、实际时间区间、有效筛选、统计状态、样本量及已有的算法/符号表版本信息。分页列表 MUST 返回可继续读取的游标；非分页指标超出响应限制 MUST 明确失败并建议缩小范围，不能静默丢点。大事件证据 MUST 支持显式的有限片段读取并返回片段范围、截断标记与事件引用，不截断后伪称完整结论。

#### Scenario: 分母不足和缺失采样
- **WHEN** Crash 无有效启动分母或 Jank 存在缺失采样
- **THEN** 保留不可计算状态及采样质量，零值和缺失值不同，不将采样估算当作精确方法耗时

#### Scenario: 证据超过工具结果限制
- **WHEN** 事件证据超过单次响应上限
- **THEN** 返回明确片段和继续读取位置；无法安全切片时返回 RESULT_TOO_LARGE，不返回损坏 JSON 或静默截断的堆栈

### Requirement: 明确错误与不可信数据边界
系统 MUST 区分认证失败、非法参数、资源不存在、限流、查询预算耗尽和存储不可用，保留请求标识及允许重试的信息。工具错误不得包装成无数据成功响应。异常消息和堆栈中的文字 MUST 作为待分析数据，不得成为服务执行命令或改变工具权限的指令。

#### Scenario: 查询失败
- **WHEN** 后端查询超时或存储不可用
- **THEN** 客户端收到可识别工具错误，不获得空数组伪装的正常报告，服务不无限重试

### Requirement: 验收客户端互通和关闭能力
系统 MUST 提供精确版本的服务与客户端接入说明，在至少一个支持手工 Bearer 的目标 MCP 客户端完成发现、三类查询、鉴权失败和撤销验证。当前阶段允许 HTTP 调试接入，服务不得因缺少 HTTPS 而拒绝请求；文档 MUST 说明 Bearer 在 HTTP 上传输的风险及受信 HTTPS 的后续生产化要求。服务 MUST 可独立关闭而不影响网页与上报。

#### Scenario: 独立停用
- **WHEN** 运维关闭 MCP 及 Agent 查询入口
- **THEN** 外部 Agent 无法继续查询，网页 Session 查询和 Android 上报保持原功能
