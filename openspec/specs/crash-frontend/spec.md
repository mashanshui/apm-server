## Purpose

为项目成员提供可直接使用的 JVM Crash 分析页面，使用户能够从统计总览逐级定位到 Crash 问题、具体事件和脱敏后的原始堆栈，并正确理解无数据与统计分母不足等状态。

## Requirements

### Requirement: Crash 总览与筛选

前端 MUST 提供项目 Crash 总览页面，展示启动会话数、Crash 事件数、崩溃会话数、受影响设备数、每千会话崩溃率、无崩溃会话率、时间趋势和问题排行。页面 MUST 支持项目、时间范围、应用版本、渠道、环境、Android 版本、设备型号和问题指纹筛选，并将同一组筛选条件应用到相关查询结果。

#### Scenario: 首次打开 Crash 总览

- **WHEN** 用户打开一个项目的 Crash 总览页面
- **THEN** 页面使用默认时间范围查询总览、趋势和问题排行，并显示统计卡片、趋势图和问题列表

#### Scenario: 使用筛选条件刷新数据

- **WHEN** 用户修改时间范围或任一 Crash 维度筛选条件并提交
- **THEN** 页面使用新的筛选条件刷新总览、趋势和问题排行，并明确显示当前筛选状态

#### Scenario: 筛选条件无效

- **WHEN** 服务端返回时间范围、筛选值或请求参数校验错误
- **THEN** 页面保留用户输入，显示可理解的错误信息，并允许用户修正后重新查询

### Requirement: 统计状态和查询状态呈现

前端 MUST 保留服务端返回的 Crash 统计语义。比例字段为 `null` 或统计状态为 `denominator_insufficient` 时，页面 MUST 显示分母不足或不可计算，不得显示为零；统计状态为 `no_data` 或列表为空时，页面 MUST 显示无数据。查询过程中 MUST 显示加载状态，查询失败时 MUST 显示可重试的错误状态。

#### Scenario: 存在有效分母且没有 Crash

- **WHEN** 查询结果包含有效启动会话分母、Crash 事件数为零且状态为 `ok`
- **THEN** 页面显示真实的零 Crash 结果和可计算的比例，而不是无数据

#### Scenario: 缺少启动会话分母

- **WHEN** 查询结果的比例字段为 `null` 且状态为 `denominator_insufficient`
- **THEN** 页面将比例显示为分母不足或不可计算，并保留其他可用的计数指标

#### Scenario: 查询范围没有数据

- **WHEN** 查询结果状态为 `no_data` 或趋势、问题列表为空
- **THEN** 对应区域显示无数据提示，不将空结果渲染为零值趋势或虚假的问题

#### Scenario: 查询请求失败

- **WHEN** 网络请求超时、服务端返回 5xx 或返回未预期的错误响应
- **THEN** 页面显示错误提示和重试入口，且不使用上一次查询结果冒充当前结果

### Requirement: Crash 问题和事件下钻
前端 MUST 允许从问题排行进入指纹事件列表，再按 eventId 进入详情，保持当前应用和筛选上下文及服务端游标分页。问题和事件 MUST 清楚标记 temporary/resolved；临时问题 MUST 展示 buildId 和待还原或失败状态，不能解释为跨版本稳定问题。补处理期间排行和归属允许变化，页面 MUST 保持既有数据加载、错误和非快照分页提示。

#### Scenario: 从问题排行查看事件
- **WHEN** 用户选择临时或正式问题
- **THEN** 展示该指纹下当前事件、版本、构建、设备及处理状态，临时问题有明确标记

#### Scenario: 加载下一页问题或事件
- **WHEN** 响应包含 nextCursor 且用户加载更多
- **THEN** 使用原应用与筛选请求下一页，不重复追加已有记录，并遵守后台归组变化的非快照语义

#### Scenario: 没有更多结果
- **WHEN** nextCursor 为空
- **THEN** 不再继续分页，不把加载结束误认为所有事件均已还原

#### Scenario: 临时问题已变化
- **WHEN** 用户打开已被补处理移空的临时指纹页面
- **THEN** 显示临时归组可能变化的说明和返回问题列表入口，不伪造唯一正式问题跳转，已知事件仍按 eventId 可达

### Requirement: Crash 事件详情和堆栈展示
前端 MUST 展示单事件的应用、发生/接收时间、版本、构建、渠道、环境、系统、设备、会话、异常类型、当前指纹和持久化还原状态。JVM 主异常详情 MUST 只解析当前 stack 契约：pending/failed 为脱敏原始异常链，symbolicated 为完整还原输出；删除原始/实时还原双份切换及 raw_only、rawCrash、symbolicatedStackText 的旧版解析和展示分支。MUST 安全呈现完整原因链、内联和多候选，并展示失败原因、处理时间及实际符号表来源。mapping 删除后，已成功结果仍可查看；状态不得解释为所有帧都被正确还原。管理员 MUST 可从未完成 JVM 事件进入带 appVersion、mapping 类型及原 buildId 的管理入口；管理员可清空上传表单中的构建以登记版本默认 mapping。不支持的响应格式 MUST 显示协议错误，不猜测或转换为旧视图。

详情 MUST 增加独立诊断区域，显示崩溃线程、其他线程及各自当前堆栈、日志、内存、文件描述符和运行环境；MUST 保持主异常与辅助线程状态分开，不能将“主异常已还原”解释为诊断完整或所有线程已还原。

#### Scenario: 查看原始堆栈事件
- **WHEN** JVM 事件状态为 pending 或 failed
- **THEN** 展示已存原始异常链、等待或失败原因，以及可用诊断，允许按角色进入 JVM 分析任务，不在详情触发同步还原

#### Scenario: 查看不存在或无权限的事件
- **WHEN** 接口返回资源不存在或访问被拒绝
- **THEN** 显示统一提示，不泄露其他应用数据

#### Scenario: 查看持久化还原结果
- **WHEN** JVM 事件为 symbolicated，当前 mapping 甚至已删除
- **THEN** 展示固定完整输出及当时来源，诊断仍可查看，不实时调用还原，不显示原始堆栈切换，也不要求重新上传

#### Scenario: 补传后刷新
- **WHEN** 管理员上传 JVM mapping 后立刻返回 JVM 详情
- **THEN** 后台未完成时仍显示当前 pending/failed；刷新到成功后才显示固定结果，应用切换后旧响应不能覆盖新应用

#### Scenario: 旧详情格式被拒绝
- **WHEN** 后端响应仅有旧双份字段或使用 raw_only 状态
- **THEN** 页面报告协议不匹配，不渲染旧视图或调用实时还原补齐数据

#### Scenario: 从 JVM 事件上传准确版本
- **WHEN** 管理员从 appVersion=2.0、buildId=release 的未成功事件进入符号表页
- **THEN** 预填两个原值并选择 mapping 类型，不使用当前其他版本、最近上传记录或文件修订号代替应用版本

### Requirement: 浏览器请求的项目范围与凭据安全

前端 MUST 使用当前服务端用户会话访问 Crash 查询接口，并为每个请求绑定路由中的当前项目范围。服务端 MUST 根据认证主体与项目成员关系独立授权，MUST NOT 把 `X-Project-Id`、`X-User-Project-Ids`、URL 参数或浏览器状态视为用户身份及成员关系证明。前端 MUST NOT 在浏览器代码、请求、存储或日志中使用 Crash 上报用的 `X-Project-Key` 或其他项目密钥。

#### Scenario: 请求当前项目数据

- **WHEN** 已登录项目成员为当前项目发起任一 Crash 查询
- **THEN** 请求携带服务端会话并绑定当前项目路径，服务端确认成员关系后返回数据，且浏览器不会发送上报项目 Key

#### Scenario: 切换项目后查询

- **WHEN** 用户从一个项目切换到另一个有权访问的项目
- **THEN** 页面清理或重新校验旧项目的查询结果，后续请求只使用新项目范围，不能将旧项目数据显示在新项目页面中

#### Scenario: 访问无成员关系的项目

- **WHEN** 已登录用户通过修改 URL 或请求头访问没有成员关系的项目 Crash 页面
- **THEN** 服务端拒绝查询并使用不泄露项目是否存在的响应，页面不展示目标项目或旧项目数据

#### Scenario: 会话失效后查询

- **WHEN** Crash 查询返回未认证或会话过期响应
- **THEN** 页面停止展示当前项目的受保护数据并进入统一的重新登录流程

### Requirement: 当前代码单事件任务入口
页面 MUST 允许 OWNER、ADMIN、DEVELOPER 为当前 JVM fatal 事件创建任务，VIEWER 只读，并展示已有 taskId 的自然语言分析或修复指引。入口资格 MUST 依据事件事实及可用当前堆栈，不依赖 rawCrash 字段或等待后台成功。MUST 明示针对宿主当前项目，网页创建不代表本地进程已启动；MUST NOT 要求分析专用 buildId、commitSha、仓库映射、混淆声明或核验依据。切换应用、事件和会话失效 MUST 清理旧状态并拒绝迟到响应。

#### Scenario: 没有构建登记
- **WHEN** 用户为有当前堆栈的事件创建任务，未登记源码或未上传 mapping
- **THEN** 提供当前代码任务入口及符号局限，不要求填写构建 SHA

#### Scenario: 分析与修复指令
- **WHEN** 用户选择仅分析或明确分析并修复
- **THEN** 指引分别表达只读分析与本地修改授权，网页不自行启动宿主或宣称修复已完成

#### Scenario: 成功事件没有原始副本
- **WHEN** 已还原事件仅有固定还原输出
- **THEN** 分析入口仍可用，新任务使用该输出并标明材料类型，不能伪造原始链

### Requirement: 最小 Worker 配置
设置页 MUST 保留管理员 Worker 凭据创建、分页、到期和撤销，删除构建源码登记表单、登记列表及更正入口。凭据 MUST 只表述当前应用访问范围，不再固定 performance 或仓库类型；不提供模型管理或秘密值持久化。一次展示的完整值 MUST 在关闭、离页、应用/角色切换和认证失效时清除。

#### Scenario: 配置入口
- **WHEN** OWNER/ADMIN 打开本地分析配置
- **THEN** 可管理应用 Worker 身份，不出现 APK 源码登记或独立 DeepSeek 密钥说明

#### Scenario: 普通成员和秘密清理
- **WHEN** DEVELOPER 尝试管理 Worker 或显示完整凭据后离开页面
- **THEN** 管理操作被拒绝，完整凭据不进入浏览器存储并从运行内存清除

### Requirement: 当前代码分析修复和验证展示
报告 MUST 明示当前工作区材料与历史 APK 可能不一致，展示宿主提供的源码片段、提交时当前位置匹配结果及核验局限，明确修改与验证为宿主报告，分别显示分析结论、未修复/已修改/冲突/部分完成/失败及验证结果。MUST 以实际回传为准，验证未执行或失败不能显示为问题已修复；文本安全转义，当前契约内的结果有界分页。页面 MUST 只支持证据版本 3 与报告版本 4，不保留旧任务、旧证据或旧报告的只读适配、自动升级或执行入口。

#### Scenario: 原始堆栈和证据不足
- **WHEN** 没有 mapping 或当前源码无法对应冻结材料中的帧
- **THEN** 显示符号或历史差异未知，允许展示当前契约的证据不足报告，不伪造完整定位

#### Scenario: 修改完成测试失败
- **WHEN** 报告包含已修改文件及失败或未执行的验证
- **THEN** 分开呈现两种事实，不以报告 SUCCEEDED 显示修复验证通过

#### Scenario: 不支持的分析格式
- **WHEN** 响应使用非当前证据或报告格式
- **THEN** 显示协议不匹配或资源不可用，不尝试旧版只读渲染或格式转换

### Requirement: 宿主来源及停止事实
页面 MUST 展示宿主来源、未知模型和用量，区分报告保存、本地工具关闭与宿主停止。停止未知 MUST 阻止重试；管理员实际核验入口 MUST 保留审计依据，不能把宿主自报或修复完成作为停止证明。

#### Scenario: 报告完成停止未知
- **WHEN** 当前代码报告已保存但 hostStopState 为 UNKNOWN
- **THEN** 报告可读、停止未知可见，不能自动重试或声称模型已中止

### Requirement: 诊断分区可读且真实表达采集边界
详情 MUST 提供可展开的线程列表和堆栈视图；Java 线程按 Java ID、Native 线程按系统 TID 分别展示，同名不得合并。崩溃线程与主线程 MUST 清楚标记，Java ID、系统 TID、PID 与 UUID processId MUST 使用不同标签；Native 事件无法可靠关联的 Java 快照 MUST 显示关系未知。空 Java/Native 栈 MUST 显示没有取得帧的事实，不生成调用内容。

日志 MUST 可按已返回的缓冲区查看，内存 MUST 标明单位和指标口径，FD MUST 展示已知总数及已保存条目。所有分区 MUST 区分成功空结果、未采集、不可用、跳过、部分成功和截断，并呈现安全原因；零值不能显示成缺失。文本 MUST 转义，MUST NOT 作为 HTML 执行或加载诊断文本中的链接资源。缺失诊断 MUST 不阻塞主异常查看及符合事件类型的既有分析入口。应用、事件切换或会话失效 MUST 清除旧诊断和线程选择并拒绝迟到响应。页面 MUST NOT 为排除的三类内存转储提供空白占位或采集入口。

#### Scenario: 查看完整诊断
- **WHEN** 详情包含所有诊断分区
- **THEN** 用户可按线程查看当前栈，并分别查看日志、内存、FD 和环境，不需要在超长原文中手工定位

#### Scenario: 同名线程和独立还原状态
- **WHEN** 两个 JVM 辅助线程同名，一个已还原而另一个保留原始帧
- **THEN** 分别显示线程身份、当前栈和对应状态，不合并线程或沿用主异常成功标签

#### Scenario: 缺失、截断与合法零值
- **WHEN** 一个分区未采集，一个分区被裁剪，且内存或 FD 合法值为零
- **THEN** 分别显示未采集、截断和真实零值，不全部显示为空或失败

#### Scenario: 诊断文本包含脚本
- **WHEN** 日志、线程名或路径含 HTML、脚本或链接文本
- **THEN** 只作为已转义文本显示，不执行脚本、不产生隐式网络请求

#### Scenario: 切换事件时旧响应迟到
- **WHEN** 切换应用或事件后上一请求才返回
- **THEN** 旧诊断、缓冲区和线程选择不能覆盖当前事件

#### Scenario: Native 与 Java 快照并存
- **WHEN** Native 事件包含同名 Native/Java 线程及无法关联的 Java 快照
- **THEN** 按线程类型与各自 ID 分组，未知关系清楚可见，保留每线程采集状态和精确地址

### Requirement: Native Crash 事件详情展示
前端 MUST 展示 Crash 类型、信号、raw_native 寄存器、模块及原始回溯，明示未提供 Native 还原，不显示 JVM mapping、已还原来源或 JVM 分析任务入口；概览名称与混合统计保持。OWNER/ADMIN MUST 可从模块进入 SO 管理，只预填 appVersion 和可取得的 ABI、完整 ELF Build ID，不传应用 buildId；SO 页面 MUST 没有应用构建输入。已知模块身份 MUST 校验 ZIP 包含该身份，未知身份不得猜测。SO 保存成功 MUST 不显示事件已还原。

#### Scenario: Native 原始详情
- **WHEN** 打开 raw_native 事件
- **THEN** 可查看信号、寄存器、模块、原始主栈及共享诊断，显示还原能力延期说明，不出现上传 mapping、已还原来源或创建 JVM 分析任务按钮

#### Scenario: 从明确模块上传 SO
- **WHEN** 管理员选择带完整 ELF Build ID 的模块进入 SO 上传
- **THEN** 管理页预填事件版本与模块 ABI、完整 ELF Build ID，不带应用构建；目标不匹配时报错，成功只显示文件已保存

#### Scenario: 模块缺少 Build ID
- **WHEN** 模块没有可靠 ELF Build ID
- **THEN** 页面明确模块身份未知，可进入该版本构建的通用 SO 管理，但不以文件名判断已有匹配或宣称上传文件与该模块一致

#### Scenario: 应用切换及只读成员
- **WHEN** 用户切换应用、事件或符号类型，或当前角色没有写权限
- **THEN** 清除不再适用的预填模块、文件、冲突和旧请求结果，只读成员没有上传、覆盖或删除操作
