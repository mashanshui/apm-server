# jank-monitoring-frontend Specification

## Purpose

为桌面浏览器用户提供与现有卡顿服务端契约一致的指标观察、Issue 排查和采样证据下钻能力，使用户能够在项目范围内从流畅度趋势定位到具体卡顿调用路径。

## Requirements

### Requirement: 提供项目级卡顿监控入口和稳定路由

系统 MUST 在共享项目控制台中提供卡顿监控导航，并提供卡顿指标分析、问题列表、Issue 详情和单事件详情的稳定路由。所有卡顿页面 MUST 明确展示当前项目上下文，并沿用宽度不小于 1280 像素的浅色 PC 视觉和受保护路由约束。

#### Scenario: 从项目导航进入卡顿监控

- **WHEN** 已登录项目成员在项目控制台选择卡顿监控
- **THEN** 系统进入当前项目的卡顿问题列表或明确的卡顿默认入口，并在侧栏标识卡顿模块处于选中状态

#### Scenario: 直接打开卡顿深层链接

- **WHEN** 已登录项目成员直接打开某个卡顿 Issue 或事件详情地址
- **THEN** 系统恢复当前项目和对应页面上下文，不要求先经过 Crash 页面或卡顿总览

### Requirement: 展示 FPS 和设备日挂起率指标分析

系统 MUST 提供 FPS 与设备日挂起率两个指标视图，并展示查询范围汇总、时间趋势和白名单多维分析。FPS MUST 展示平均值、P50、P90、P99、总记录数和有效记录数；挂起率 MUST 使用秒/小时前台时长单位，并展示总记录数、有效设备日记录数和相应平均值及分位数。

#### Scenario: 查看指定场景的 FPS

- **WHEN** 用户选择 FPS、指定场景和时间范围并执行查询
- **THEN** 页面展示对应汇总、按请求粒度的趋势和场景或其他白名单维度结果，并明确 FPS 分位数按从高到低口径解释

#### Scenario: 查看设备日挂起率

- **WHEN** 用户选择挂起率和有效时间范围并执行查询
- **THEN** 页面按 UTC 日展示挂起秒/前台小时趋势，并展示设备日有效记录数而不是把原始区间数解释为设备数

#### Scenario: 指标没有有效值

- **WHEN** 服务端返回 `no_data`、`no_valid_data` 或 `denominator_insufficient`
- **THEN** 页面分别展示无记录、无有效 FPS 和前台分母不足状态，所有不可计算的平均值和分位数保持为空而不是显示为零

### Requirement: 展示卡顿总览、趋势和 Issue 排行

系统 MUST 在卡顿问题列表展示卡顿事件数、受影响会话数、受影响设备数、可归组事件数、精确消息耗时分位数、卡顿趋势和 Issue 排行。Issue 表格 MUST 区分精确消息耗时与估算堆栈耗时，并支持服务端允许的时间、版本、渠道、环境、Android 版本、设备型号、场景、算法版本和指纹筛选。

#### Scenario: 查询存在卡顿数据的范围

- **WHEN** 用户打开存在合法卡顿事件的项目和时间范围
- **THEN** 页面展示总览、趋势和 Issue 结果，并允许用户通过问题指纹进入对应 Issue

#### Scenario: 卡顿范围没有数据

- **WHEN** 服务端返回 `no_data` 和空 Issue 或趋势结果
- **THEN** 页面展示当前筛选范围没有卡顿数据，不伪造零分位数或虚构问题记录

#### Scenario: 总览的部分请求失败

- **WHEN** 总览、趋势或 Issue 请求中的部分请求失败
- **THEN** 页面保留已经成功返回的区域，并为失败区域提供可识别且不会重复提交的重试入口

### Requirement: 支持卡顿 Issue 和事件逐层下钻

系统 MUST 允许用户从 Issue 排行进入该指纹的事件列表，再进入单个事件详情。Issue 事件列表 MUST 保留筛选上下文、按服务端顺序展示事件，并通过游标加载后续结果且不重复已有事件。

#### Scenario: 从 Issue 查看卡顿个例

- **WHEN** 用户选择一个 Issue 并点击其中一个事件
- **THEN** 系统进入该卡顿事件详情，同时保留返回 Issue 和问题列表所需的项目、指纹与筛选上下文

#### Scenario: 加载更多 Issue 事件

- **WHEN** 服务端返回非空 `nextCursor` 且用户加载下一页
- **THEN** 页面追加未出现过的事件并保留已加载结果；追加失败时已加载结果继续可用

#### Scenario: Issue 不提供工作流字段

- **WHEN** 服务端契约没有返回负责人、处理状态、自定义标签或评论
- **THEN** 页面不伪造这些字段，也不提供无法持久化的 Issue 工作流操作

### Requirement: 展示精确卡顿耗时和采样估算证据

卡顿事件详情 MUST 分开展示精确消息总耗时和采样推导的估算耗时，并展示阈值、采样间隔、覆盖时长、未覆盖时长、未归属估算时长及期望/尝试/成功/丢弃采样数。页面 MUST 将时间片、调用树和火焰图中的耗时明确标记为估算值，且 MUST NOT 将未归属估算时长命名为 CPU 自耗时。

#### Scenario: 查看包含完整采样证据的事件

- **WHEN** 用户打开包含采样片段、调用树和堆栈字典的卡顿事件
- **THEN** 页面展示精确消息耗时摘要，并提供时间片、估算调用树和估算火焰图视图供用户切换

#### Scenario: 采样证据存在空洞

- **WHEN** 事件分析结果包含 `covered=false` 的时间片或正数未覆盖时长
- **THEN** 时间片以不同视觉明确展示空洞，调用树和火焰图不得使用精确消息总耗时填满缺失区间

#### Scenario: 调用树节点信息有限

- **WHEN** 聚合调用树只包含类名、方法名和估算时长而没有文件或行号
- **THEN** 页面仅展示服务端实际返回的信息，并可通过对应采样堆栈查看可用的文件与行号，不自行推断缺失字段

### Requirement: 保持卡顿查询状态、认证和项目隔离

卡顿筛选、指标类型、聚合粒度和下钻上下文 MUST 保存在可恢复的站内 URL 中。浏览器请求 MUST 只使用项目路径、同源 Session Cookie 和统一 CSRF/401 处理，不得发送 Android 上报 Key 或用客户端请求头声明项目权限；切换筛选、页面或项目时 MUST 取消或隔离旧请求，防止旧响应覆盖新上下文。

#### Scenario: 刷新带筛选条件的卡顿页面

- **WHEN** 用户刷新包含合法卡顿筛选参数的页面
- **THEN** 页面从 URL 恢复筛选并重新请求当前项目数据，不依赖仅存在于内存中的结果

#### Scenario: 快速切换项目或筛选

- **WHEN** 用户在旧请求完成前切换项目、指标或筛选条件
- **THEN** 页面取消旧请求或丢弃过期响应，最终只展示最新项目和查询条件对应的数据

#### Scenario: 会话失效或跨项目访问

- **WHEN** 卡顿请求返回会话失效或项目不可见错误
- **THEN** 页面沿用统一登录回跳和安全错误语义，不泄露目标项目是否存在，也不保留旧项目卡顿数据
