# web-user-authentication Specification

## Purpose

为 Android APM 网页控制台提供可验证、可恢复且可安全终止的用户会话，使受保护页面和 API 不再依赖浏览器可伪造的项目请求头作为身份来源。

## Requirements

### Requirement: 用户使用邮箱和密码登录

系统 MUST 提供邮箱与密码登录能力，成功后建立服务端会话并返回当前用户的稳定标识、显示名称和邮箱。登录失败时 MUST 使用不区分账号不存在、账号停用或密码错误的通用提示，且 MUST NOT 在响应、日志或前端状态中暴露用户密码。


认证成功时，系统 MUST 轮换请求已有的 Session ID，并使旧标识不能恢复新认证身份；无既有 Session 时 MUST 创建新的有效会话。认证失败 MUST NOT 建立已认证会话。成功响应 MUST 刷新浏览器 XSRF-TOKEN Cookie，后续写请求 MUST 使用刷新后的值，登录入口继续受到 CSRF 防护。Token 刷新 MUST 在用户发起登录后首个写操作前可用；服务端会话标识和 CSRF 值 MUST NOT 出现在响应业务 JSON 或日志中。

#### Scenario: 使用有效凭据登录

- **WHEN** 未登录用户提交有效的邮箱和密码
- **THEN** 系统建立服务端会话，返回当前用户信息，并允许用户进入其原本请求的受保护页面或项目列表

#### Scenario: 使用无效凭据登录

- **WHEN** 用户提交不存在的邮箱、停用账号或错误密码
- **THEN** 系统拒绝登录并显示统一的账号或密码错误提示，不泄露邮箱是否已注册

#### Scenario: 重复提交登录表单

- **WHEN** 登录请求尚未完成时用户再次触发提交
- **THEN** 页面保持单个进行中的登录请求并禁用重复提交，同时保留邮箱输入且不回填密码

#### Scenario: 已有匿名会话登录
- **WHEN** 浏览器携带已有匿名 Session ID 和有效 CSRF 值提交正确凭据
- **THEN** 返回成功并更新 Session Cookie，旧 Session ID 再次请求受保护 API 时无法获得已认证身份

#### Scenario: 没有已有会话登录
- **WHEN** 浏览器完成 CSRF 引导后，在无已有 Session 的情况下提交正确凭据
- **THEN** 创建可恢复的登录会话，并返回刷新后的 CSRF Cookie

#### Scenario: 登录后的首个写请求
- **WHEN** 登录成功后浏览器立即使用最新 Cookie 和对应 CSRF 请求头修改有权访问的应用
- **THEN** 请求通过 CSRF 校验并依照应用角色执行，不要求用户重新登录或刷新页面

#### Scenario: 新 Cookie 携带旧 CSRF 请求头
- **WHEN** 浏览器携带登录成功响应设置的新 XSRF-TOKEN Cookie，但提交登录前的 CSRF 请求头
- **THEN** 请求被拒绝，不执行写操作

#### Scenario: 失败登录与退出回归
- **WHEN** 无效凭据登录，或成功登录后退出并尝试恢复该会话
- **THEN** 无效凭据不建立认证身份，退出会话不能恢复身份，原有统一登录失败提示保持不变

### Requirement: 网页恢复和保护用户会话

系统 MUST 在网页启动和进入受保护路由前确认当前服务端会话。未登录用户 MUST 被引导到登录页并保留安全的站内目标地址；已有有效会话的用户访问登录页时 MUST 被引导到项目列表或目标页面。浏览器 MUST 使用安全 Cookie 携带会话，且 MUST NOT 把访问令牌、会话标识或密码写入 `localStorage`、`sessionStorage` 或 URL。

#### Scenario: 刷新已登录页面

- **WHEN** 已登录用户刷新任一受保护页面且服务端会话仍有效
- **THEN** 页面恢复当前用户信息并继续显示该页面，不要求用户重新登录

#### Scenario: 未登录访问受保护页面

- **WHEN** 未登录用户直接打开项目或 Crash 路由
- **THEN** 页面跳转到登录页并记录经过校验的站内目标地址，登录成功后返回该地址

#### Scenario: 登录用户访问登录页

- **WHEN** 已有有效会话的用户打开登录页
- **THEN** 页面跳转到其安全目标地址或项目列表，不再次显示登录表单

### Requirement: 会话过期处理

系统 MUST 对会话过期或失效使用一致的未认证响应。前端收到该响应后 MUST 清理当前用户信息和项目相关页面状态，跳转到登录页，并明确提示会话已过期；过期前显示的数据不得继续作为已授权数据展示。

#### Scenario: 页面使用期间会话过期

- **WHEN** 任一受保护 API 返回会话已过期或未认证响应
- **THEN** 页面清理认证与项目状态，跳转登录页并显示会话过期提示，同时保留安全的当前站内地址用于重新登录后返回

### Requirement: 用户安全退出登录

系统 MUST 提供退出登录操作，在服务端使当前会话失效并清除浏览器会话 Cookie。退出请求和其他会改变状态的网页请求 MUST 受到 CSRF 防护。

#### Scenario: 正常退出

- **WHEN** 已登录用户在用户菜单中确认退出
- **THEN** 服务端使当前会话失效，页面清理用户与项目状态并跳转到登录页

#### Scenario: 使用已退出会话访问 API

- **WHEN** 浏览器在退出后再次请求任一受保护 API
- **THEN** 系统返回未认证响应且不返回用户或项目数据
