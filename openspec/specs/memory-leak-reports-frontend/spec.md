# memory-leak-reports-frontend Specification

## Purpose

为授权应用成员提供基于 SDK 分析报告的 Java 内存泄漏问题页面，通过筛选、发生趋势、设备影响和可展开引用链帮助定位重复疑似问题，清楚区分没有数据与请求失败，并避免展示报告无法支持的内存量结论。

## Requirements

### Requirement: 提供应用内泄漏问题入口

前端 MUST 在内存指标旁提供 Java 内存泄漏入口及 /apps/:appId/memory-leaks 路由，使用现有 Session 和应用上下文。页面 MUST 包含筛选、趋势、问题表三个区域，仅消费授权后端 API。首版 MUST 不提供 HPROF 解析、内存详情路由、工单、标签、备注或条件对比功能。

#### Scenario: 导航与权限
- **WHEN** 已登录应用成员打开泄漏入口
- **THEN** 显示当前应用页面；未登录执行现有登录跳转，无应用权限显示访问失败

### Requirement: 筛选可恢复且状态隔离

页面 MUST 支持服务端定义的时间、版本、设备、进程、场景、厂商、sdkInt、触发原因、匿名设备、signature 和关键词筛选，基础筛选外的字段可折叠。筛选、分页、排序和趋势粒度 MUST 保存到 URL，修改筛选重置第一页；切换应用不得展示旧应用请求结果。列表与趋势 MUST 独立显示加载、错误、重试和空数据状态。

#### Scenario: 深链接与请求竞态
- **WHEN** 用户刷新带筛选 URL，随后快速切换应用
- **THEN** 恢复合法查询条件，旧请求不能覆盖新应用数据

#### Scenario: 单区域失败
- **WHEN** 列表成功而趋势失败
- **THEN** 保留列表并在趋势区域提供错误和重试，不显示虚假的零值趋势

### Requirement: 展示发生与设备趋势

页面 MUST 提供发生次数/影响设备数切换及5分钟、小时、天粒度，显示服务端零值空桶。页面 MUST 不对每桶设备数求和冒充全区间设备数，不展示泄漏内存P50、影响用户、复现率或累计趋势。

#### Scenario: 同设备跨桶
- **WHEN** 同一设备在两个时间桶报告同一问题
- **THEN** 两桶各显示一个设备，全区间总设备数仍以服务端去重结果为准

### Requirement: 聚合列表与行内引用链

页面 MUST 显示问题类名、SDK 原因、signature、引用链摘要、最近发生时间、次数及占比、影响设备及占比、版本集合和分页排序。引用链 MUST 可在行内展开，展示 gcRoot、referenceType、declaredClass（若存在）和 reference，保留原顺序，长内容可阅读。内容 MUST 按文本安全渲染；未知或缺失信息不替换为零。页面 MUST 标明为 SDK 报告的疑似问题，不将大数组阈值等原因统一重命名为已确认 Activity 泄漏；不显示无来源的最大泄漏内存。

#### Scenario: 展开与收起
- **WHEN** 用户展开一个问题
- **THEN** 当前页显示该问题的完整引用链，无需进入详情页，收起后保留筛选和分页

#### Scenario: 无法支持的内存量
- **WHEN** 报告仅包含语义不明的 size
- **THEN** 页面不显示最大泄漏内存或 retained size，类名和引用字段中的 HTML 字符按普通文本显示
