# desktop-web-console Specification

## Purpose

为登录、项目管理和 Crash 分析提供一致的浅色 PC 控制台信息架构，使桌面浏览器用户能够清楚识别当前用户、当前项目和可执行操作。

## Requirements

### Requirement: 控制台采用统一浅色 PC 视觉

网页控制台 MUST 使用统一的浅色视觉变量和组件状态，页面背景、侧栏、面板、表单、表格、提示与交互反馈 MUST 在浅色背景下保持清晰层级和可读对比度。设计与验收范围 MUST 面向宽度不小于 1280 像素的 PC 浏览器，不要求为移动端或窄屏提供折叠导航、卡片重排或触控专用交互。

#### Scenario: 在标准 PC 视口访问

- **WHEN** 用户在 1280、1440 或 1920 像素宽的桌面视口打开登录页或控制台页面
- **THEN** 页面保持稳定的浅色布局，主要导航、标题、表单和主要操作无需横向滚动即可使用

#### Scenario: 在窄屏访问

- **WHEN** 用户在小于 1280 像素宽的视口打开控制台
- **THEN** 系统不承诺移动端重排或折叠菜单，但不得因为隐藏主要操作而形成看似支持移动端的错误体验

### Requirement: 控制台明确展示用户和应用上下文

受保护页面 MUST 使用共享控制台布局，展示产品标识、当前用户入口、应用切换器和应用级导航。应用上下文页 MUST 以当前应用名称作为主要展示文本，并明确展示包名或 `appId` 等辅助身份信息；应用列表和创建应用页 MUST 使用不依赖当前应用的工作区导航。所有稳定页面地址 MUST 使用 `/apps/{appId}`，不得继续生成 `/projects/{projectId}` 地址。

#### Scenario: 查看项目内页面

- **WHEN** 用户打开应用设置、Crash 或卡顿页面
- **THEN** 共享布局显示当前用户、当前应用以及可用的应用分析和设置导航

#### Scenario: 查看项目工作区页面

- **WHEN** 用户打开应用列表或创建应用页面
- **THEN** 页面保持产品与用户上下文，但不伪造当前应用或显示只适用于某个应用的选中导航

### Requirement: 应用切换不会串用旧应用数据

应用切换器 MUST 只列出当前用户有权限的应用。切换应用后，系统 MUST 进入目标应用的稳定入口并清理或重新校验旧应用的数据、筛选、凭据和写入状态，不得把旧应用内容显示在新应用上下文中。

#### Scenario: 从 Crash 详情切换项目

- **WHEN** 用户在某应用的 Crash 详情页选择另一个应用
- **THEN** 页面进入目标应用的 Crash 总览并重新加载数据，不复用原应用的事件详情、问题指纹或 App Key

#### Scenario: 用户只有一个项目

- **WHEN** 当前用户只有一个可访问应用
- **THEN** 应用切换器仍明确显示该应用，并提供返回应用列表的入口而不展示虚假的其他选项

### Requirement: 路由回退使用真实工作区

系统 MUST 为未知路由显示明确的未找到页面或引导到应用列表，且 MUST NOT 自动进入硬编码的演示应用。登录后若用户没有可访问应用，默认入口 MUST 为应用空状态；若用户有应用，应用列表仍 MUST 可作为稳定入口。旧 `/projects/*` 路由 MUST NOT 作为兼容别名重定向到新应用路由。

#### Scenario: 打开未知路由

- **WHEN** 已登录用户访问未匹配地址或旧 `/projects/{projectId}` 地址
- **THEN** 页面显示未找到状态并提供返回应用列表的操作，不推断或重定向到某个 `appId`

#### Scenario: 登录后没有项目

- **WHEN** 登录成功且当前用户没有任何可访问应用
- **THEN** 页面进入应用列表的空状态并提供创建应用入口

### Requirement: 页面操作状态可识别且可操作

登录、应用列表、应用创建和应用设置页面 MUST 为加载、空结果、校验失败、权限只读、请求失败、保存中和保存成功提供明确反馈。所有输入 MUST 有可关联的可见标签，键盘焦点 MUST 可见，主要操作 MUST 能通过键盘完成。

#### Scenario: 保存项目设置

- **WHEN** 有编辑权限的用户提交应用显示名称或描述设置
- **THEN** 页面在请求期间阻止重复提交，并在成功或失败后显示对应反馈

#### Scenario: 使用键盘操作表单

- **WHEN** 用户仅使用键盘访问登录或应用表单
- **THEN** 用户能够按合理顺序定位输入与按钮、识别焦点并提交表单

### Requirement: 控制台提供卡顿分析导航并保持模块上下文

应用控制台 MUST 在 JVM Crash 之外提供卡顿监控导航，并明确区分卡顿指标分析和卡顿问题分析。用户从任一卡顿页面切换应用时，系统 MUST 进入目标应用的对应卡顿稳定入口并重新请求数据，不得默认跳回无关模块或复用旧应用的 Issue、事件、指标结果、App Key 和筛选状态。

#### Scenario: 在项目控制台查看卡顿导航

- **WHEN** 用户打开任一有应用上下文的控制台页面
- **THEN** 侧栏提供卡顿监控入口，并在卡顿页面正确标识当前卡顿子模块

#### Scenario: 从卡顿指标页切换项目

- **WHEN** 用户在某应用的卡顿指标页选择另一个可访问应用
- **THEN** 页面进入目标应用的卡顿指标页，保留兼容的指标视图但重新加载目标应用数据

#### Scenario: 从卡顿详情页切换项目

- **WHEN** 用户在卡顿 Issue 或事件详情页选择另一个可访问应用
- **THEN** 页面进入目标应用的卡顿问题列表，不携带原应用的指纹、事件 ID、游标或详情数据

### Requirement: 控制台创建并展示应用上报凭据

创建应用页面 MUST 展示 `name`、`description` 和全平台唯一的小写 Android 包名三个输入项，其中只有 `packageName` 必填，并在提交前提供与服务端一致的格式校验。`name` 为空时页面和服务端 MUST 使用包名作为默认显示名称，`description` 为空时保存为空。应用列表、应用切换器、面包屑和应用工作区标题 MUST 以 `name` 作为主要展示文本，并可将 `packageName` 作为辅助技术信息展示。应用设置页 MUST 为所有应用成员展示只读 `appId` 与 `packageName`；只有 `OWNER` 与 `ADMIN` 可以按需查询、显示和复制完整 App Key。页面 MUST 默认不请求、不显示完整 App Key，MUST NOT 把完整 App Key 放入应用列表、普通应用状态、URL、Web Storage、日志或长期缓存，并 MUST 在离开应用、切换应用、查询失败或会话失效时清除内存中的完整 App Key。

#### Scenario: 创建应用时填写名称、描述和包名

- **WHEN** 用户打开创建应用页面，填写名称、描述以及合法且尚未注册的 `packageName`
- **THEN** 页面提交三个字段，创建应用并进入 `/apps/{appId}/settings`，应用列表和设置页展示用户填写的名称与描述以及系统生成且不可修改的 `appId` 和包名

#### Scenario: 创建应用时只填写包名

- **WHEN** 用户只填写合法且尚未注册的 `packageName`，名称和描述保持为空
- **THEN** 页面成功创建应用，使用包名作为显示名称、描述为空，并进入 `/apps/{appId}/settings`

#### Scenario: 创建应用时包名非法或重复

- **WHEN** 用户输入空包名、包含大写字母、只有一个分段、包含不允许字符或服务端返回 `PACKAGE_NAME_CONFLICT`
- **THEN** 页面在包名字段显示对应错误、保留输入，并且不显示不明确的创建成功状态

#### Scenario: Owner 查看并复制 App Key

- **WHEN** 应用 `OWNER` 或 `ADMIN` 在设置页明确触发查看 App Key
- **THEN** 页面通过独立凭据接口取得完整 App Key、显示隐藏与复制入口，并保持普通应用 Store 中不存在该 Key

#### Scenario: Developer 查看应用设置

- **WHEN** `DEVELOPER` 或 `VIEWER` 打开应用设置页
- **THEN** 页面展示只读 `appId` 与包名，但不展示 App Key、查看按钮或复制按钮

#### Scenario: 凭据查询失败

- **WHEN** 有权限用户查询 App Key 时收到权限、会话或服务错误
- **THEN** 页面清除任何旧 App Key、提供与错误类型一致的反馈，并保持应用其他基础信息可用

#### Scenario: 切换应用后清除 App Key

- **WHEN** 用户已显示一个应用的完整 App Key 后切换应用、离开设置页或会话失效
- **THEN** 页面立即清除内存中的完整 App Key，不在目标应用页面短暂显示旧应用凭据
