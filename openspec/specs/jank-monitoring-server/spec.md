# jank-monitoring-server Specification

## Purpose

为后续 Android SDK 提供稳定、可版本化的卡顿数据上报契约，并由服务端完成卡顿 Issue、场景 FPS 和设备日挂起率的可靠存储、统一统计与受权限保护的查询。

## Requirements

### Requirement: 接收三类卡顿监控事件
系统 MUST 通过 `POST /ingest/v1/stack-artifacts:parse` 接收 `schemaVersion=2 / artifactType=RHEA_JANK` 的卡顿个例压缩包，并在现有批量上报入口继续支持 `eventType=frame_scene_summary` 和 `eventType=foreground_suspension_summary`。批量入口 MUST 不再接受 `eventType=jank` 的结构化 JSON 载荷；不匹配、缺失或同时携带多个专用载荷的批量事件 MUST 继续作为不可重试的事件级错误拒绝。

#### Scenario: 分别接受卡顿个例和指标事件
- **WHEN** 客户端通过压缩包入口上传合法卡顿个例，并通过批量入口上传合法的场景帧指标汇总和前台挂起汇总
- **THEN** 系统分别完成卡顿个例落库和指标事件部分接受处理，三类数据均进入现有查询与统计链路

#### Scenario: 拒绝批量 JSON 卡顿个例
- **WHEN** 批量上报事件声明 `eventType=jank`
- **THEN** 系统拒绝该事件并返回稳定、不可重试的卡顿传输方式错误，提示改用卡顿压缩包入口

#### Scenario: 拒绝指标载荷类型不匹配
- **WHEN** 帧指标或前台挂起事件缺少对应载荷，或携带其他类型的专用载荷
- **THEN** 系统拒绝该事件并返回稳定、不可重试的载荷类型错误

### Requirement: 校验卡顿个例的精确时间和采样证据
卡顿个例压缩包 MUST 包含正数的主线程消息总耗时、卡顿阈值、场景和最小采样间隔，并 MUST 能解析出 `processId` 对应主线程的至少一个有效堆栈 segment。采样时间 MUST 表示相对该次消息开始的单调时钟偏移并落在消息区间内；服务端 MUST NOT 将跨设备单调时钟值解释为墙上时间。客户端 MUST 按当前 processor 契约提供 `attemptedSampleCount`，但服务端 MUST 忽略该值；实际采样数量 MUST 由服务端解析主线程证据得到。

#### Scenario: 接受带主线程证据的卡顿个例
- **WHEN** 卡顿压缩包包含精确消息边界、合法主线程采样证据和完整文件校验信息
- **THEN** 系统保留精确总耗时和解析证据，派生采样数量，并将该事件纳入卡顿统计和 Issue 归组

#### Scenario: 拒绝消息区间外或无效的采样证据
- **WHEN** 解析结果的主线程采样偏移不在消息区间内、堆栈为空或无法识别目标主线程
- **THEN** 系统拒绝该事件并返回不可重试的卡顿证据错误

#### Scenario: 服务端忽略客户端尝试采样数
- **WHEN** processor 成功解析包含 `attemptedSampleCount` 的卡顿 manifest
- **THEN** 服务端不读取或保存该值，并完全根据主线程 segments 派生正式采样质量数据

### Requirement: 区分精确卡顿耗时与估算堆栈耗时
系统 MUST 将主线程消息总耗时标记为精确测量值，将基于解析 segments 和采样间隔推导的调用树总耗时与未归属耗时标记为估算值。系统 MUST 保存服务端派生的 `parsedSampleCount`、`expectedSampleCount` 和 `missingSampleCount` 以及算法版本、采样间隔和覆盖范围，且 MUST NOT 把这些估算字段命名或解释为精确方法耗时、CPU 自耗时或客户端确认的丢弃次数。

#### Scenario: 查询卡顿事件耗时证据
- **WHEN** 已授权用户查询一个由卡顿压缩包生成的事件
- **THEN** 响应分别返回精确消息总耗时、明确标记为估算的调用树耗时，以及服务端派生的采样数量和覆盖质量

#### Scenario: 采样存在空洞
- **WHEN** 相邻样本间隔超过算法允许的连续覆盖上限，或理论采样数量大于解析数量
- **THEN** 系统保留未覆盖区间和 `missingSampleCount`，不使用卡顿总时长、报告总记录数或客户端字段填满该空洞

### Requirement: 限制、脱敏和保护卡顿载荷
系统 MUST 对场景、属性、堆栈、采样数量、堆栈深度、字典规模和单事件体积实施配置化上限，并在存储前对允许的文本字段执行规范化、脱敏和截断。完整卡顿载荷、堆栈和设备标识 MUST NOT 写入服务端日志。

#### Scenario: 卡顿详情超过限制
- **WHEN** 卡顿事件的采样数、堆栈帧数、字典规模或解压后体积超过配置上限
- **THEN** 系统拒绝该事件，返回不可重试的大小错误，并且不写入部分详情

#### Scenario: 文本字段包含敏感动态值
- **WHEN** 场景、属性或堆栈文本包含路径参数、标识符或其他受限制内容
- **THEN** 系统按照白名单和脱敏规则存储规范化结果，日志只保留事件 ID、错误类别和计数

### Requirement: 卡顿事件幂等和部分接受
系统 MUST 以 `projectId + eventId` 识别卡顿个例压缩包和其他卡顿指标事件的重试，并保证同一逻辑事件不会重复计入明细、Issue、FPS 或挂起率统计。单个卡顿压缩包 MUST 返回 `accepted` 或 `duplicate` 的最小成功结果；指标批次中的单条永久错误 MUST NOT 阻止其他合法事件写入；临时存储故障 MUST 使用现有可重试响应语义。

#### Scenario: 重复上报卡顿压缩包
- **WHEN** 客户端使用同一 `eventId` 重试已经接受的卡顿压缩包
- **THEN** 系统返回 `duplicate` 成功状态，且卡顿次数、Issue 次数和受影响设备数不增加

#### Scenario: 指标批次部分合法
- **WHEN** 同一批次包含合法帧指标事件和字段非法的前台挂起事件
- **THEN** 系统写入合法事件、拒绝非法事件，并返回准确的接受数、拒绝数和事件级错误

### Requirement: 服务端生成版本化卡顿 Issue 指纹
系统 MUST 根据项目、应用、规范化后的关键应用堆栈和必要的稳定上下文生成服务端卡顿指纹，并保存指纹版本。行号、内存地址、采样次数和其他动态值 MUST NOT 导致相同根因被不必要拆组；客户端提供的指纹 MUST NOT 作为正式 Issue 身份。

#### Scenario: 相同根因归为同一 Issue
- **WHEN** 两个卡顿事件的关键应用调用路径相同，但行号、采样数量或动态标识不同
- **THEN** 系统生成相同版本的卡顿指纹，同时保留各事件独立的精确耗时和采样详情

#### Scenario: 不同关键调用路径分组
- **WHEN** 两个卡顿事件的规范化关键应用调用路径不同
- **THEN** 系统将其归入不同 Issue，除非后续通过新指纹版本明确重新归组

### Requirement: 提供卡顿总览、趋势、Issue 和事件查询
系统 MUST 提供项目范围内的卡顿总览、时间趋势、Issue 排行、Issue 个例列表和单事件详情查询。查询 MUST 支持时间、应用版本、渠道、环境、Android 版本、设备型号、场景、指纹和算法版本筛选，并限制最大时间范围、返回数量、游标和执行时间。


总览、趋势、Issue 和事件页 MUST 基于筛选时间窗内全部逻辑事件计算，`limit` MUST 只控制列表返回条目，MUST NOT 截断统计输入。去重、计数、设备/会话集合和耗时分位数 MUST 在内存验证模式与持久化模式保持一致；分位数使用升序第 `max(1, ceil(N*p))` 个有效值，无有效值返回 null。总览及趋势收到合法 limit 时仍 MUST 返回完整统计，非列表入口携带 cursor MUST 返回 `400 INVALID_CURSOR`。

Issue MUST 按事件数降序、最近发生时间降序、指纹升序；事件 MUST 按发生时间降序、事件 ID 升序。列表 MUST 返回版本化不透明 nextCursor，绑定应用、列表类型、首次实际绝对时间窗、全部有效筛选及排序位置。继续请求省略时间时 MUST 恢复原时间窗；旧格式、损坏、跨应用、跨指纹、跨列表或筛选不匹配的游标 MUST 返回 `400 INVALID_CURSOR`，不得回到第一页。静态数据集在同一查询上下文下 MUST 能完整遍历且不重不漏；游标不承诺新增或迟到事件下的快照一致性。

查询 MUST 受执行时间、扫描行数/字节数、数据库内存及响应字节预算保护；超时返回 `408 QUERY_TIMEOUT`，资源超限返回 `422 QUERY_RESOURCE_LIMIT`，存储不可用返回可重试的 `503 EVENT_STORE_UNAVAILABLE`。失败 MUST NOT 返回空数据或带成功状态的部分统计。网页与只读 Agent 查询 MUST 共用统计语义，允许各自保留已发布的页大小上限。

#### Scenario: 查询卡顿总览
- **WHEN** 已授权用户查询存在卡顿数据的项目和时间范围
- **THEN** 系统返回卡顿次数、受影响会话数、受影响设备数、精确卡顿耗时分位数和可归组事件数

#### Scenario: 查询 Issue 排行
- **WHEN** 已授权用户按相同筛选条件查询卡顿 Issue
- **THEN** 系统返回指纹版本、事件数、受影响设备数、首次和最近发生时间、精确卡顿耗时分位数及明确标记的估算关键堆栈耗时分位数

#### Scenario: 下钻单个卡顿事件
- **WHEN** 已授权用户通过 Issue 选择一个事件
- **THEN** 系统返回公共事件信息、精确消息耗时、场景、采样时间片、调用树、堆栈字典、估算字段和采集质量

#### Scenario: 查询范围无数据
- **WHEN** 筛选范围内没有合法卡顿事件
- **THEN** 系统返回明确的 `no_data` 状态和空结果，不伪造零分位数

#### Scenario: 跨项目访问卡顿数据
- **WHEN** 当前用户不是目标项目成员，或无权查看该项目
- **THEN** 系统拒绝总览、Issue 和事件详情查询，不泄露目标项目是否存在

#### Scenario: 事件数量超过默认页大小
- **WHEN** 一个时间窗包含 120 个唯一事件、60 个 Issue，并分别使用 limit=20 和 limit=50 查询
- **THEN** 总览和趋势均覆盖 120 个事件；Issue 计数及耗时分位数覆盖该 Issue 全部事件，不随页大小改变

#### Scenario: 多页遍历及并列排序
- **WHEN** 静态数据中存在超过一页的 Issue 和同一 Issue 下的事件，且部分排序值相同
- **THEN** 连续使用 nextCursor 可遍历全部匹配条目，最后一页游标为空，条目不重复、不遗漏

#### Scenario: 省略时间的续页请求
- **WHEN** 首次查询省略 from/to，并在稍后持相同筛选和 nextCursor 继续查询
- **THEN** 系统沿用首次响应的绝对时间窗，返回稳定排序的后续页

#### Scenario: 游标与查询上下文不匹配
- **WHEN** 用户提交旧纯指纹游标、损坏游标，或更换应用、指纹、场景、算法版本、时间或其他筛选后复用旧游标
- **THEN** 系统返回 `400 INVALID_CURSOR`，不返回第一页或其他查询的数据

#### Scenario: 查询预算耗尽
- **WHEN** 合法查询超过执行时间、扫描量、数据库内存或响应字节预算
- **THEN** 系统返回对应的 408 或 422 错误，不返回部分计数或截断趋势

#### Scenario: 网页与 Agent 对照
- **WHEN** 网页用户与该应用查询 Token 对同一静态数据集使用相同筛选
- **THEN** 两种入口得到相同总数、分位数和排序，在各自页大小下均能遍历完整结果

### Requirement: 接收并统计场景帧指标
场景帧指标汇总 MUST 包含场景、统计区间、真实 UI 刷新帧数、活跃渲染时长、刷新率、归一化 FPS、帧指标算法版本和必要的帧耗时分布计数。零刷新帧、非正活跃时长、越界 FPS 或服务端不支持的算法版本 MUST 作为不可重试错误拒绝。

#### Scenario: 接受合法场景帧汇总
- **WHEN** 事件包含至少一帧真实 UI 刷新、合法统计区间和受支持的 FPS 算法版本
- **THEN** 系统保存该场景记录，并可按场景、版本、设备和时间范围查询

#### Scenario: 静止场景不稀释 FPS
- **WHEN** 场景在统计区间内没有真实 UI 刷新帧
- **THEN** 系统拒绝该记录并返回不可重试的帧数据错误，不将静止停留时间作为 FPS 分母

#### Scenario: 计算 FPS 尾部分位数
- **WHEN** 查询范围内存在多条兼容算法版本的场景 FPS 记录
- **THEN** 系统按 FPS 从高到低计算平均值、P50、P90 和 P99，并满足 `P50 >= P90 >= P99`

#### Scenario: 算法版本不兼容
- **WHEN** 查询范围包含不能安全合并的多个 FPS 算法版本
- **THEN** 系统按算法版本拆分返回结果，禁止把不兼容记录合并为一个分位数

### Requirement: 接收并统计设备日挂起率
前台挂起汇总 MUST 包含统计区间、前台总时长、超过阈值帧间隔的完整累计挂起时长、挂起次数、阈值和算法版本。服务端 MUST 先按项目、匿名设备、UTC 日期及查询维度合并区间，再以“累计挂起秒数除以前台小时数”计算设备日挂起率，最后在设备日记录上计算分位数。

#### Scenario: 计算设备日挂起率
- **WHEN** 同一设备在一个 UTC 日期内上报多条合法前台挂起汇总
- **THEN** 系统先合并累计挂起时长和前台时长，再生成一条设备日挂起率记录

#### Scenario: 同一设备重复事件不放大挂起率
- **WHEN** 某条前台挂起汇总以相同 `eventId` 重试
- **THEN** 设备日前台时长、挂起时长和挂起次数只累计一次

#### Scenario: 查询挂起率分位数
- **WHEN** 查询范围内存在多个有效设备日挂起率
- **THEN** 系统按挂起率从低到高返回平均值、P50、P90 和 P99，并同时返回有效设备日记录数

#### Scenario: 缺少有效前台分母
- **WHEN** 记录的前台时长不为正数，或查询范围内没有有效设备日前台时长
- **THEN** 上报记录被拒绝，或查询返回 `denominator_insufficient`，而不是将挂起率显示为零

### Requirement: 提供卡顿指标趋势和多维查询
系统 MUST 提供场景 FPS 和设备日挂起率的趋势与多维查询，至少支持时间、应用版本、渠道、环境、Android 版本、设备型号、场景和算法版本筛选。趋势查询 MUST 通过项目范围内的稳定 HTTP API 接受 `metric` 和 `interval`，其中 FPS 支持 `hour` 与 `day`，设备日挂起率仅支持 UTC `day`；不支持的指标、粒度或维度 MUST 返回稳定参数错误。响应 MUST 按时间桶和算法版本返回平均值、P50、P90、P99、总记录数、指标对应的有效记录数、状态和数据源，并保持时间桶左闭右开。挂起率趋势 MUST 先按项目、匿名设备、UTC 日期和查询维度合并设备日记录，再计算每个 UTC 日时间桶的分位数，不得按小时拆分或重复计算同一设备日。多维响应 MUST 在字段缺失时区分总上报数与该字段的有效上报数。

#### Scenario: 按场景查询 FPS 趋势
- **WHEN** 已授权用户指定场景、版本、时间范围和 `interval=hour|day` 查询 FPS
- **THEN** 系统按请求粒度和算法版本返回各时间桶的平均值、P50、P90、P99、总记录数和有效记录数

#### Scenario: 查询设备日挂起率趋势
- **WHEN** 已授权用户指定时间范围和 `interval=day` 查询设备日挂起率
- **THEN** 系统按 UTC 日期返回先合并设备日再计算的平均值、P50、P90、P99、原始区间数和有效设备日记录数

#### Scenario: 挂起率请求小时粒度
- **WHEN** 用户以 `metric=suspension_rate` 和 `interval=hour` 请求趋势
- **THEN** 系统返回稳定的 `INVALID_INTERVAL` 参数错误，不用小时区间伪造设备日挂起率

#### Scenario: 查询挂起率设备分布
- **WHEN** 已授权用户按设备型号或 Android 版本查询挂起率分布
- **THEN** 系统返回各维度值的设备日记录数、有效记录数和挂起率分位数

#### Scenario: 查询不支持的维度
- **WHEN** 用户请求未列入白名单的聚合字段
- **THEN** 系统拒绝请求并返回稳定的查询参数错误，不把任意字段拼接到数据库查询

#### Scenario: 指标趋势没有有效数据
- **WHEN** 某个时间桶没有记录、FPS 没有有效值或挂起率没有有效前台分母
- **THEN** 系统分别返回可判定的空桶或 `no_data`、`no_valid_data`、`denominator_insufficient` 状态，且不可计算的数值为 `null` 而不是零

### Requirement: 发布可供移动端对接的版本化契约
系统 MUST 在仓库中提供中文卡顿接入文档、各事件 JSON Schema、完整请求示例、字段单位与时钟语义、算法版本、大小限制、错误码、重试策略、固定数据集和期望统计。协议兼容变更 MUST 通过版本演进完成，不得静默改变既有字段含义或统计公式。

#### Scenario: 移动端按文档构造请求
- **WHEN** 移动端仅依据发布的 Schema、字段说明和示例构造合法批次
- **THEN** 服务端能够接受事件，且固定数据集查询结果与文档中的期望值一致

#### Scenario: 未知协议版本
- **WHEN** 客户端上报服务端不支持的 Schema 或算法版本
- **THEN** 系统返回稳定、不可重试的版本错误，并保留现有受支持版本行为
