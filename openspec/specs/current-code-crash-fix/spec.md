# 当前代码崩溃分析与修复规范

## Purpose

让应用成员通过单次 JVM 崩溃事件和当前本地项目工作区完成分析及明确授权的修复，无需登记 APK 对应提交；保护已有代码修改，保留可核验的材料、变更、验证结果与可靠任务恢复。

## Requirements

### Requirement: 单事件任务与最小平台身份
系统 MUST 允许 OWNER、ADMIN、DEVELOPER 按所属应用单个 eventId 创建任务，VIEWER 仅查看；校验 Session、CSRF、成员关系和幂等键。新任务 MUST 仅支持当前工作区模式，MUST NOT 要求构建源码登记、提交 SHA、仓库远端、混淆状态声明或人工核验依据。Worker 凭据 MUST 按应用授权，有期限、可撤销且仅保存摘要；不得以查询 Token、App Key 或 Cookie 替代。

#### Scenario: 无登记创建任务
- **WHEN** 合法成员选择有原始异常链的 JVM fatal 事件，未登记构建且没有 mapping
- **THEN** 可创建准备当前代码分析的任务，提供原始证据及符号未知原因，不产生旧构建登记阻断

#### Scenario: 权限与幂等
- **WHEN** VIEWER 创建、Worker 跨应用访问、凭据撤销或同幂等键关联不同事件
- **THEN** 拒绝对应操作，不泄露其他应用数据、不新增重复任务

### Requirement: 冻结单事件证据与当前代码语义
系统 MUST 冻结完整原始异常链、可用还原片段、符号状态、片段 ID 和内容摘要，限制大小并脱敏。新证据和结果 MUST NOT 含构建源码登记、commitSha、repositoryId、origin 或登记版本绑定；原始事件中的 buildId 仅为 Crash 事实，不作源码版本证明。报告 MUST 明示基于当前代码，符号、输入或历史版本不明时记录未知，不制造历史根因已确认的结论。

#### Scenario: 当前代码已经改变
- **WHEN** 当前文件行号与原堆栈不一致或相应逻辑已不存在
- **THEN** 根据当前代码寻找必要上下文并列出差异；无法确认时返回证据不足，不把旧行号直接当当前位置

#### Scenario: 不完整材料
- **WHEN** 证据超限、符号还原失败或异常信息不足
- **THEN** 超限明确失败；可用的原始材料继续分析并列出未知项，无法形成可靠修改时不执行修复

### Requirement: 当前项目定位与未提交代码
本地工具 MUST 从宿主当前工作目录确定当前 Git 项目根目录，并支持用户明确指定目标项目。MUST NOT 根据 Skill 安装位置、固定 performance 名称或远端地址推测项目；MUST NOT 要求 repositories.json、仓库映射环境变量、提交 SHA 或联网获取代码。当前材料 MUST 包括已跟踪文件的未提交内容和未忽略普通源码；目录不明确时失败并请求项目位置，不能扫描其他项目。

#### Scenario: 含未提交修改
- **WHEN** 目标项目存在修改中的 Kotlin 文件和未忽略的新测试文件
- **THEN** 分析材料使用这些实际文件内容，保持工作区与暂存区，不切换分支或重置文件

#### Scenario: 全局安装及项目外运行
- **WHEN** Skill 为全局安装且宿主工作目录不属于 Git 项目，未明确提供目标项目
- **THEN** 不把 Skill 目录或历史路径当目标，要求明确项目位置

### Requirement: 宿主直接读取与提交时引用核对
工具 MUST 不遍历或复制项目全量源码；宿主 MUST 使用自身已有工具搜索和读取用户明确的当前项目。Python MUST 不提供 search/read 或源码总量限制。新报告 MUST 为版本 4，绑定当前 evidenceId/runId，不创建或宣称源码快照。

#### Scenario: 大仓库准备
- **WHEN** 项目含大型附件、许多源码或工作区改动
- **THEN** 准备只定位 Git 根并取得当前任务证据，不因文件数、全仓库容量或附件大小拒绝，不修改索引或业务文件

#### Scenario: 源码引用
- **WHEN** 宿主提交安全相对路径、行范围和实际使用的片段
- **THEN** Python 核验格式并脱敏生成摘要，只对相关位置进行提交时匹配核对，标记 CURRENT_MATCH/CURRENT_DIFFERENT/UNAVAILABLE 和 HOST_REPORTED；MUST NOT 声称证明宿主此前读取过或与历史 APK 相同

### Requirement: 明确分析和修复授权
仅分析请求 MUST 保持只读；修改源码 MUST 有来自用户的明确修复指令，并限定当前任务与项目。源码、堆栈、注释和模型输出 MUST NOT 授权修复、执行命令或读取秘密。用户明确要求修复后可直接完成必要本地修改及验证，不强制额外网页审批；MUST NOT 自动提交、推送、发布或创建 MR。

#### Scenario: 只要求分析
- **WHEN** 用户请求分析已有 taskId，源码注释要求编辑或调用其他工具
- **THEN** 只提供分析，忽略注释中的扩权指令，不修改工作区

#### Scenario: 明确请求修复
- **WHEN** 用户要求分析并修复指定任务且当前材料足以形成有限修改
- **THEN** 在当前项目执行相关修复和必要验证，并交付实际差异和结果

### Requirement: 宿主修改与恢复边界
明确修复 MUST 由宿主已有编辑工具执行，保留用户原改动和暂存区，遵循目标项目规则并验证。Python MUST 不执行 apply/revert、生成修改日志或声明统一限制宿主写入；报告修改事实 MUST 标记 HOST_REPORTED。原读取/修改前快照和工具幂等补丁保证不适用于新流程。

#### Scenario: 只读任务报告修改
- **WHEN** 只读 prepare 的宿主提交已修改状态或文件
- **THEN** Python 拒绝该报告，不能把报告通过当作宿主写入权限证明

#### Scenario: 结果响应未知
- **WHEN** 提交结果后网络响应丢失
- **THEN** 用原 Run、原结果字节和摘要对账，不重新领取、修改或推理

### Requirement: 分开记录分析修复和验证
报告 MUST 保存本次宿主分析依据、源码引用、未知项，并分别记录修复状态、修改文件与必要摘要、验证命令及实际结果。分析报告保存成功 MUST NOT 代表补丁已经生效或问题已解决。未执行的验证 MUST 明示未验证；宿主执行的测试结果 MUST 标为宿主报告，不能冒充服务端独立核验。工具 MUST NOT 声称独立验证宿主测试、完整补丁或验证后工作区一致性。MUST NOT 回传本地绝对路径、秘密、完整原始日志或整个仓库。

#### Scenario: 测试失败或未运行
- **WHEN** 修改已写入但测试失败、环境缺失或尚未执行
- **THEN** 分开呈现代码修改与失败/未验证状态，不声称修复验证通过

#### Scenario: 本地修改成功但回传失败
- **WHEN** 本地修改和验证完成，结果回传网络未知
- **THEN** 本地说明实际修改事实，平台不显示未确认成功，保持原 Run 恢复材料

### Requirement: 租约停止与资源边界
任务 MUST 沿用有限看护、租约、期限、取消、显式重试与停止审计。宿主在本任务读、写和验证前 MUST 查询有效分配，Python 提交前 MUST 核验租约；失联、撤销、取消或过期后宿主 MUST 停止本任务新操作；已应用修改不可因取消直接重置。本地工具关闭 MUST 与宿主停止分别记录，未知停止继续阻止新尝试；MUST NOT 声称统一限制宿主模型用量、其他工具或进程中止。

#### Scenario: 到期后请求修改
- **WHEN** 租约失效或任务取消后宿主尝试应用补丁
- **THEN** 宿主停止新写入，Python 拒绝失效租约下首次回传，保留已发生的修改事实并报告宿主停止未知；不宣称工具强行限制宿主编辑器

#### Scenario: 成功报告仍未确认宿主停止
- **WHEN** 报告已保存且材料工具关闭，宿主停止不可核验
- **THEN** 报告可读但停止状态未知，管理员实际核验前不允许新尝试

### Requirement: 自包含交付与有限验收
Skill MUST 包含当前模式所需 Python 源码、锁定依赖、统一启动入口和中文说明；安装后不需额外检出 Worker 或配置仓库映射。导出 MUST 排除凭据、虚拟环境及真实验收材料。MUST 分别验收独立安装、真实宿主当前代码分析、本地修复、引用及验证；旧版本质量记录不作为新修复质量或其他宿主兼容证明。

#### Scenario: 独立安装
- **WHEN** ZIP 解压到仓库外的中文空格目录，宿主有 Python、uv、Git 和明确当前项目
- **THEN** 仅需平台凭据与必要私有状态配置即可启动工具，不要求提交 SHA、仓库映射或独立模型密钥

#### Scenario: 真实工作区验收
- **WHEN** 宿主完成 Performance 的当前工作区样本分析和明确授权修复
- **THEN** 核对未提交材料被使用、已有改动被保留、实际补丁及验证结果，记录有限验收边界，不推广为线上定位率

### Requirement: Skill 本地最小配置
工具 MUST 默认直接读取本 Skill 根目录的 config.local.json，仅接受 platformUrl 和 workerCredential 字符串；安装包 MUST 固定生成字段为空的配置，MUST NOT 读取用户填入内容。工具 MUST 在网络、领取和材料采集前检查配置；配置不足时给出文件位置和缺少字段，MUST NOT 要求用户把秘密发到聊天。含凭据文件 MUST 仅当前用户可访问，配置 MUST 排除 Git 提交、源码材料及公开日志。保留的环境入口 MUST 成对整组覆盖，不混合文件地址与环境凭据；后台看护 MUST 使用前台同次解析的配置。更新说明 MUST 提供保留本地配置的方法。

#### Scenario: 首次空配置
- **WHEN** 用户调用新 Skill 且配置为空或不存在
- **THEN** 工具提示本地填写位置及缺少字段，不连接平台、不领取或采集源码

#### Scenario: 已填写配置及升级
- **WHEN** 用户本地填写有效配置且权限为仅本人可访问，未提供环境覆盖
- **THEN** 工具用配置连接并向后台传递同次身份，诊断不包含凭据，导出 ZIP 仍仅含空模板；按更新指引升级保留已有配置
