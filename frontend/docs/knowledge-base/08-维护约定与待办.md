# 维护约定与待办

## 文档维护规则

1. 前端页面、路由、组件职责、API 消费、查询状态、配置、启动方式、测试或部署约束变化时，在同一任务中更新本知识库。
2. 新增主题页必须从本知识库 `README.md` 建立导航。
3. 只记录已经从代码、自动化测试或明确的外部验收中核对的事实。
4. 明确区分“代码已实现”“自动化测试覆盖”“外部环境冒烟验证”和“目标/待确认事项”。
5. 后端接口或统计口径变化时，同时核对平台知识库和前端消费文档，不能复制出相互独立的两套契约。
6. 代码与文档冲突时，以当前代码和已发布 API 为事实来源，并在修正文档时记录仍待确认的产品决策。
7. 当前说明原位修订，不追加逐轮任务/测试/部署记录。环境最近核验集中在平台状态页；前端测试页维护方法、最近完整基线和必要证据，不复制后端/Python 计数。
8. 普通操作结果留在任务回复/CI；有复现价值的专项证据维护唯一入口。已确认待办移入主题，历史过程由 Git 或现有专项记录追溯，完整规则见[平台维护约定](../../../docs/knowledge-base/README.md#内容归属与维护约定)。

## 改动检查表

- [ ] 路由表和页面导航是否同步。
- [ ] API 路径、请求头、查询参数和 TypeScript 类型是否同步。
- [ ] 加载、空数据、分母不足、错误和分页状态是否仍完整。
- [ ] 是否新增了跨页面状态，需要评估现有 URL + composable 模型。
- [ ] 是否补充正常路径、参数边界和关键失败分支测试。
- [ ] `typecheck`、测试和生产构建是否按风险执行。
- [ ] 是否影响身份认证、应用隔离、静态托管或代理配置。
- [ ] 本知识库及平台知识库中的必要边界说明是否同步。

## 待确认决策

- 正式生产网关、浏览器支持范围和可访问性等级。
- 是否引入 OIDC、开放注册和组织级权限。
- API 契约是否引入 OpenAPI 并生成 TypeScript 类型。
- 当前使用独立 Nginx 托管；生产域名、证书、缓存与回退策略仍需明确。
- 前端性能目标与代表性数据规模。
- 新增业务域后是否引入全局状态或请求缓存库。

应用级永久 Key 查看已实现，不再属于待办。未来若增加应用删除、Key 撤销或轮换，必须重新设计权限、确认交互和缓存清理，不能把 Key 放入通用应用 Store。
