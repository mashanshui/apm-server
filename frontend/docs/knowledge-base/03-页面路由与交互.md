# 页面、路由与交互

## 路由表

| 页面 | 路由 | 当前作用 |
|---|---|---|
| 登录 | `/login` | 邮箱密码登录、会话过期提示和安全回跳 |
| 应用列表 | `/apps` | 应用搜索、空状态、创建入口、进入 Crash/设置 |
| 创建应用 | `/apps/new` | 名称、描述可选，唯一小写 Android 包名必填；提交前校验和冲突反馈，appId 由服务端生成 |
| 应用设置 | `/apps/:appId/settings` | Owner/Admin 编辑名称描述；其他角色只读 |
| Crash 总览 | `/apps/:appId/crashes` | 统计卡片、趋势、筛选和问题排行 |
| Crash 问题事件 | `/apps/:appId/crashes/issues/:fingerprint` | 查看一个 Crash 指纹下的事件 |
| Crash 事件详情 | `/apps/:appId/crashes/events/:eventId` | 查看 Crash 元数据、异常链和堆栈 |
| 卡顿指标分析 | `/apps/:appId/jank-metrics` | FPS/设备日挂起率汇总、趋势和多维分析 |
| 内存指标分析 | `/apps/:appId/memory-metrics` | PSS、VSS、Java 堆汇总、百分位卡片和趋势 |
| 内存泄漏问题 | `/apps/:appId/memory-leaks` | SDK 报告疑似问题、UTC 趋势、筛选、分页和行内引用链 |
| 卡顿问题分析 | `/apps/:appId/janks` | 卡顿总览、趋势、筛选和 Issue 排行 |
| 卡顿 Issue 事件 | `/apps/:appId/janks/issues/:fingerprint` | 查看一个卡顿指纹下的事件并游标追加 |
| 卡顿事件详情 | `/apps/:appId/janks/events/:eventId` | 查看精确消息耗时和采样估算证据 |

所有受保护路由由 Session 守卫保护；未匹配路由显示 `/404` 风格的未找到页面并提供返回应用列表入口，不再跳转 `demo-app`。未登录访问受保护路由时保留经过校验的站内 `redirect`，登录用户打开 `/login` 时回到安全目标或 `/apps`。

共享 `AppLayout` 提供浅色侧栏、应用切换器、Crash、卡顿指标、卡顿问题、应用设置导航和用户菜单。设计基线为 1280 像素 PC，不提供移动端折叠导航或窄屏重排。卡顿指标页切换应用时保留兼容指标视图；卡顿 Issue/事件详情切换时进入目标应用问题列表并移除旧指纹、事件和游标。

## 总览页

`CrashOverviewView.vue` 同时请求总览、趋势和问题排行，并展示：

- 六张统计卡片。
- 当前查询时间范围和数据源标识。
- 小时或天粒度的 Crash 事件折线图。
- 服务端统计状态说明。
- 按事件量排序的问题表和游标“加载更多”。

当服务端返回 `denominator_insufficient` 时，计数仍可展示，但两个比例必须保持不可用，不能转成 0；`no_data` 则显示当前范围没有事件。

## 问题事件页

`CrashIssueEventsView.vue` 固定使用路由中的问题指纹，并保留其余筛选条件。事件按后端顺序展示，可通过游标继续加载；点击事件后进入详情页，同时把筛选和指纹上下文保留在 URL 中。

## 事件详情页

`CrashEventDetailView.vue` 展示事件、应用、时间、版本、构建、渠道、环境、系统、设备、会话、匿名设备、指纹和符号化状态等元数据。

- 详情元信息区由 `EventIdentityFields.vue` 统一展示“设备 ID”“启动 ID”“进程 ID”三个独立字段；即使主进程两个值相同也不合并。
- 有值字段通过浏览器剪贴板复制完整原值，缺失字段显示“—”并禁用复制；成功和失败反馈分别使用状态/警告语义，失败不显示成功。
- 身份字段为只读文本，不增加关联查询、列表、路由或 ID 跳转；当前仓库的 Crash/Jank 详情接口没有额外 processName 字段可改写，已有服务端提供的进程名称字段应继续原样展示。

- 有指纹上下文时返回问题事件页，否则返回总览。
- `raw_only` 表示当前只展示服务端脱敏后的原始异常链和堆栈，不代表已经完成反混淆。
- `applicationFrame=true` 的堆栈帧显示 `APP` 标识。
- 没有异常链时显示空状态，不伪造堆栈内容。

## 卡顿问题与 Issue 下钻

`JankIssuesView.vue` 并行加载总览、问题趋势和 Issue 排行，三个区域分别维护加载、错误和重试状态。总览展示卡顿事件、受影响会话/设备、可归组事件和精确消息 P50/P90/P99；Issue 表将精确消息耗时与采样估算堆栈耗时分列，并允许横向滚动。

`JankIssueEventsView.vue` 固定使用路由指纹，保留公共筛选上下文，按服务端游标追加事件并以事件 ID 去重。追加失败只显示区域错误，不清除已经加载的数据。页面不展示服务端未提供的负责人、状态、标签或评论。

## 卡顿事件证据

`JankEventDetailView.vue` 分开展示精确消息总耗时、卡顿阈值、采样间隔、覆盖、空洞、未归属采样估算，以及服务端派生的期望/已解析/缺失采样计数。详情元信息区复用 `EventIdentityFields.vue`，展示并复制三个身份字段，不生成任何跳转链接。

- 时间片按相对偏移绘制，覆盖片段可从堆栈字典查看实际文件和行号，空洞不分配给方法。
- 递归调用树默认折叠深层节点，只展示类名、方法名和服务端估算时长，不推断缺失位置。
- SVG 火焰图仅按调用树估算时长布局，提供节点提示和树形替代内容；最多绘制 1000 个节点以限制初始渲染规模。
- 所有采样派生值均标记为“采样估算”；未归属估算时长不命名为 CPU 自耗时。

## 卡顿指标分析

`JankMetricsView.vue` 提供 FPS 与设备日挂起率页签，分别加载区间汇总、统一趋势和多维分析。FPS 支持小时/UTC 天，使用帧/秒并按从高到低解释 P50/P90/P99；挂起率固定 UTC `day`，使用秒/小时前台时长，有效记录表示有效设备日。趋势按算法版本拆成平均值、P50、P90、P99 系列，缺失桶保持 `null` 且不连线。

页面分别处理 `no_data`、`no_valid_data` 和 `denominator_insufficient`，不可计算值显示为空，合法零值正常显示。挂起率不接受场景筛选或场景维度，切换时自动清空并回退到设备型号维度。

## 内存指标分析

`MemoryMetricsView.vue` 提供三个固定页签：PSS、VSS、Java 堆。筛选器支持时间、应用版本、Android 版本、设备型号、进程名、Activity 名称（`scene`）、前后台以及小时/日粒度；页面只请求 `/memory-metrics/summary` 和 `/memory-metrics/trend`，不展示 FD 触顶率、32/64 位筛选或多维下钻。

概览区域为平均值、P50、P90、P95、P99 五张卡片，并单独显示有效样本数。趋势图一次接收服务端返回的全部百分位，前端通过 P50/P90/P95/P99 切换当前展示列；字节值换算为 MiB 并保留两位小数，`null` 桶断线，合法 0 保持可见。概览和趋势分别维护加载、错误和重试状态，应用切换保留内存筛选的 URL 状态。

## 筛选与 URL 状态

筛选器支持：

- 开始时间、结束时间。
- 应用版本、渠道、环境。
- Android 版本、设备型号、问题指纹；卡顿额外支持场景和算法版本。
- 趋势粒度 `hour` 或 `day`。
- 内存页面额外保存 `metric`、`percentile`、进程名、Activity 名称（`scene`）和前后台；URL 不生成 32/64 位参数。

没有显式时间范围时，前端默认生成最近 24 小时。后端仍是约束的最终执行者：最大查询范围为 31 天，非法参数应返回明确错误。

## 通用页面状态

每个数据区域应明确区分：

- 加载中。
- 成功且有数据。
- 成功但无数据。
- 分母不足。
- 请求失败并可重试。
- 分页追加失败，但保留已经加载的数据。

应用页还明确区分首次无应用、搜索无结果、加载失败、创建冲突、保存中、保存成功、权限只读和未保存离开确认。应用切换只列出当前用户有成员关系的应用，并依据当前模块进入目标应用的 Crash 总览、卡顿指标页或卡顿问题列表。

创建应用时页面展示应用名称、描述和包名，只有包名必填；前端按与服务端一致的点分段规则以及名称/描述长度校验，并在提交失败时保留全部表单输入。空名称和空描述交由服务端使用包名/null 默认值。应用列表、切换器、面包屑和应用工作区标题优先展示名称，包名作为辅助技术信息。设置页默认只显示包名和“查看 Key”按钮；授权用户触发后才请求完整 Key，可隐藏或复制。`DEVELOPER`/`VIEWER` 不显示凭据操作，所有角色都不能修改包名或 Key。
