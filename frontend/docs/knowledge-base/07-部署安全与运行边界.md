# 部署、安全与运行边界

本页维护前端托管和浏览器安全约束。统一发布步骤见[平台部署](../../../docs/knowledge-base/07-部署与运维.md)，当前环境版本与健康核验见[平台状态](../../../docs/knowledge-base/00-当前实现与验证边界.md#环境最近核验)，不在多处追加部署记录。

## 当前运行形态

开发时使用独立 Vite 和 `/api` 代理，Spring Boot 不托管前端静态资源。Compose 中的 Nginx 提供构建产物、history fallback、静态资源缓存，以及 `/api/`、`/ingest/`、`/mcp` 和 `/healthz` 代理；当前监听 HTTP 80，本地覆盖为回环 8080。

生产构建输入为 `frontend/dist`；更新源码后必须重新构建，脚本复用旧 dist 时不能视为已发布新源码。Vite/preview 只用于开发预览，生产发布与回退使用匹配的静态产物、后端及网关配置。

## 生产部署约束

```text
浏览器 → Nginx HTTPS 同源入口（HTTPS 待配置）
          ├─ / 与静态资源 → Vue 构建产物
          ├─ /api/、/ingest/ → Spring Boot
          └─ /mcp → 独立 MCP 服务
```

- 配置生产域名、HTTPS、证书续期与 `APM_SESSION_COOKIE_SECURE=true`。
- 保持 history fallback 和同源相对路径；`VITE_API_BASE_URL` 属于构建期配置。
- 当前有 nosniff、DENY 和 no-referrer 响应头；完整 CSP、缓存/回退策略和 CI/CD 仍需生产验收。
- 检查入口、静态资源、登录/退出及本次相关页面；构建、Nginx 语法或路由 HTTP 200 不代替浏览器验收。

## 当前安全边界

- 前端不接触 ClickHouse URL、用户名或密码。
- 前端不发送 Android 上报用的应用 Key。
- 前端使用同源 Session Cookie；状态变更请求发送 `X-XSRF-TOKEN`，不把密码、Session 标识或 CSRF Token 写入 Web Storage。
- 401 由统一 HTTP 客户端转换为会话过期事件，清理 Pinia 用户/应用状态并跳转登录。
- 页面只消费服务端已经脱敏的异常内容。
- Crash 请求不发送 `X-App-Id` 或 `X-User-App-Ids`；服务端根据认证主体和成员关系授权。
- 路由中的 `appId`、`fingerprint` 和 `eventId` 都是用户可控输入，服务端必须独立鉴权和校验。
- 404 的前端兜底文案不区分资源不存在与无权限，避免帮助枚举资源。
- 应用查询 Token 仅在创建响应中展示完整值；组件关闭、应用切换、卸载或 Session 401 时清空。浏览器错误采集和会话回放也必须排除 Token 响应与该 DOM 文本。

## 凭据与外部查询

完整 App Key 仅由授权用户按需查看，查询 Token 与 Worker 凭据仅创建时一次展示；都只保存在组件局部内存，关闭、离页、应用/角色切换或会话失效时清空。CSP、错误采集、会话回放和日志工具不得采集敏感 DOM 或凭据响应。

查询 Token 与 Android 上报 Key、网页 Session、分析 Worker 是不同身份。网页通过 Session/CSRF 管理查询 Token，不自动把它加入网页请求。`APM_AGENT_QUERY_ENABLED=false` 拒绝新 Token 和外部查询，网页列表/撤销仍可用；`MCP_ENABLED` 独立控制 MCP。当前 HTTP 调试没有生产 TLS 保障，有效 Token 的有限云端验收见[接口证据](../../../docs/validation/backend-api-cloud-validation.md)，生产 HTTPS 仍待验收。

单事件任务和应用 Worker 交互见[分析页面](local-analysis.md)，网页不自动启动宿主，不管理模型或执行云端修复。

## 尚待验收与产品化

生产 HTTPS/Secure Cookie、配置隔离、完整角色与越权浏览器矩阵、会话过期/权限变更、跨浏览器和可访问性仍待验收。OIDC、开放注册、找回密码、多因素认证、成员邀请和永久 Key 泄露处置属于产品待办，统一见[维护约定](08-维护约定与待办.md)，平台安全原则见[安全与隐私](../../../docs/knowledge-base/06-安全与隐私.md)。
