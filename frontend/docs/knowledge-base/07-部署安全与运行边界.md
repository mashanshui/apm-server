# 部署、安全与运行边界

## 当前开发形态

前端是独立 Vite 工程，Spring Boot 当前不托管其静态资源。Vite 开发服务器和 `/api` 代理只用于本地开发，不是生产网关。

## 目标生产形态

```text
浏览器
  → HTTPS 同源网关或静态 Web 服务器
      ├─ / 与静态资源 → frontend 构建产物
      └─ /api          → Spring Boot
```

生产托管至少需要：

- HTTPS 和安全响应头。
- `/api` 到 Spring Boot 的同源反向代理。
- Vue Router history 路由回退到 `index.html`。
- 静态资源缓存策略与版本回滚能力。
- 环境化 API 基地址；优先保持同源相对路径。
- 构建、发布、健康检查和回滚的 CI/CD 记录。

仓库现已提供 `docker/nginx.conf` 和 `compose.cloud.yaml` 的小规模云端 Web 运行形态：Nginx 提供静态资源、Vue history fallback，并将 `/api` 和 `/ingest` 代理到 Spring Boot。该配置当前只监听 HTTP 80，尚未提供域名、HTTPS、证书自动续期、CSP 完整策略或正式 CDN/回滚流程；`npm run build` 成功仍不等同于这些生产能力已经完成。

## 当前安全边界

- 前端不接触 ClickHouse URL、用户名或密码。
- 前端不发送 Android 上报用的应用 Key。
- 前端使用同源 Session Cookie；状态变更请求发送 `X-XSRF-TOKEN`，不把密码、Session 标识或 CSRF Token 写入 Web Storage。
- 401 由统一 HTTP 客户端转换为会话过期事件，清理 Pinia 用户/应用状态并跳转登录。
- 页面只消费服务端已经脱敏的异常内容。
- Crash 请求不发送 `X-App-Id` 或 `X-User-App-Ids`；服务端根据认证主体和成员关系授权。
- 路由中的 `appId`、`fingerprint` 和 `eventId` 都是用户可控输入，服务端必须独立鉴权和校验。
- 404 的前端兜底文案不区分资源不存在与无权限，避免帮助枚举资源。

## 生产前必须补齐

- OIDC、开放注册、找回密码、多因素认证和成员邀请/角色编辑。
- 生产域名、HTTPS、证书自动续期、安全响应头、CSP 和 Session Cookie Secure 配置。
- 浏览器端到端越权、会话过期和权限变更测试。
- 敏感错误与日志审查，禁止在浏览器暴露数据库或内部实现信息。
- 生产环境、预发布环境和开发环境的配置隔离。
- Key 撤销/轮换、mapping 和符号表等后续管理域的权限边界。

平台级安全决策见[安全与隐私](../../../docs/knowledge-base/06-安全与隐私.md)和[ADR-JVM-CRASH-004](../../../docs/knowledge-base/10-架构决策记录.md)。

完整应用 Key 只允许在设置页组件局部内存中短暂存在。生产 CSP、错误采集、会话回放和前端日志工具不得采集该 DOM 文本或接口响应；复制操作由用户显式触发，页面不会写入 Web Storage 或 URL。
