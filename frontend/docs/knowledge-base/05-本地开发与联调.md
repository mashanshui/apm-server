# 本地开发与联调

## 环境要求

- Node.js 与 npm，具体兼容性以当前 Vite/Vue 依赖和锁文件验证为准。
- Java 17 和仓库自带 Gradle Wrapper，用于启动后端。
- 网页管理联调需要 PostgreSQL；Crash 数据默认使用 ClickHouse，临时 Crash 页面开发可使用后端内存模式。Docker Desktop 用于启动本地 PostgreSQL。

首次安装依赖：

```powershell
Set-Location frontend
npm.cmd install
```

仓库已提交 `package-lock.json`。CI 或可重复安装场景优先使用 `npm.cmd ci`。

本地首次启动前可以通过环境变量设置管理员（PowerShell 示例）：

```powershell
$env:APM_BOOTSTRAP_ADMIN_EMAIL = 'admin@example.com'
$env:APM_BOOTSTRAP_ADMIN_PASSWORD = 'change-me-locally'
```

也可以让启动脚本以安全输入方式读取邮箱和密码，不在命令行参数中传递密码：

```powershell
.\scripts\start-dev.ps1 -StorageMode memory -PromptForBootstrapAdmin
```

若只想把邮箱和显示名称作为参数传入，密码仍通过环境变量提供：

```powershell
.\scripts\start-dev.ps1 `
  -StorageMode memory `
  -BootstrapAdminEmail 'admin@example.com' `
  -BootstrapAdminDisplayName '平台管理员'
```

生产环境不要使用示例密码；应通过密钥管理系统注入并设置安全的 Session Cookie 配置。

仓库根目录的 `.env.local` 会被 `start-dev.ps1` 自动读取，适合保存本机管理员凭据；显式设置的进程环境变量优先，`.env.local` 已通过 `.gitignore` 排除，不得提交。

## 一键启动

在仓库根目录执行：

```powershell
.\scripts\start-dev.ps1
.\scripts\stop-dev.ps1
```

启动脚本会先启动 Compose PostgreSQL，再启动默认 ClickHouse 模式的 Spring Boot 后端和 Vite 前端。也可以使用：

```powershell
# Crash 使用内存存储（管理库仍需要 PostgreSQL）
.\scripts\start-dev.ps1 -StorageMode memory

# 只启动后端
.\scripts\start-dev.ps1 -NoFrontend
```

脚本状态和日志位于被 Git 忽略的 `build/dev-services/`；脚本会显式启用 Flyway，并在本地开发默认使用非 Secure、SameSite=Lax 的 Session Cookie。完整的后端与 ClickHouse 启动约束见[平台部署与运维](../../../docs/knowledge-base/07-部署与运维.md)和[ClickHouse 本地初始化](../../../docs/clickhouse-local.md)。

## 分别启动

后端准备好后，在另一个终端运行：

```powershell
Set-Location frontend
npm.cmd run dev
```

访问：

```text
http://127.0.0.1:5173/login
```

Vite 默认监听 5173，并把 `/api` 代理到 `http://localhost:8080`。预览服务器默认监听 4173。

## 准备固定数据

后端启动后，可以从仓库根目录发送固定数据集：

```powershell
$body = Get-Content -Raw 'src\test\resources\fixtures\crash-dataset.json'
$headers = @{ 'X-App-Key' = '<应用设置页显示的完整 appKey>'; 'X-Schema-Version' = '2' }
Invoke-RestMethod `
  -Uri 'http://localhost:8080/ingest/v1/batches' `
  -Method Post `
  -ContentType 'application/json' `
  -Headers $headers `
  -Body $body
```

首次管理员由 `APM_BOOTSTRAP_ADMIN_EMAIL`、`APM_BOOTSTRAP_ADMIN_PASSWORD` 和可选的 `APM_BOOTSTRAP_ADMIN_DISPLAY_NAME` 创建。启动前还必须稳定配置 `APM_APP_KEY_ENCRYPTION_KEY`。打开 `/login` 登录后进入 `/apps`，填写可选名称/描述和固定数据集中的 `packageName` 创建应用，再到设置页查看 appKey。`X-App-Key` 只用于模拟 Android 上报；浏览器查询使用 Session + 应用成员关系，两者不能互相替代。

本变更不兼容旧项目模型；测试数据库需先清空再迁移。应用创建后，UUID `appId` 和包名均不可修改，显示名称和描述可由 Owner/Admin 更新，appKey 永久有效。固定数据上报前必须确认每个事件 `packageName` 与应用绑定包名完全一致，否则整个批次返回 403 且零写入。

## 数据源确认

总览、趋势、问题和事件列表响应包含 `dataSource`：

- `clickhouse`：页面显示“数据源 · ClickHouse”。
- `memory`：页面显示“内存联调”。

该标识有助于发现后端误启为内存模式，但不能替代数据正确性、权限或持久化验收。

## 常见排查

| 现象 | 优先检查 |
|---|---|
| 页面提示无法连接查询服务 | Spring Boot 是否监听 8080，Vite 代理配置是否仍指向正确地址 |
| 页面有框架但没有数据 | 查询时间范围、应用 ID、固定数据是否已上报、后端存储模式 |
| 登录页提示无法连接 | PostgreSQL 是否已启动、引导管理员邮箱/密码是否配置、后端是否监听 8080 |
| 写请求返回 403 | 浏览器是否先访问 `/api/v1/session` 获得 `XSRF-TOKEN`，请求是否发送 `X-XSRF-TOKEN` |
| 应用列表为空 | 当前登录用户是否是应用成员；创建首个应用后刷新 Session/应用列表 |
| 显示“内存联调” | `APM_STORAGE_MODE` 是否被显式设为 `memory`，是否复用了旧 Gradle daemon 环境 |
| 404 或安全兜底错误 | 路由中的应用/事件/指纹是否正确，后端应用范围校验是否通过 |
| 比例显示不可用 | 是否缺少同一筛选范围内有效的 `app_start` 会话分母 |
| 刷新子路由失败 | 生产静态服务器是否配置 history fallback 到 `index.html` |
