# 本地开发与联调

## 环境要求

- macOS 全栈启动需要 Docker Desktop；首次构建还需要 Java 21 和仓库自带 Gradle Wrapper。本机没有 Node.js/npm 时，脚本使用 Docker Node 22 构建前端。
- 网页管理联调需要 PostgreSQL；Crash 数据默认使用 ClickHouse。独立开发 Vite 时仍需本机 Node.js/npm。
- 内存异常报告页面需要后端执行 `006_memory_leak_reports.sql`；上传接口使用 `X-App-Key`，查询页面使用登录 Session，不需要前端直连 ClickHouse。

首次安装依赖：

```bash
cd frontend
npm ci
```

仓库已提交 `package-lock.json`；可重复安装使用 `npm ci`。

本地全栈首次启动前在根目录 `.env.local` 配置管理员：

```dotenv
APM_BOOTSTRAP_ADMIN_EMAIL=admin@example.com
APM_BOOTSTRAP_ADMIN_PASSWORD=<本地随机密码>
```

生产环境不要使用示例密码；应通过密钥管理系统注入并设置安全的 Session Cookie 配置。

仓库根目录的 `.env.local` 会被 `start-dev.sh` 通过 Compose 读取，适合保存本机管理员凭据；`.env.local` 已通过 `.gitignore` 排除，不得提交。完整必需配置见[平台部署与运维](../../../docs/knowledge-base/07-部署与运维.md)。

## 一键启动

在仓库根目录执行：

```bash
./scripts/start-dev.sh
./scripts/stop-dev.sh
```

启动脚本启动 PostgreSQL、ClickHouse、Spring Boot、Nginx/Vue 和默认关闭对外查询的 MCP 五个容器，等待全部健康后可访问 `http://127.0.0.1:8088/login`。已有构建产物会复用；需要重新构建时执行：

```bash
./scripts/start-dev.sh --build
```

容器日志可用 `docker compose --env-file .env.local -f compose.cloud.yaml -f compose.local.yaml logs` 查看；停止脚本保留数据卷。完整的后端与 ClickHouse 启动约束见[平台部署与运维](../../../docs/knowledge-base/07-部署与运维.md)和[ClickHouse 本地初始化](../../../docs/clickhouse-local.md)。

## 分别启动

后端准备好后，在另一个终端运行：

```bash
cd frontend
npm run dev
```

访问：

```text
http://127.0.0.1:5173/login
```

Vite 默认监听 5173，并把 `/api` 代理到 `http://localhost:8080`。若单独启动后端且监听其他端口，可在启动 Vite 前设置 `VITE_BACKEND_PROXY_TARGET=http://127.0.0.1:<后端端口>`；该变量只用于本地开发代理，不是浏览器中的 Token 配置。预览服务器默认监听 4173。

## 准备固定数据

后端启动后，可以从仓库根目录发送固定数据集：

```powershell
$body = Get-Content -Raw 'backend\src\test\resources\fixtures\crash-dataset.json'
$headers = @{ 'X-App-Key' = '<应用设置页显示的完整 appKey>'; 'X-Schema-Version' = '2' }
Invoke-RestMethod `
  -Uri 'http://localhost:8080/ingest/v1/batches' `
  -Method Post `
  -ContentType 'application/json' `
  -Headers $headers `
  -Body $body
```

首次管理员由 `APM_BOOTSTRAP_ADMIN_EMAIL`、`APM_BOOTSTRAP_ADMIN_PASSWORD` 和可选的 `APM_BOOTSTRAP_ADMIN_DISPLAY_NAME` 创建。启动前还必须稳定配置 `APM_APP_KEY_ENCRYPTION_KEY`。打开 `/login` 登录后进入 `/apps`，填写可选名称/描述和固定数据集中的 `packageName` 创建应用，再到设置页查看 appKey。`X-App-Key` 只用于模拟 Android 上报；浏览器查询使用 Session + 应用成员关系，两者不能互相替代。

本变更不兼容旧项目模型；测试数据库需先清空再迁移。应用创建后，UUID `appId` 和包名均不可修改，显示名称和描述可由 Owner/Admin 更新，appKey 永久有效。固定数据上报前必须确认每个事件 `packageName` 与应用绑定包名完全一致，否则整个批次返回 403 且零写入。

## 数据源确认

总览、趋势、问题和事件列表响应包含 `dataSource`：

- `clickhouse`：页面显示“数据源 · ClickHouse”。
- `memory`：页面显示“内存联调”。

该标识有助于发现后端误启为内存模式，但不能替代数据正确性、权限或持久化验收。

## 常见排查

| 现象 | 优先检查 |
|---|---|
| 页面提示无法连接查询服务 | Spring Boot 是否监听 8080，Vite 代理配置是否仍指向正确地址 |
| 页面有框架但没有数据 | 查询时间范围、应用 ID、固定数据是否已上报、后端存储模式 |
| 登录页提示无法连接 | PostgreSQL 是否已启动、引导管理员邮箱/密码是否配置、后端是否监听 8080 |
| 写请求返回 403 | 浏览器是否先访问 `/api/v1/session` 获得 `XSRF-TOKEN`，请求是否发送 `X-XSRF-TOKEN` |
| 应用列表为空 | 当前登录用户是否是应用成员；创建首个应用后刷新 Session/应用列表 |
| 显示“内存联调” | `APM_STORAGE_MODE` 是否被显式设为 `memory`，是否复用了旧 Gradle daemon 环境 |
| 404 或安全兜底错误 | 路由中的应用/事件/指纹是否正确，后端应用范围校验是否通过 |
| 比例显示不可用 | 是否缺少同一筛选范围内有效的 `app_start` 会话分母 |
| 刷新子路由失败 | 生产静态服务器是否配置 history fallback 到 `index.html` |

## 后端目录边界

统一启停仍从仓库根目录调用 `scripts/`，后端源码及测试夹具已移至 `backend/`。后端独立构建和配置见[后端构建与本地运行](../../../backend/docs/knowledge-base/05-构建配置与本地运行.md)，前端代理地址与 API 契约保持不变。
