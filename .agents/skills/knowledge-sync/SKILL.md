# 知识库与配套文档更新

将指定范围内的当前事实原位更新到所属文档。仅修改受影响的文档，不顺手修改实现、提交代码或执行归档。

## 触发与范围

- 用户可以直接使用 `$knowledge-sync`，并用自然语言指定功能、工程、文件、提交范围或 OpenSpec 变更；用户明确要求更新知识库或配套文档也属于显式调用。
- OpenSpec 归档流程可以显式调用本 skill，必须传入选定变更名称与已解析的变更目录；在当前流程中执行并等待完成，不后台运行。
- 按用户明确范围、当前任务中已经确认的改动、Git 差异确定本次核对范围。检查暂存、未暂存和相关未跟踪文件，避免纳入无关改动；用户指定提交范围时同时检查相应历史。
- 归档调用必须阅读选定变更的实际规划材料、任务和增量规格，并追踪对应实现及验证证据；遵循 OpenSpec 已解析的路径，不假定只有默认文件名。实现已经提交、工作树干净或没有增量规格，都不能作为跳过文档核对的理由。
- 无法从输入、任务上下文或差异确定范围时，先询问范围，不默认整理全仓。若核对后无需修改，仍说明检查范围与依据。

## 核对与更新

1. 阅读[根协作规则](../../../AGENTS.md#文档归属与同步)、所涉工程的 AGENTS.md、[平台知识库](../../../docs/knowledge-base/README.md)、[当前实现与验证边界](../../../docs/knowledge-base/00-当前实现与验证边界.md)及相关主题。
2. 对照当前代码、数据库迁移和已发布 API 核对文档，规划材料只用于确定范围和目标，不能证明实现完成。发现冲突时列出差异和依据并确认；本次任务已有明确决策可作为确认依据，仍无法判定的差异须请求确认，不猜测覆盖。
3. 按根规则的文档归属更新受影响内容：根知识库维护平台架构、跨端约定和状态，各工程知识库维护内部机制与测试，API 文档维护服务端契约，客户端文档维护接入步骤。继续检查相关示例、夹具、测试说明、运维和验收资料及导航，仅修改实际受影响项。
4. API 路由、字段、错误或统计口径变化时，同时核对 API 正文、相关测试与示例；客户端字段、队列、批量、重试和接入变化时核对客户端说明及 Android 主题。必要实现测试仍在开发阶段执行，本 skill 不以文档改写替代测试；发现实现或测试缺口时报告，不擅自扩大为代码修复。
5. 使用中文原位修订当前事实、步骤和约束，删除失效描述。完整契约与接入步骤保留唯一正文，其他主题链接引用；新增资料加入所属导航，移动或重命名时同步引用。
6. 保留证据边界：分别说明代码实现、存在测试、测试执行、外部冒烟与待验证目标。未执行的验证如实标注，不把历史记录或规划写成当前验收。环境最近核验集中在平台状态页，测试方法与最近完整基线归各工程测试页。
7. 不追加日常构建、部署、重启、清理、文档检查或逐轮进度流水。可复用故障、重要迁移、独立验收或性能证据维护唯一入口及必要限制，历史过程通过 Git、OpenSpec 归档或已有专题追溯。示例只使用安全占位值。

## 校验与完成条件

- 核对更新文字与对应代码、配置、契约和已有验证证据；检查受影响 Markdown 的本地文件、锚点、导航、代码围栏及移动后的引用，并运行 `git diff --check`。
- 按实际改动执行必要校验；纯文档修改不要求各端业务构建。没有重新执行的业务、设备或环境验证必须说明，不补写成功结论。
- 只有范围核对、必要更新和文档校验均已完成，且不存在影响本次文档准确性的未解决差异时，报告“更新完成”。核对后无需修改也可以完成，但须给出依据。
- skill 缺失的依赖、执行中断、无法确认的关键差异或必要校验失败均报告“更新未完成”，列出原因与剩余事项。已准确记录的既有验证边界不自动视为失败。
- 归档调用遇到“更新未完成”时，停止归档并保留原变更目录，不执行移动或报告归档成功。本 skill 本身不负责同步 OpenSpec 主规格或移动变更。

## 结果汇报

给出“更新完成”或“更新未完成”、本次核对范围和必要差异依据；分别列出根、后端、前端、Android 知识库及 API、客户端文档的更新文件，不受影响的类别明确说明。其他示例、测试说明、导航或运维资料有改动时一并列出，最后说明校验结果、未执行验证和未解决事项。
