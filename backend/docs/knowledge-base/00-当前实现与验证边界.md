## 后端能力摘要

已实现 JSON/gzip 上报、Crash、卡顿和内存指标查询、v3 卡顿 ZIP 接收边界、网页认证和应用成员授权。JSON 批次、卡顿 manifest 和内存报告 metadata 都校验 UUID v4 `processId`，并在领域对象和 ClickHouse 载体中保留原值；内存事件使用 `memory_sample`/`memorySample`，分别统计 PSS、VSS 和 Java 堆的原始字节样本；内存异常报告使用 metadata+report multipart 文件上传、可选 HPROF 保存、ClickHouse/内存适配器和问题/趋势查询；后端仍为模块化单体。HPROF 解析和内存详情页不在首版。

本变更新增 `007_event_process_identity.sql`，为六类事件/报告表增加可表达历史缺失值的 `process_id String DEFAULT ''`；不改变排序键、TTL、去重键或聚合维度。当前服务端固定使用 `rhea-trace-processor:1.0.2`，已通过客户端主线程-only v3 ZIP 的 UUID v4 解析和云端 HTTP/落库验收；Android SDK 生命周期、持久队列、生产制品仓库和容量仍属于独立外部边界。

JSON 批量入口的缺失、空值、数值 PID 和非 v4 `processId` 均为永久校验错误；迁移前 ClickHouse 行读回空字符串时映射为缺失值。详情 DTO 已回传 Crash/Jank 的 `processId`，前端展示和复制逻辑由前端知识库维护。

测试方法、日期和数量统一见[测试与质量保障](06-测试与质量保障.md)。后端自动化不替代 Android 真机、跨端 HTTP、生产容量、TTL、备份恢复和正式制品仓库验证。

## 已识别的原文差异

- 平台历史材料中“关闭 ClickHouse 即无外部数据库依赖”的表述不涵盖管理域；正常服务仍需要 PostgreSQL，H2 仅是测试或专门装配冒烟。
- 原平台存储草案含统一原始表设计，当前代码已采用 Crash/Jank 专属存储端口；草案与已实现适配器分开标记，不据草案修改代码。
- 原灰度文档仍提到开发期请求头权限，而当前代码已采用 Session/成员授权；该历史差异保留并在平台待确认事项登记，本次不改写历史行为。
