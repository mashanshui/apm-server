## 已识别的原文差异

- 平台历史材料中“关闭 ClickHouse 即无外部数据库依赖”的表述不涵盖管理域；正常服务仍需要 PostgreSQL，H2 仅是测试或专门装配冒烟。
- 原平台存储草案含统一原始表设计，当前代码已采用 Crash/Jank 专属存储端口；草案与已实现适配器分开标记，不据草案修改代码。
- 原灰度文档仍提到开发期请求头权限，而当前代码已采用 Session/成员授权；该历史差异保留并在平台待确认事项登记，本次不改写历史行为。

## 2026-09-30 后端文档核对与差异修正

本次检查本目录全部 11 篇文档，对照源码、配置、迁移、脚本和测试修正下列差异；仅修改文档，不改变数据库、业务代码或接口路由。历史验收保留日期，本次回归结果单独写入[测试记录](06-测试与质量保障.md#2026-09-30-文档核对与后端回归)。

| 原描述与问题 | 当前依据与修正 |
|---|---|
| ArchUnit 已检查依赖环、新应用层/持久化层规则，bootstrap 独占全部安全装配 | `ArchitectureBaselineTests` 仅检查白名单、跨模块内部包及旧包分层；安全链实际位于 `identity.internal.config`，Agent 还依赖 Platform API |
| 卡顿个例聚合/分页可套用数据库聚合结论 | `ClickHouseJankQuerySql` 先按时间升序 `LIMIT`，`JankQueryService` 再在 Java 聚合；记录超过上限时的完整性缺口，区别 FPS/挂起率 SQL 聚合 |
| 设备哈希使用应用盐，属性名有业务白名单 | 三个 sanitizer 使用同一部署级盐且不拼接 appId；属性键是格式约束，报告 parser 保留原始设备标识及 report |
| memory 模式仅设置模式即可联调且没有外部依赖 | `StorageProperties` 可用标志默认 false，需设置 `APM_STORAGE_IN_MEMORY_AVAILABLE=true`；管理域仍需要 PostgreSQL |
| 004 可重复无损初始化，TTL 只是示例 | 004 对十张空业务表执行删除/重建；TTL 由 SQL 生效，报告 retention 配置不修改 DDL |
| 附件保留变量和 256 MiB 上传能力说明不准确 | 正确变量为 `APM_MEMORY_REPORT_ATTACHMENT_RETENTION_DAYS`；默认 multipart 32/34 MiB 会先限制大附件 |
| 文件移动总是原子，注册文件缺失可继续卡顿解析 | 文件系统不支持时回退普通移动；无注册记录与已有记录文件丢失是不同分支，后者卡顿返回存储错误 |
| 云部署不做部署后检查、Actuator 三个入口都可直接访问 | 部署脚本等待五个容器健康，业务另验；只有 health 匿名开放，info/metrics 需要 Session |
