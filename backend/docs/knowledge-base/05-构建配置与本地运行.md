## Android 符号表与二进制堆栈解析配置

Android mapping 通过网页接口上传到 `apm.symbol.directory`，不再由生产路径按 `<mapping-root>/<appId>/<buildId>.txt` 读取。符号表默认单文件 32 MiB、Retrace 输出 1 MiB、上传校验和详情解析共享并发 2；完整字段和 Crash/Jank 生效语义见[后端符号表实现](symbol-mapping.md)与[符号表 API](../../../docs/api/symbol-api.md)。

| 环境变量 | 默认值 | 运维含义 |
|---|---:|---|
| `APM_SYMBOL_DIRECTORY` | `build/symbols` | mapping 受控文件卷，生产必须使用持久卷 |
| `APM_SYMBOL_MAX_FILE_BYTES` | `33554432` | 单份 mapping 上限 |
| `APM_SYMBOL_MAX_OUTPUT_BYTES` | `1048576` | Crash 单次 Retrace 输出上限 |
| `APM_SYMBOL_MAX_CONCURRENT_OPERATIONS` | `2` | 上传校验和详情解析共享并发许可 |

## 二进制堆栈解析配置

完整 btrace 产物通过原始请求体同步解析，配置如下：

| 环境变量 | 默认值 | 运维含义 |
|---|---:|---|
| `APM_STACK_PARSER_MAX_ARTIFACT_BYTES` | `67108864` | 原始 `.rheajank.zip` 请求体上限；调高前必须同时验证 processor 限制、堆和临时磁盘 |
| `APM_STACK_PARSER_MAX_CONCURRENT_PARSES` | `2` | 单实例同步解析许可数；满载返回 503 和 `Retry-After` |
| `APM_STACK_PARSER_MAPPING_ROOT` | 空 | 仅保留测试构造器兼容配置；生产卡顿解析从统一符号表注册表按 `appId + buildId` 读取 |

服务端解析时会使用系统临时目录，不保存原始 ZIP 和完整报告；解析后同步写入卡顿事实与详情。当前服务端要求 manifest 的 `processId` 为 UUID v4，processor `1.0.2` 已接受客户端主线程-only manifest v3 ZIP，并完成云端首次接受、重复和详情验证。生产仍需从受控制品仓库获取兼容版本，并单独验证解析耗时、503 比例、JVM 堆、临时磁盘、数据库写入和并发容量。接口契约见[卡顿压缩包解析与落库 API](../../../docs/api/stack-artifact-api.md)。

初始化 ClickHouse 时必须按顺序执行 `001_crash_schema.sql`、`002_jank_schema.sql`、`003_jank_sampling_quality.sql`、`004_application_identity_schema.sql`、`005_memory_metrics.sql`、`006_memory_leak_reports.sql` 和 `007_event_process_identity.sql`；004 只允许在受影响业务表为空时执行，旧质量列与旧项目结构不自动迁移，005/006 只新增内存采样和异常报告表，007 只追加 `process_id` 列。

内存异常报告配置位于 `apm.memory-leak-report.*`：metadata 默认 2 MiB、report 文件默认 2 MiB、HPROF 附件业务上限默认 256 MiB、总请求业务上限默认 260 MiB、报告保留配置默认 90 天、附件保留 7 天、孤立文件宽限 24 小时，附件目录默认 `build/memory-report-artifacts`。`APM_MEMORY_REPORT_MAX_REPORT_BYTES` 和 `APM_MEMORY_REPORT_ATTACHMENT_RETENTION_DAYS` 可分别覆盖 report 大小和附件保留天数；`APM_MEMORY_REPORT_RETENTION_DAYS` 不会动态修改 ClickHouse TTL，数据库期限仍由 006 SQL 决定。服务端不解析 HPROF，也不暴露静态附件路径。

Spring multipart 和 Compose 的默认限制仍是单 part `32MB`、总请求 `34MB`，先于上述业务限制生效；因此默认部署不能接收 256 MiB HPROF。需要大附件时同时配置 `APM_MULTIPART_MAX_FILE_SIZE` 和 `APM_MULTIPART_MAX_REQUEST_SIZE`，后者须为所有 part 及 multipart 边界预留空间，并对照业务总请求上限；Nginx 当前 `client_max_body_size` 为 `260m`。调高业务上限时也要同步网关上限。

云端运行使用根目录 `compose.cloud.yaml`。部署镜像不在云端重新解析内部 Maven 制品，而是先在具备 `rhea-trace-processor:1.0.2` Maven Local 的环境执行 `bootJar`，再将 `backend/build/libs/*-SNAPSHOT.jar` 作为运行镜像输入；前端先执行 `npm run build`，将 `frontend/dist` 作为 Nginx 镜像输入。云端通过环境变量把 PostgreSQL、ClickHouse、应用主密钥、设备哈希盐和引导管理员配置注入 Spring Boot，数据库和附件使用 Docker 持久卷；ClickHouse 调试容器内存上限固定为 `2 GiB`，避免在 MergeTree/系统日志运行期间触发原 `1 GiB` 限制。当前云端为调试环境，Compose 将 PostgreSQL 5432 和 ClickHouse HTTP 8123 映射到公网，便于本地后端直接连接；正式环境不得沿用该暴露方式。

根目录 `scripts/deploy-cloud.sh` 将上述制品准备和云端 Compose 更新串成一次部署。脚本默认执行 `bootJar` 和前端构建，不运行自动化测试或业务 API 验收；更新后逐项等待 PostgreSQL、ClickHouse、后端、MCP 和 Web 五个容器均为 `running healthy`，最长 600 秒，超时以失败退出。`.env.cloud` 仍只保存在服务器，Docker 数据卷不会被删除。健康等待不等同于上报、查询或有效 Token 的业务验收。

## 服务健康基线

当前已配置并可使用：


`/actuator/health` 可匿名访问，`/actuator/info` 与 `/actuator/metrics` 要求网页 Session 认证。当前没有 `/api/v1/ping` 自定义接口，也没有把 ClickHouse 注册为 Actuator 健康贡献者；ClickHouse 访问失败会在上报或查询请求中体现为存储错误。正式部署前需要补齐依赖健康状态、就绪/存活探针和告警。

## 工程与命令

以下 macOS 命令从仓库根目录执行，以 Android Studio JBR 启动 Gradle；Windows 对应路径为 `C:\Program Files\Android\Android Studio\jbr`，使用 `backend/gradlew.bat`。实际编译和测试使用 `backend/build.gradle.kts` 指定的 Java 21 工具链；JBR 版本与工具链版本不必相同。IDE 应关联 `backend/settings.gradle.kts`，后端保持 Java 21、Spring Boot 4.1 与单模块 Gradle 构建。

```bash
export JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home'
export GRADLE_USER_HOME="$PWD/.gradle-local"
bash ./backend/gradlew -p backend clean build --no-daemon
bash ./backend/gradlew -p backend test --no-daemon
bash ./backend/gradlew -p backend bootJar --no-daemon
bash ./backend/gradlew -p backend bootRun --no-daemon
```

进入 `backend/` 后可执行 `bash ./gradlew test` 等命令。产物位于 `backend/build/libs/`，Gradle 工程缓存位于 `backend/.gradle/`；根目录既有缓存和历史产物不会自动搬迁或删除。

用 IDEA 打开仓库根目录时，Gradle 关联路径应为 `$PROJECT_DIR$/backend`，项目 SDK 和编译目标均应使用 Java 21。根目录 `.idea/` 保存本地工程、工作区和数据库连接配置，不纳入 Git；修正关联时保留其他本地配置。迁移前遗留的根 `.gradle/` 可在没有构建占用时清理，但不要误删 Wrapper 所在的 `backend/gradle/`、统一脚本使用的 `.gradle-local/` 或 `build/dev-services/`。

构建需要 R8 `com.android.tools:r8:8.9.35` 和 `io.github.mashanshui:rhea-trace-processor:1.0.2`；仓库按 `mavenLocal()`、仅匹配 `com.android.tools` 的阿里云 Google Maven 镜像、Google Maven 官方源回退、阿里云公共 Maven 镜像、Maven Central 兜底的顺序解析，processor 仍需要预先发布到 Maven Local。macOS 使用当前用户的 `~/.m2/repository`；不能将本机已有缓存视为正式制品仓库验收。

## 环境配置与工作目录

macOS 全栈脚本通过 Docker Compose 读取根目录被忽略的 `.env.local`，并使用本机 PostgreSQL 与 ClickHouse。直接 `bootRun` 不会自动导入该文件，必须先在进程环境提供 PostgreSQL、稳定的 App Key 加密主密钥及所选存储模式需要的配置。

`scripts/start-dev.sh` 仅在需要构建 JAR 时优先使用 `APM_JAVA_HOME`，否则通过 macOS `/usr/libexec/java_home -v 21` 查找 JDK 21；不会修改系统级 `JAVA_HOME`。启动和云端部署脚本均通过 `bash` 调用 `backend/gradlew`，不依赖 Wrapper 文件的可执行位。缺少 JDK 21 时，构建会在容器启动前报错。

后端工程目录为 `backend/`。符号表文件由 `apm.symbol.directory` 管理，生产应配置到持久卷；不要再按客户端提供的路径读取 mapping。全栈脚本使用根目录 `.gradle-local/` 完成本机构建，运行日志由 `docker compose logs` 查看。远程数据库调试需单独为 `bootRun` 配置 `APM_DATABASE_URL`、`CLICKHOUSE_URL` 及凭据，不属于全栈脚本功能。

## 存储开关与账号

ClickHouse 应用账号需要 `SELECT` 和 `INSERT` 权限；Grafana 应使用独立只读账号。当前 `apm.clickhouse.read-only-user` 只是配置约定，代码实际使用 `apm.clickhouse.username/password` 发起读写请求，部署时必须按最小权限配置并通过环境变量注入密码。

存储实现的条件开关实际由 `apm.storage.mode=memory|clickhouse` 控制；当前 `apm.clickhouse.enabled` 没有参与仓库 Bean 的条件选择，不能仅依赖它关闭 ClickHouse 访问，发布前应统一配置并补充启动校验。临时内存联调需同时设置 `APM_STORAGE_MODE=memory` 和 `APM_STORAGE_IN_MEMORY_AVAILABLE=true`；后者在生产配置中默认 false，否则内存仓库读写仍返回存储不可用。仅替换事件存储不会免除管理域的 PostgreSQL 依赖。

## 单事件分析增量（2026-10-01）

分析使用独立 Worker 身份，Session、上报 Key 与查询 Token 不能替代。租约失效、取消或功能关闭后，环境停止仍须可信 Worker 回执或管理员实际核验，停止未知不能重试或清理内容。默认功能关闭，生产协议由 Nginx 入口处理；应用继续 HTTP。30 天到期保留摘要，新增表回滚时保留。详细权限、恢复流程和有限验证边界见[本地分析实现](local-analysis.md)。


单事件分析开关 `APM_AGENT_ANALYSIS_ENABLED` 默认 false，由 Compose 后端环境显式传入；本地覆盖沿用该配置。当前宿主模式只向 Python 注入应用 Worker 凭据，模型沿用宿主配置，不要求独立模型密钥；凭据不传入网页或 MCP。当前未部署此增量到云端。关闭语义和验收边界见单事件分析专项记录。
