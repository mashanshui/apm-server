# 后端构建配置与本地运行

本页维护独立构建、运行配置与排障。统一启停、发布与数据保护见[平台部署与运维](../../../docs/knowledge-base/07-部署与运维.md)。

## 工程与命令

以下命令从仓库根目录执行，使用已安装的 Java 21；Windows 使用 `backend/gradlew.bat -p backend`。IDE 应关联 `backend/settings.gradle.kts`，后端保持 Java 21、Spring Boot 4.1 与单模块 Gradle 构建。
```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
export GRADLE_USER_HOME="$PWD/.gradle-local"
bash ./backend/gradlew -p backend clean build --no-daemon
bash ./backend/gradlew -p backend test --no-daemon
bash ./backend/gradlew -p backend bootJar --no-daemon
bash ./backend/gradlew -p backend bootRun --no-daemon
```

进入 `backend/` 后可执行 `bash ./gradlew test` 等命令。产物位于 `backend/build/libs/`，Gradle 工程缓存位于 `backend/.gradle/`。

用 IDEA 打开仓库根目录时，Gradle 关联路径为 `$PROJECT_DIR$/backend`，项目 SDK 和编译目标为 Java 21；`.idea/` 保持本地忽略。

构建需要 R8 `com.android.tools:r8:8.9.35` 和 `io.github.mashanshui:rhea-trace-processor:1.0.4`；仓库按 `mavenLocal()`、仅匹配 `com.android.tools` 的阿里云 Google Maven 镜像、Google Maven 官方源回退、阿里云公共 Maven 镜像、Maven Central 兜底的顺序解析，processor 仍需要预先发布到 Maven Local。macOS 使用当前用户的 `~/.m2/repository`；不能将本机已有缓存视为正式制品仓库验收。

processor 的固定摘要、制品更新核验和条件专项见[后端测试](06-测试与质量保障.md#processor-制品校验)。替换同版本制品前仍须核验来源、内容和解析行为，不得仅为通过测试更新摘要。

## 环境配置与工作目录

macOS 全栈脚本通过 Docker Compose 读取根目录被忽略的 `.env.local`，并使用本机 PostgreSQL 与 ClickHouse。直接 `bootRun` 不会自动导入该文件，必须先在进程环境提供 PostgreSQL、稳定的 App Key 加密主密钥及所选存储模式需要的配置。

`scripts/start-dev.sh` 仅在需要构建 JAR 时优先使用 `APM_JAVA_HOME`，否则通过 macOS `/usr/libexec/java_home -v 21` 查找 JDK 21；不会修改系统级 `JAVA_HOME`。启动和云端部署脚本均通过 `bash` 调用 `backend/gradlew`，不依赖 Wrapper 文件的可执行位。缺少 JDK 21 时，构建会在容器启动前报错。

后端工程目录为 `backend/`。符号表文件由 `apm.symbol.directory` 管理，生产应配置到持久卷；不要再按客户端提供的路径读取 mapping。全栈脚本使用根目录 `.gradle-local/` 完成本机构建，运行日志由 `docker compose logs` 查看。远程数据库调试需单独为 `bootRun` 配置 `APM_DATABASE_URL`、`CLICKHOUSE_URL` 及凭据，不属于全栈脚本功能。

## 管理域本地配置

首次管理员通过 `.env.local` 中的 `APM_BOOTSTRAP_ADMIN_EMAIL`、`APM_BOOTSTRAP_ADMIN_PASSWORD` 和可选的 `APM_BOOTSTRAP_ADMIN_DISPLAY_NAME` 配置。全栈脚本使用本地 PostgreSQL、启用 Flyway，并按 Compose 的默认值将 Session Cookie 设为非 Secure、SameSite=Lax；生产环境必须覆盖为 HTTPS 安全配置。

## 存储开关与账号

ClickHouse 应用账号需要 `SELECT` 和 `INSERT` 权限；Grafana 应使用独立只读账号。当前 `apm.clickhouse.read-only-user` 只是配置约定，代码实际使用 `apm.clickhouse.username/password` 发起读写请求，部署时必须按最小权限配置并通过环境变量注入密码。

存储实现的条件开关实际由 `apm.storage.mode=memory|clickhouse` 控制；当前 `apm.clickhouse.enabled` 没有参与仓库 Bean 的条件选择，不能仅依赖它关闭 ClickHouse 访问，发布前应统一配置并补充启动校验。临时内存联调需同时设置 `APM_STORAGE_MODE=memory` 和 `APM_STORAGE_IN_MEMORY_AVAILABLE=true`；后者在生产配置中默认 false，否则内存仓库读写仍返回存储不可用。仅替换事件存储不会免除管理域的 PostgreSQL 依赖。

## Android 符号表与二进制堆栈解析配置

Android mapping 通过网页接口上传到 `apm.symbol.directory`，不再由生产路径按 `<mapping-root>/<appId>/<buildId>.txt` 读取。符号表默认单文件 32 MiB、Retrace 输出 1 MiB、上传校验和后台 Crash 解析共享并发 2；完整字段和 Crash/Jank 生效语义见[后端符号表实现](symbol-mapping.md)与[符号表 API](../../../docs/api/symbol-api.md)。

| 环境变量 | 默认值 | 运维含义 |
|---|---:|---|
| `APM_SYMBOL_DIRECTORY` | `build/symbols` | mapping 受控文件卷，生产必须使用持久卷 |
| `APM_SYMBOL_MAX_FILE_BYTES` | `33554432` | 单份 mapping 上限 |
| `APM_SYMBOL_MAX_OUTPUT_BYTES` | `1048576` | Crash 单次 Retrace 输出上限 |
| `APM_SYMBOL_MAX_CONCURRENT_OPERATIONS` | `2` | 上传校验和后台 Crash 解析共享并发许可 |

## 二进制堆栈解析配置

### JVM Crash 后台组件

新后台组件使用 V15 和 ClickHouse 008；启动时校验新事实/状态所需结构，缺表或缺列直接失败，不回退旧表。公开链路切换边界见[后台处理组件](symbol-mapping.md#后台处理组件与恢复边界)。测试只使用隔离数据库，不能把应用启动成功视为已经完成新业务切换。

| 环境变量 | 默认值 | 资源边界 |
|---|---:|---|
| `APM_CRASH_BACKGROUND_ENABLED` | `true` | 定时执行和轮转对账开关；关闭不删除 pending 或已登记结果 |
| `APM_CRASH_BACKGROUND_BATCH_SIZE` | `100` | 允许 1～100，大载荷可在预算内有限减半；同时构建数固定为 1 |
| `APM_CRASH_BACKGROUND_INTERVAL_MS` | `1000` | 上一批结束后的固定延迟，不建立事件内存队列 |
| `APM_CRASH_BACKGROUND_RECONCILE_INTERVAL_MS` | `30000` | 每次轮转最多 100 个活动构建，并执行有限到期清理 |
| `APM_CRASH_BACKGROUND_MAX_PENDING_PUBLICATIONS` | `100` | 全局未确认载荷最多条数，可配置范围 1～1000 |
| `APM_CRASH_BACKGROUND_MAX_PENDING_BYTES` | `16777216` | 全局未确认载荷字节上限，单份编码仍不超过 2 MiB |

后台 R8 与上传校验、同步 Jank 解析继续共用 `APM_SYMBOL_MAX_CONCURRENT_OPERATIONS=2` 和 `APM_SYMBOL_MAX_OUTPUT_BYTES=1048576`。失败退避、正常关闭与恢复限制见[符号表专题](symbol-mapping.md#后台处理组件与恢复边界)；所有查询扫描、内存、执行和响应上限仍来自 `apm.query.*`。

### 卡顿 ZIP 同步解析

完整 btrace 产物通过原始请求体同步解析，配置如下：

| 环境变量 | 默认值 | 运维含义 |
|---|---:|---|
| `APM_STACK_PARSER_MAX_ARTIFACT_BYTES` | `67108864` | 原始 `.rheajank.zip` 请求体上限；调高前必须同时验证 processor 限制、堆和临时磁盘 |
| `APM_STACK_PARSER_MAX_CONCURRENT_PARSES` | `2` | 单实例同步解析许可数；满载返回 503 和 `Retry-After` |
| `APM_STACK_PARSER_MAPPING_ROOT` | 空 | 仅保留测试构造器兼容配置；生产卡顿解析从统一符号表注册表按 `appId + buildId` 读取 |

服务端解析时会使用系统临时目录，不保存原始 ZIP 和完整报告；解析后同步写入卡顿事实与详情。当前服务端要求 manifest 的 `processId` 为 UUID v4；本地 Maven Local processor `1.0.4` 支持同步及类型 `24` 的异步主线程采样，并读取 `asyncSampleIntervalNs` 估算异步点覆盖范围。该版本尚未发布到远程制品仓库，云端服务未随本地升级。历史 processor `1.0.2` 的设备 ZIP 云端验收不能证明异步采样可用。生产仍需从受控制品仓库获取兼容版本，并单独验证解析耗时、503 比例、JVM 堆、临时磁盘、数据库写入和并发容量。接口契约见[卡顿压缩包解析与落库 API](../../../docs/api/stack-artifact-api.md)。

初始化 ClickHouse 时必须按顺序执行 `001_crash_schema.sql`、`002_jank_schema.sql`、`003_jank_sampling_quality.sql`、`004_application_identity_schema.sql`、`005_memory_metrics.sql`、`006_memory_leak_reports.sql`、`007_event_process_identity.sql` 和 `008_background_crash_symbolication.sql`；004 只允许在受影响业务表为空时执行，旧质量列与旧项目结构不自动迁移，005/006 只新增内存采样和异常报告表，007 只追加 `process_id` 列。

内存异常报告配置位于 `apm.memory-leak-report.*`：metadata 默认 2 MiB、report 文件默认 2 MiB、HPROF 附件业务上限默认 256 MiB、总请求业务上限默认 260 MiB、报告保留配置默认 90 天、附件保留 7 天、孤立文件宽限 24 小时，附件目录默认 `build/memory-report-artifacts`。`APM_MEMORY_REPORT_MAX_REPORT_BYTES` 和 `APM_MEMORY_REPORT_ATTACHMENT_RETENTION_DAYS` 可分别覆盖 report 大小和附件保留天数；`APM_MEMORY_REPORT_RETENTION_DAYS` 不会动态修改 ClickHouse TTL，数据库期限仍由 006 SQL 决定。服务端不解析 HPROF，也不暴露静态附件路径。

Spring multipart 和 Compose 的默认限制仍是单 part `32MB`、总请求 `34MB`，先于上述业务限制生效；因此默认部署不能接收 256 MiB HPROF。需要大附件时同时配置 `APM_MULTIPART_MAX_FILE_SIZE` 和 `APM_MULTIPART_MAX_REQUEST_SIZE`，后者须为所有 part 及 multipart 边界预留空间，并对照业务总请求上限；Nginx 当前 `client_max_body_size` 为 `260m`。调高业务上限时也要同步网关上限。

运行镜像使用本机构建的 JAR，不在云端解析内部 Maven 制品。统一发布、持久卷、端口和部署验收由[平台部署页](../../../docs/knowledge-base/07-部署与运维.md)维护。

## 服务健康基线

当前已配置并可使用：

```http
GET /actuator/health
GET /actuator/info
GET /actuator/metrics
```

`/actuator/health` 可匿名访问，`/actuator/info` 与 `/actuator/metrics` 要求网页 Session 认证。当前没有 `/api/v1/ping` 自定义接口，也没有把 ClickHouse 注册为 Actuator 健康贡献者；ClickHouse 访问失败会在上报或查询请求中体现为存储错误。正式部署前需要补齐依赖健康状态、就绪/存活探针和告警。

Crash 质量指标已经注册到 Micrometer，包括 `apm_ingest_events_received_total`、`apm_ingest_events_rejected_total`、`apm_ingest_events_duplicate_total`、`apm_ingest_retryable_failures_total`、`apm_crash_denominator_insufficient_total`，以及上报/可见延迟 Timer。

卡顿接收还注册了 `apm_jank_events_received_total`、`apm_jank_events_accepted_total`、`apm_jank_events_rejected_total`、`apm_jank_events_duplicate_total`、`apm_jank_events_schema_rejected_total`、`apm_jank_events_algorithm_rejected_total`、按版本标记的 `apm_jank_schema_version_total`/`apm_jank_algorithm_version_total`、`apm_jank_visible_delay` 和 `apm_jank_fact_detail_inconsistency_total`。其中事实/详情不一致计数表示卡顿事实写入成功但详情写入失败的可观测故障，不代表已经完成自动补偿；重复和可见延迟的生产告警阈值仍待确认。

## Agent 查询运行开关

设置 APM_AGENT_QUERY_ENABLED=true 才开放 /api/agent/v1 并允许创建新查询 Token；默认 false。额度由 APM_AGENT_TOKEN_PER_MINUTE、APM_AGENT_TOKEN_CONCURRENT、APM_AGENT_APP_PER_MINUTE、APM_AGENT_APP_CONCURRENT、APM_AGENT_INVALID_PER_IP_PER_MINUTE 配置。mcp-server 独立运行，固定连接 backend，配置和启动步骤见 [MCP README](../../../mcp-server/README.md)。Compose 容器只有 backend 需要 PostgreSQL/ClickHouse 凭据，MCP 不配置数据库凭据。

## 单事件分析运行配置

`APM_AGENT_ANALYSIS_ENABLED` 默认 false，由 Compose 显式传入。Python 仅接收应用 Worker 凭据；模型沿用宿主配置，模型密钥不传入 Java、网页或 MCP。Skill、支持报告版本 4 的后端和网页须配套升级，保留 `config.local.json`，旧活动/待回传记录须先用原工具结束并核验停止。配置和恢复规则见[分析专题](local-analysis.md)及[Worker 运行说明](../../../agent-skills/apm-crash-analyze/worker/README.md)。

## 常见排查

| 现象 | 检查与处理 |
|---|---|
| Wrapper 下载或缓存锁失败 | 核对 JDK 21、网络和 `GRADLE_USER_HOME`；脚本通过 bash 调用 Wrapper |
| processor 无法解析 | 检查 Maven Local 的固定坐标、来源和摘要；不要把本机缓存当作正式仓库 |
| 应用装配失败 | 检查 PostgreSQL、Flyway、稳定主密钥和完整后端日志 |
| health 为 UP 但遥测失败 | Actuator 未包含 ClickHouse 健康贡献者，仍需执行实际写入/查询 |
| 运行中出现 NoClassDefFoundError | 核对运行 JAR 是否被后续构建覆盖；复制到独立版本目录后重启，后续构建不得覆盖正在运行的文件 |
| 重启后内存事件消失 | memory 模式不持久化遥测事件；需要跨重启保留时使用 ClickHouse |

独立运行后端连接云端调试数据库时，显式设置 `APM_DATABASE_URL`、`CLICKHOUSE_URL` 及凭据；Compose 全栈始终使用容器内数据库。配置保持本地忽略，不在文档重复服务器地址或输出真实值。
