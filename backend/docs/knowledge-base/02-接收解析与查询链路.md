# 后端接收解析与查询链路

本页记录服务端内部处理过程。HTTP 字段、错误码和统计口径以[API 文档](../../../docs/api/README.md)为准；端到端可靠性见[平台协议与可靠性](../../../docs/knowledge-base/04-上报协议与可靠性.md)。

## 当前事件与卡顿服务端链路

仓库已有独立 Nginx HTTP Web 容器；后端上报链路没有通用限流器或 Kafka，Agent 只读查询另有单实例频率/并发限额。JSON/gzip 批次由 `ingest` 处理协议、应用鉴权和整批包名校验，再通过公开 API 分派给 Crash、Jank 或 Memory；公共协议在进入领域前要求 UUID v4 `processId`，事件经过专属校验、脱敏和 `(appId,eventId)` 幂等写入。卡顿个例由 `jank` 的原始 `.rheajank.zip` 入口同步执行 App Key 校验、受限读取、manifest 身份预检、processor 解析、服务端质量派生、脱敏、指纹和领域端口写入。各领域根据 `apm.storage.mode` 使用内存或 ClickHouse 适配器，存储不可用统一返回可重试 503。

内存异常报告由 `memory.internal.web.MemoryLeakReportController` 独立接收必填 metadata JSON 文件、必填 report JSON 文件和可选 HPROF。`MemoryLeakReportParser` 对 metadata、SDK 四个顶层字段、UUID v4 `processId`、GC 路径和大小边界做有界校验，保留受限 report 原始 JSON；`MemoryLeakReportIngestService` 在单实例内按 `appId/eventId` 串行处理 metadata+report 摘要冲突和 HPROF 摘要，附件由 `MemoryLeakArtifactStore` 流式临时写入后优先原子移动，不支持时回退为普通移动。`MemoryLeakQueryService` 只从报告事实按 signature 展开问题和 UTC 趋势，不把异常报告送入 `memory_sample`。

`processId` 的缺失、空值、数值 PID 和非 v4 值都属于永久校验错误；服务端不从上传连接、进程名或 `sessionId` 随机/自动推断。历史 ClickHouse 行读取为空字符串时映射为缺失值，不能伪造 UUID。当前 `rhea-trace-processor:1.0.2` 已支持客户端主线程-only UUID v4 manifest；服务端不静默丢弃或替换该字段。

## 接收与查询的职责分配

- `ingest` 负责 JSON/gzip 协议、批次编排与信号分派，通过 `identity`、`crash`、`jank`、`memory` 的公开 API 调用业务能力。
- `jank` 负责原始 ZIP 的受限读取、processor 解析、mapping 选择、质量派生、脱敏、指纹以及事实/详情写入；原始 ZIP 和完整报告不作为持久化对象。
- Crash 查询通过 `CrashQueryPort` 在 ClickHouse 完成过滤、逻辑去重、统计和摘要分页，内存适配器保留 Java 参考计算；FPS/挂起率指标和内存指标通过各自领域专属端口在数据库聚合。卡顿个例查询由 `ClickHouseJankQuerySql` 先过滤、按 `event_time,event_id` 升序取 `limit` 条（默认 50、最大 500），连同 `jank_payload_json/jank_analysis_json` 返回 Java，再由 `JankQueryService` 统计、分桶、排序和分页；没有使用 Issue 小时聚合表，超出该数量时不能保证完整统计或持续翻页。内存适配器筛选后保留全部事件，不能据小型固定集声称两种适配器在超过 `limit` 时仍等价。
- 内存异常报告按应用/时间/普通维度在数据库过滤后读入 Java 聚合和分页；`signature` 和 `keyword` 在 Java 过滤，尚无数据库聚合分页及独立扫描预算。内存概览与趋势分别统计非缺失原始样本，分位数使用线性插值；公开公式只在 API 文档维护。卡顿个例与报告查询缺口见[平台待确认事项](../../../docs/knowledge-base/13-待确认事项.md)。
- `bootstrap` 负责 Spring 装配、异常翻译和 Micrometer；`platform` 提供无业务表语义的 ClickHouse HTTP 能力。

身份校验与文件访问安全顺序见[安全实现](04-认证授权与安全实现.md)，写入一致性见[持久化](03-持久化与数据库迁移.md)。
