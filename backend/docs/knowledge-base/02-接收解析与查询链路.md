# 后端接收解析与查询链路

内存指标使用运行期观测峰值与独立009表，历史窗口默认90天；三项峰值上下文独立，查询按lastSampledAt归属并返回runCount。客户端和联合验收仍待完成，完整契约见[内存API](../../../docs/api/memory-metrics-api.md)。

本页记录服务端内部处理过程。HTTP 字段、错误码和统计口径以[API 文档](../../../docs/api/README.md)为准；端到端可靠性见[平台协议与可靠性](../../../docs/knowledge-base/04-上报协议与可靠性.md)。

## 当前事件与卡顿服务端链路

仓库已有独立 Nginx HTTP Web 容器；后端上报链路没有通用限流器或 Kafka，Agent 只读查询另有单实例频率/并发限额。JSON/gzip 批次由 `ingest` 处理协议、应用鉴权和整批包名校验，再通过公开 API 分派给 Crash、Jank 或 Memory；公共协议在进入领域前要求 UUID v4 `processId`，事件经过专属校验、脱敏和 `(appId,eventId)` 幂等写入。卡顿个例由 `jank` 的原始 `.rheajank.zip` 入口同步执行 App Key 校验、受限读取、manifest 身份预检、processor 解析、服务端质量派生、脱敏、指纹和领域端口写入。各领域根据 `apm.storage.mode` 使用内存或 ClickHouse 适配器，存储不可用统一返回可重试 503。

内存异常报告由 `memory.internal.web.MemoryLeakReportController` 独立接收必填 metadata JSON 文件、必填 report JSON 文件和可选 HPROF。`MemoryLeakReportParser` 对 metadata、SDK 四个顶层字段、UUID v4 `processId`、GC 路径和大小边界做有界校验，保留受限 report 原始 JSON；`MemoryLeakReportIngestService` 在单实例内按 `appId/eventId` 串行处理 metadata+report 摘要冲突和 HPROF 摘要，附件由 `MemoryLeakArtifactStore` 流式临时写入后优先原子移动，不支持时回退为普通移动。`MemoryLeakQueryService` 只从报告事实按 signature 展开问题和 UTC 趋势，不把异常报告送入 `memory_peak_summary`。

`processId` 的缺失、空值、数值 PID 和非 v4 值都属于永久校验错误；服务端不从上传连接、进程名或 `sessionId` 随机/自动推断。历史 ClickHouse 行读取为空字符串时映射为缺失值，不能伪造 UUID。当前使用 Maven Local 的 `rhea-trace-processor:1.0.4`，支持客户端主线程-only UUID v4 manifest 和异步采样类型 `24`；服务端不静默丢弃或替换该字段。

## Crash 接收与后台处理

Crash/app_start 只写当前事实数据集。每个新 Crash 先确认版本 0 的 pending/raw_chain 状态，再确认不可变事实；两侧确认后才 accepted。部分写入通过原 eventId/buildId/occurredAt 重试补缺，不重置已还原状态。接收后仅做可用 mapping 检查与构建唤醒，不调用 R8；跨库通知失败由持久化轮转对账补偿。

后台每批固定活动 mapping 文件租约，成功唯一登记后同版本同字节发布并读回对账。详情、analysisSnapshot 和分析任务冻结仅只读当前单份 stack，不再请求内还原。摘要先取最新状态再筛选指纹，Crash 与启动分母均来自新事实；不混入旧事实、旧启动或旧聚合。资源与恢复见[符号表专题](symbol-mapping.md)。

## 接收与查询的职责分配

- `ingest` 负责 JSON/gzip 协议、批次编排与信号分派，通过 `identity`、`crash`、`jank`、`memory` 的公开 API 调用业务能力。
- `jank` 负责原始 ZIP 的受限读取、processor 解析、mapping 选择、质量派生、脱敏、指纹以及事实/详情写入；原始 ZIP 和完整报告不作为持久化对象。
- Crash、Jank 的总览/趋势/Issue/事件摘要均在 ClickHouse 完成过滤、逻辑去重、统计及最终分页；内存适配器保留 Java 参考。Jank 使用完整排序游标，Issue 聚合后应用 limit+1，摘要不读取采样 JSON，详情独立。没有引入小时聚合表，新路径的资源证据见[查询验收](backend-api-query-validation.md)。
- 内存异常报告在 ClickHouse FINAL 中展开路径、字面筛选并按事件/signature 去重，一次查询返回全范围总计和有序问题页，不读取 report_json；同时间最新路径按 eventId 升序选取。趋势在数据库聚合，Java 只补齐已校验的最多 2000 空桶。页偏移使用 long，两种查询均应用平台默认预算。内存指标的缺失样本和线性插值口径保持。
- `bootstrap` 负责 Spring 装配、异常翻译和 Micrometer；`platform` 提供无业务表语义的 ClickHouse HTTP 能力。

身份校验与文件访问安全顺序见[安全实现](04-认证授权与安全实现.md)，写入一致性见[持久化](03-持久化与数据库迁移.md)。
