# 后端工程结构与模块边界

后端是独立 Gradle 单模块、单个 Spring Boot 进程。平台组件拓扑和架构决策分别见[总体架构](../../../docs/knowledge-base/02-总体架构与模块.md)与[架构决策](../../../docs/knowledge-base/10-架构决策记录.md)。

## 代码组织与依赖规则

当前代码按以下业务模块组织：

```text
com.shanshui.apmserver
├─ bootstrap    # Spring 配置绑定、安全装配、异常翻译和 Micrometer 实现
├─ identity     # 用户、Session、应用、成员、App Key 与 PostgreSQL 适配器
├─ ingest       # JSON/gzip 协议、请求限制、批次编排与信号分派
├─ crash        # Crash/app_start 模型、接收、查询及专属存储适配器
├─ jank         # 卡顿 ZIP、FPS/挂起率、查询及专属存储适配器
├─ memory       # PSS/VSS/Java 堆采样、查询及专属存储适配器
├─ telemetry    # 不依赖框架的公共事件元数据、写入结果和异常语义
└─ platform     # 无业务表语义的 ClickHouse HTTP 与公共基础配置
```

业务模块对外只暴露 `api` 包，实现放在 `internal` 包。`bootstrap` 是唯一组合根，可以装配所有模块；`ingest` 只能通过 API 调用 Identity、Crash、Jank 与 Memory；Crash、Jank、Memory 不能相互依赖；`platform` 不依赖业务模块。ArchUnit 在测试阶段强制模块依赖白名单、`internal` 隔离、应用层不依赖 Web，以及持久化层不依赖 Web/应用实现。这些是代码边界，不等于独立部署单元。

模块内部统一按需要继续划分：

```text
<module>
├─ api          # 跨模块允许依赖的接口、命令、结果和最小配置端口
└─ internal
   ├─ application  # 领域用例编排
   ├─ domain       # 信号专属模型与规则
   ├─ port         # 领域定义的持久化端口
   ├─ persistence  # PostgreSQL、ClickHouse 或内存适配器
   └─ web          # HTTP 请求转换与 Controller
```

仓库根包仅保留 `ApmServerApplication` 作为 Spring Boot 启动入口。原 `domain/service/repository/web/config/security` 顶层生产包已迁空，不再作为跨模块入口。

## 当前工程差异

当前 `backend/build.gradle.kts` 的工具链统一为 Java 21，与原方案推荐一致。Spring Boot 4.1、Gradle Toolchain 和开发/部署环境按 Java 21 作为构建基线；历史 JDK 17 验证记录仍保留为历史证据。

当前 `backend/build.gradle.kts` 实际依赖包含 Actuator、Jackson、Validation、WebMVC、Spring Security、Spring Session JDBC、Spring Data JPA、Flyway、PostgreSQL 驱动、Testcontainers、R8 `8.9.35` 和非传递接入的 `rhea-trace-processor:1.0.2` fat JAR；ClickHouse 仍使用 JDK `HttpClient`。项目依赖按 Maven Local、仅匹配 `com.android.tools` 的阿里云 Google Maven 镜像、Google Maven 官方源、阿里云公共 Maven 镜像、Maven Central 的顺序解析；processor 仍需由 Maven Local 提供。客户端主线程-only v3 UUID ZIP 已通过本机解析和云端 HTTP/落库验收，生产仍不能依赖本地缓存。正常运行环境需要 PostgreSQL，测试默认使用 H2，PostgreSQL schema 测试在 Docker 可用时使用 Testcontainers。

前端依赖、页面范围和未实现能力由[前端知识库](../../../frontend/docs/knowledge-base/README.md)维护。平台侧只依赖其遵守“浏览器不直连 ClickHouse、正式权限由后端强制执行、生产通过同源网关或静态服务器代理 `/api`”的边界。
