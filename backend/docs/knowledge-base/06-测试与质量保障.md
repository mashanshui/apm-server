# 后端测试与质量保障

本页维护测试方法、执行条件与有用的证据摘要。普通构建、重启、部署和文档检查的逐次输出留在任务结果或 CI；专项查询计划和性能证据通过下方唯一入口维护。

## 执行命令与分层

从仓库根目录执行（Java 21）：

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
export GRADLE_USER_HOME="$PWD/.gradle-local"
bash backend/gradlew -p backend test --no-daemon --console=plain
```

macOS 的 JDK 发现方式如上；其他环境设置已安装的 JDK 21，Windows 使用 `backend/gradlew.bat -p backend`。构建配置或依赖变化时运行 `clean build`。HTML 报告位于 `backend/build/reports/tests/test/`，机器可读结果位于 `backend/build/test-results/test/`，这些构建目录会被覆盖，不是永久证据库。

| 层次 | 测试入口与重点 | 限制 |
|---|---|---|
| JUnit / MockMvc | 协议、校验、脱敏、指纹、授权、幂等、错误及分页 | 不代表真实 Servlet/外部数据库链路 |
| ArchUnit | `ArchitectureBaselineTests`：依赖白名单、跨模块 internal 隔离、旧包反向依赖 | 没有依赖环及新包分层断言 |
| PostgreSQL | `ManagementSchemaIntegrationTests`、`AuthenticationHttpPostgresTests`、分析任务/迁移专项 | Docker/Testcontainers；schema 校验、JDBC 会话及真实 HTTP；需报告环境跳过 |
| ClickHouse | Crash/Jank/Memory 集成与资源预算测试 | 独立测试库，不能推导生产并发、TTL 或恢复 |
| SQL / Grafana 资源 | 迁移、Schema 与 JSON 结构 | 结构检查不等于数据库或 Dashboard 实际运行 |
| processor / R8 | `RheaStackAnalyzerIntegrationTests`、`R8RetraceEngineTests`、解析/租约专项 | 默认 ZIP 会改写历史夹具的 UUID、主线程采样及摘要，不等于未经修改的真机 ZIP |

`rhea.jank.fixture` 虽被测试读取，但当前 Gradle 未转发该属性；不能仅传 `-D` 就声称外部 ZIP 已用于测试。真实设备产物需另行核验。固定期望见[Crash](../../../docs/crash-fixed-dataset.md)、[卡顿](../../../docs/jank-fixed-dataset.md)、[内存](../../../docs/memory-fixed-dataset.md)和[报告](../../../docs/memory-leak-fixed-dataset.md)数据集。

## 条件专项

| 专项 | 显式条件 | 证据入口 |
|---|---|---|
| Crash 合成容量 | `RUN_CRASH_BENCHMARK=true` | [Crash 查询基线](crash-query-performance-baseline.md) |
| 真实 release mapping | `-Dapm.real.mapping=<真实 mapping 绝对路径>` | `R8RetraceEngineTests`；路径不超过业务文件限制 |
| 符号表性能 | 同时设置 `-Dapm.symbol.benchmark=true` 和 mapping 路径 | 下方[符号表验收](#符号表端到端与性能边界) |
| 卡顿指标 JVM 基线 | 定向执行 `JankMetricsPerformanceTests` | [卡顿指标基线](jank-performance-baseline.md) |

Gradle 显式转发 mapping 和 symbol benchmark 属性。跳过项必须与通过项分列；基线开关默认关闭，常规集成通过不能替代容量专项。

## 最近完整自动化基线

2026-10-05 在 Java 21、macOS、Maven Local processor `1.0.2` 和可用 Docker 环境执行 `clean build`：290 项中 287 通过、0 失败、3 项条件跳过，编译、test/check 和 Boot JAR 均完成。三个跳过项为上表 Crash 容量、真实 mapping 及符号表性能；常规 PostgreSQL/ClickHouse 集成实际执行。

此结果仅表示注明日期的完整自动化基线，不是当前环境每次启动的保证。更早的 processor 摘要失败已由下述来源核验和锁定值更新解决，不再作为当前未解决失败；历史过程可在 Git 版本中追溯。

## processor 制品校验

当前依赖为 `io.github.mashanshui:rhea-trace-processor:1.0.2`，`isTransitive=false`。测试校验实际加载 JAR 的 SHA-256；替换制品须先核验来源、内容和行为，不能仅更新锁定值规避失败。

2026-10-05 已有核验结果：

| 项目 | 结果 |
|---|---|
| Maven Local JAR | 27,374,640 字节；SHA-256 `0c1ac6952ab92526bec24355523048b5e10b14a6ec8a85c9c03070cc67ddb64f` |
| 来源和结构 | 发布元数据与文件一致、ZIP CRC 通过；与对应 processor 构建产物字节一致；sources 与 305 份源码、9,295 个编译类核对一致 |
| 解析行为 | 目标 JAR 上执行 processor 的 ZIP/manifest/mapping/流生命周期测试 42 项通过；后端解析定向 19 项通过；更新锁定值后 Rhea 集成 5 项通过 |
| 运行产物 | Boot JAR 内嵌 processor 摘要与锁定值一致 |
| 外部边界 | 仅本机 Maven Local 制品验证，不是生产受控制品仓库发布或容量验收 |

## 符号表端到端与性能边界

2026-09-20 在 JDK 21、PostgreSQL 16.15、本地文件卷与正式后端页面完成：17,451,901 字节 mapping 上传、后端重启读取、管理员 revision 条件替换、Crash 连续详情实时 Retrace 且事件/指纹不变，以及 v3 Jank 新事件解析/详情。Jank 应用帧与替换样本不匹配，不能声称该样本已还原应用帧。

官方 R8 `8.9.35` 的性能专项保留以下小样本结果：

| mapping 大小 | 首次校验 | 重复详情中位数 / P95 | 采样堆增量 / 当前线程分配 |
|---|---:|---:|---:|
| 17,451,901 字节 | 793.23 ms | 105.19 / 226.73 ms（5 次） | 36.40 / 120.32 MiB |
| 33,554,432 字节 | 941.85 ms | 263.33 / 263.92 ms（3 次） | 91.34 / 484.87 MiB |

最大样本由真实 mapping 追加合法空白扩展，未清空操作系统缓存；堆以 1 ms 轮询，线程分配由 ThreadMXBean 测量。并发 8、许可 2 的受控测试得到 2 个许可及 6 个 busy，并确认许可释放；这些数据不代表稳定尾延迟或生产容量。复跑示例：

```bash
bash backend/gradlew -p backend test --no-daemon --rerun-tasks \
  --tests '*SymbolMappingPerformanceTests' \
  -Dapm.symbol.benchmark=true -Dapm.real.mapping=/绝对路径/mapping.txt
```

## 按能力查证据

| 能力 | 自动化与外部证据 | 独立边界 |
|---|---|---|
| 登录、CSRF、请求错误、PATCH | `AuthenticationApiIntegrationTests`、`AuthenticationHttpPostgresTests`、`FrameworkApiErrorTests`、`AppApiIntegrationTests`；[查询正确性验收](backend-api-query-validation.md) | Cookie Secure=true、全角色浏览器及生产部署另验 |
| Crash 下推与预算 | `ClickHouseCrashQueryIntegrationTests`、`ClickHouseHttpClientQueryBudgetTests`；[Crash 基线](crash-query-performance-baseline.md) | 百万事件宽窗口被预算拒绝，未证明生产容量 |
| Jank/报告完整统计、分页及预算 | `ClickHouseJankAggregationTests`、`ClickHouseMemoryLeakAggregationTests`；[十万个例/万份报告证据](backend-api-query-validation.md) | 合成分布与顺序查询，不是生产并发 |
| FPS/挂起率 | `JankMetricsPerformanceTests`、固定数据脚本；[卡顿基线](jank-performance-baseline.md) | 指标与个例查询不能共用容量结论 |
| 内存采样/报告上传 | 内存测试、真实固定集的写入/重复/冲突/查询；[平台证据摘要](../../../docs/knowledge-base/08-测试与质量保障.md#跨端证据索引) | 不含 SDK 队列或 HPROF 解析 |
| 进程身份/设备 ZIP | 协议及迁移测试、processor `1.0.2` 实际设备 ZIP 解析与有限云端写入/重复/详情 | 不含完整 SDK 生命周期 |
| Agent/MCP 查询 | Token/Agent 授权与限额测试；[双应用验收](../../../docs/agent-query-e2e-validation.md)、[云端接口证据](../../../docs/backend-api-cloud-validation.md) | 不含 HTTPS 或生产容量 |
| 当前代码分析 | `AnalysisTaskPostgresTests`、`AnalysisMigrationPostgresTests`、ArchUnit；[当前代码验收](../../../docs/analysis-validation/current-code-validation.md) | 合成数据与受控宿主不证明生产修复质量或宿主停止 |

云端健康、运行版本和数据状态以[平台最近核验](../../../docs/knowledge-base/00-当前实现与验证边界.md#环境最近核验)为准，证据中的历史资源不能当作当前仍存在。
