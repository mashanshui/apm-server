# 后端测试与质量保障

运行峰值使用MemoryMetrics/MemoryPeak专项验证协议、90天窗口、上下文和旧事件拒绝；持久化与真实HTTP专项覆盖幂等、原身份、503、Agent/MCP一致性，查询预算专项覆盖十万目标运行及资源拒绝。Pixel_6真实SDK联合J1..J7通过，含启动中断、原任务重试和覆盖安装。命令、限流等待、原数据恢复及边界见[统一验收](../../../docs/validation/memory-runtime-peaks/README.md)。HTTP专项显式保留其他事件7天窗口，避免通用测试配置的3650天掩盖回归。

本页维护测试方法、执行条件与有用的证据摘要。普通构建、重启、部署和文档检查的逐次输出留在任务结果或 CI；专项查询计划和性能证据通过下方唯一入口维护。

## 执行命令与分层

宿主分析工具测试在 `agent-skills/apm-crash-analyze/worker/` 执行 `uv run --locked pytest`；已准备的虚拟环境也可用 `.venv/bin/python -m pytest`。合仓回归使用真实 Git 根和未提交的嵌套 Android 文件，检查子目录根定位、带前缀引用的匹配/不匹配与索引保留；报告使用版本 4 的合成材料，不领取真实平台任务。完整工具基线见下文。

从仓库根目录执行（Java 21）：

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
export GRADLE_USER_HOME="$PWD/.gradle-local"
bash backend/gradlew -p backend test --no-daemon --console=plain
```

macOS 的 JDK 发现方式如上；其他环境设置已安装的 JDK 21，Windows 使用 `backend/gradlew.bat -p backend`。构建配置或依赖变化时运行 `clean build`。HTML 报告位于 `backend/build/reports/tests/test/`，机器可读结果位于 `backend/build/test-results/test/`，这些构建目录会被覆盖，不是永久证据库。

| 层次 | 测试入口与重点 | 限制 |
|---|---|---|
| JUnit / MockMvc | 协议、校验、脱敏、指纹、授权、幂等、错误及分页 | 不代表真实 Servlet/外部数据库链路 |
| ArchUnit | `ArchitectureBaselineTests`：依赖白名单、跨模块 internal 隔离、旧包反向依赖 | 没有依赖环及新包分层断言 |
| PostgreSQL | `ManagementSchemaIntegrationTests`、`AuthenticationHttpPostgresTests`、分析任务/迁移专项 | Docker/Testcontainers；schema 校验、JDBC 会话及真实 HTTP；需报告环境跳过 |
| ClickHouse | Crash/Jank/Memory 集成与资源预算测试 | 独立测试库，不能推导生产并发、TTL 或恢复 |
| SQL / Grafana 资源 | 迁移、Schema 与 JSON 结构 | 结构检查不等于数据库或 Dashboard 实际运行 |
| processor / R8 | `RheaStackAnalyzerIntegrationTests`、`AsyncStackArtifactApiIntegrationTests`、`R8RetraceEngineTests`、解析/租约专项 | 历史 ZIP 会改写 UUID、主线程采样及摘要；异步回归使用三个合成类型 24 点，校验 50ms 来源间隔、无统计标记及 accepted/duplicate；两者均不等于未经修改的真机 ZIP |

`rhea.jank.fixture` 虽被测试读取，但当前 Gradle 未转发该属性；不能仅传 `-D` 就声称外部 ZIP 已用于测试。真实设备产物需另行核验。固定期望见[Crash](../../../docs/datasets/crash-fixed-dataset.md)、[卡顿](../../../docs/datasets/jank-fixed-dataset.md)、[内存](../../../docs/datasets/memory-fixed-dataset.md)和[报告](../../../docs/datasets/memory-leak-fixed-dataset.md)数据集。

## 条件专项

| 专项 | 显式条件 | 证据入口 |
|---|---|---|
| 新状态后台候选容量 | `RUN_CRASH_BENCHMARK=true`，定向 `BackgroundCrashQueryPerformanceTests` | [百万当前数据集候选基线](crash-query-performance-baseline.md#新模型后台候选基线)；覆盖后台候选与前台一天窗口并行，不代表生产容量 |
| 真实 release mapping | `-Dapm.real.mapping=<真实 mapping 绝对路径>` | `R8RetraceEngineTests`；路径不超过业务文件限制 |
| 符号表性能 | 同时设置 `-Dapm.symbol.benchmark=true` 和 mapping 路径 | 下方[符号表验收](#符号表端到端与性能边界) |
| 卡顿指标 JVM 基线 | 定向执行 `JankMetricsPerformanceTests` | [卡顿指标基线](jank-performance-baseline.md) |

Gradle 显式转发 mapping 和 symbol benchmark 属性。跳过项必须与通过项分列；基线开关默认关闭，常规集成通过不能替代容量专项。

## processor 制品校验

当前依赖为 Maven Local 的 `io.github.mashanshui:rhea-trace-processor:1.0.4`，`isTransitive=false`。测试校验实际加载 JAR 的 SHA-256；替换制品须先核验来源、内容和行为，不能仅更新锁定值规避失败。

2026-11-06 已有核验结果：

| 项目 | 结果 |
|---|---|
| Maven Local JAR | 27,376,770 字节；SHA-256 `c6601c0df2592612747e4e36fe24dc628533abb7f6a6cbb1fae70ab36f8e01c9`；位置为 `~/.m2/repository/io/github/mashanshui/rhea-trace-processor/1.0.4/` |
| 来源和结构 | Maven 坐标/manifest 版本一致，JAR 与 sources 的 ZIP CRC 通过；两者分别与本机 btrace processor 构建产物字节一致；源码含异步类型 24 校验及来源间隔估算 |
| 解析行为 | 旧 1.0.2 对现有异步设备 ZIP 报“sampling 记录类型无效: 24”，1.0.4 可解析；合成异步点回归校验类型、50ms 间隔和无线程统计，真实 Processor 的 MockMvc 请求验证 accepted/duplicate；完整后端基线见上文 |

| 外部边界 | 仅本机 Maven Local 制品与本地模拟器上传验证，未发布远程 Maven 制品或升级云端；不是生产容量验收 |
