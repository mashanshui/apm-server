# 后端认证授权与安全实现

本页记录服务端执行安全约束的方式。跨端身份、权限与隐私原则见[平台安全与隐私](../../../docs/knowledge-base/06-安全与隐私.md)，公开契约见[应用 API](../../../docs/api/app-api.md)。

## 上报鉴权与包名校验顺序

两条入口都先把 `X-App-Key` 的 SHA-256 摘要映射为 `appId + packageName`。缺失、格式错误和未知 Key 统一在读取正文前返回 401；PostgreSQL 鉴权故障返回可重试 503 和 `Retry-After: 30`。正文解析后必须显式提供 `packageName`：JSON 任一事件不匹配会在部分接受前整批 403，ZIP manifest 不匹配会在 mapping、指纹和存储前 403。服务端只使用鉴权结果提供的系统 `appId`，不接受正文声明的应用 ID，也不使用全局项目 ID 或全局 Key 补值。


## 载荷保护与凭据实现

服务端对异常消息替换邮箱、URL、用户路径、手机号和 UUID，并截断字段；`anonymousDeviceId` 使用应用盐 SHA-256 保存，`processId` 只接受标准 UUID v4 并保留原值，属性名采用白名单，测量值只保留数字。进程实例标识不是鉴权凭据，不能替代 `appId`、Session 或 App Key。应用日志不输出请求体、异常消息、堆栈或完整 App Key。当前事件模型拒绝未知 JSON 字段，且 `attributes` 默认最多保留 32 项。

App Key 不再来自全局配置或开发默认值；每个应用由 `SecureRandom` 生成独立 Key，格式为 `apm_ak_` 加无填充 Base64URL 随机值。`APM_APP_KEY_ENCRYPTION_KEY` 必须是 Base64 编码的 32 字节值且没有默认值，用于 AES-256-GCM 恢复完整 Key；部署方必须稳定注入并备份。`APM_DEVICE_HASH_SALT` 和 `CLICKHOUSE_PASSWORD` 仍应使用受保护配置，并验证所有敏感值不会进入日志、镜像或版本库。

`POST /ingest/v1/stack-artifacts:parse` 在读取正文前校验 `X-App-Key`，只接受版本化媒体类型和受限原始输入流；`Content-Length` 与实际读取字节都受 `apm.stack-parser.max-artifact-bytes` 限制。入口先校验 manifest UUID v4 `processId`，processor 再校验 ZIP 固定条目、manifest、声明大小、SHA-256 和解压总量；错误响应只返回稳定错误码，不回显 processor 异常文本、ZIP 内容或服务端路径。

客户端不再发送 mapping 标识或路径。服务端只使用通过产物完整性校验的 `buildId`，从按应用隔离的符号表注册表取得当前受控文件租约，并执行规范化路径与 `toRealPath()` 包含校验以阻止跨应用和符号链接逃逸；文件缺失时继续保存未解混淆证据。网页 mapping 上传要求 Session/CSRF 和 `OWNER`/`ADMIN`，文件目录应使用持久卷且不能通过下载接口暴露。

服务端不保存原始 ZIP、完整 processor 报告或 Crash Retrace 结果；mapping 文件只保存在受控卷，数据库保存摘要和版本审计，卡顿事件保存查询需要的脱敏事实和证据。成功响应只有业务元数据；错误与日志不得回显 App Key、ZIP、完整堆栈、设备原标识、processor/R8 内部异常或服务端路径。

## 凭据读写投影

应用管理域新增独立一对一 `app_ingest_credential` 表和 `AppKeyCrypto`/`AppIngestCredentialService`。普通应用查询只读取包名投影，不加载密文或摘要；上报鉴权只按 Key 摘要唯一索引读取 `appId + packageName` 投影，不执行解密。只有敏感凭据查询接口才加载密文并使用部署主密钥解密。
