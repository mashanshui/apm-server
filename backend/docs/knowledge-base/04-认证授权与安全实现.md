# 后端认证授权与安全实现

## 应用查询 Token

V5 迁移新增 `app_query_token`：应用和创建者外键、唯一 SHA-256 摘要、短显示前缀、固定 `apm:read` 权限、创建/到期/撤销时间；不保存完整值或可恢复密文。`QueryTokenMaterial` 用 `SecureRandom` 生成 32 字节随机值。管理服务在 PostgreSQL 应用行悲观锁下检查有效数量，按配置默认限制每应用 20 个；只能选 30、90、365 天，默认 90 天。状态按查询时刻派生，撤销是幂等软删除。

管理接口沿用网页 Session、CSRF 和 `OWNER`/`ADMIN` 成员检查。独立 `/api/agent/v1/**` 安全链为无状态请求级 Bearer 认证，每次通过 Token 摘要查库并检查撤销/到期；Cookie、网页 Session 和 `X-App-Key` 不参与此链。当前 Agent HTTP 提供应用信息及 Crash、卡顿、内存共 19 个 GET 查询路由；缺失、未知、撤销和过期 Token 统一返回 401，凭据数据库故障为 503。详情见[查询 Token API](../../../docs/api/query-token-api.md)与[Agent HTTP API](../../../docs/api/agent-query-api.md)。

## 上报鉴权与包名校验顺序

JSON 批次和卡顿 ZIP 两条入口都先把 `X-App-Key` 的 SHA-256 摘要映射为 `appId + packageName`。缺失、格式错误和未知 Key 统一在控制器读取正文前返回 401；PostgreSQL 鉴权故障返回可重试 503 和 `Retry-After: 30`。正文解析后必须显式提供 `packageName`：JSON 任一事件不匹配会在部分接受前整批 403，ZIP manifest 不匹配会在 mapping、指纹和存储前 403。服务端只使用鉴权结果提供的系统 `appId`，不接受正文声明的应用 ID，也不使用全局项目 ID 或全局 Key 补值。

内存异常报告也使用 App Key，但其 `@RequestPart MultipartFile` 参数由 Spring 在调用控制器前解析；`resolve-lazily=true` 不能保证鉴权先于 multipart part 解析。纯 JSON 请求进入独立拒绝路由并返回 415。不能把上述两条原始流入口的“鉴权前不读正文”保证泛化到 multipart 报告上传。

## 载荷保护与凭据实现

Crash、卡顿和内存采样 sanitizer 对异常文本替换邮箱、URL、用户路径、手机号和 UUID，并截断字段；`anonymousDeviceId` 使用部署级 `APM_DEVICE_HASH_SALT` 与去除首尾空白的设备标识拼接后计算 SHA-256，不包含 `appId`，没有按应用派生盐。内存异常报告 parser 不调用这些 sanitizer，保存 metadata 的设备标识和受限 report 原始 JSON；客户端必须提供不含个人信息的匿名随机标识和诊断内容，不能声称报告已获得相同脱敏。`processId` 只接受标准 UUID v4 并保留原值。进程实例标识不是鉴权凭据，不能替代 `appId`、Session 或 App Key。

公共事件信封拒绝未知字段；`attributes` 的键只校验 `[A-Za-z0-9_.-]{1,64}` 格式，没有业务属性名白名单。Crash sanitizer 对输入前 32 项筛选合法键并脱敏字符串值，`measurements` 只保留数字。应用日志不输出请求体、异常消息、堆栈或完整 App Key；已有长度、格式和模式替换约束不能视为任意诊断内容的完整隐私审查。

Crash 补充现场中的线程名、帧、logcat、proc 文本和设备文本在客户端持久化前及服务端存储前分别处理已知凭据、邮箱、手机号、URL 和私有路径；FD 只保留安全目标类别。结构化线程 Java ID、数值 TID/PID、UUID `processId`、`buildId` 和内存字节数不套用自由文本替换。网页/Agent 详情按应用授权，MCP 大现场分片读取；分析任务冻结证据仍只包含主异常。模式脱敏不能识别任意未知秘密，采集端不应主动记录敏感业务内容。

App Key 不再来自全局配置或开发默认值；每个应用由 `SecureRandom` 生成独立 Key，格式为 `apm_ak_` 加无填充 Base64URL 随机值。`APM_APP_KEY_ENCRYPTION_KEY` 必须是 Base64 编码的 32 字节值且没有默认值，用于 AES-256-GCM 恢复完整 Key；部署方必须稳定注入并备份。`APM_DEVICE_HASH_SALT` 和 `CLICKHOUSE_PASSWORD` 仍应使用受保护配置，并验证所有敏感值不会进入日志、镜像或版本库。

`POST /ingest/v1/stack-artifacts:parse` 在读取正文前校验 `X-App-Key`，只接受版本化媒体类型和受限原始输入流；`Content-Length` 与实际读取字节都受 `apm.stack-parser.max-artifact-bytes` 限制。入口先校验 manifest UUID v4 `processId`，processor 再校验 ZIP 固定条目、manifest、声明大小、SHA-256 和解压总量；错误响应只返回稳定错误码，不回显 processor 异常文本、ZIP 内容或服务端路径。

客户端不再发送 mapping 标识或路径。服务端使用同一 ZIP 的预检应用版本及完整性校验后的非空 buildId，按认证应用/版本优先专用、缺失时选择版本默认 mapping，取得实际来源的受控文件租约，并执行规范化路径与 `toRealPath()` 包含校验以阻止跨应用和符号链接逃逸；没有 mapping 注册记录时继续保存未解混淆证据，已有记录对应文件缺失或不可读时卡顿解析返回可重试存储错误，JVM 后台工作记录存储失败并退避，详情只读已有状态而不执行还原。网页 mapping 上传要求 Session/CSRF 和 `OWNER`/`ADMIN`，文件目录应使用持久卷且不能通过下载接口暴露。

SO 批次的 Session、请求头 CSRF 和应用写角色先于 multipart 正文读取；随后取得单实例不排队许可及磁盘预算，受控流式接收、ZIP/ELF 校验和清理共享期限。请求参数不能替代 CSRF 头。此保证只适用于 SO 专用路由，不泛化到其他 multipart 入口。SO 不执行或加载二进制文件，也不进入 R8；失败分类与安全提示见[符号表专题](symbol-mapping.md#so-接收与校验)。

服务端不保存原始 ZIP 或完整 processor 报告；Crash 首次成功后的完整脱敏 Retrace 结果和来源按事件持久化，mapping/SO 文件只保存在受控卷，数据库另保存摘要和版本审计。卡顿事件保存查询需要的脱敏事实和证据。错误与应用排障日志不得回显 App Key、ZIP、完整堆栈、设备原标识、processor/R8 内部异常或服务端路径。

## 凭据读写投影

应用管理域新增独立一对一 `app_ingest_credential` 表和 `AppKeyCrypto`/`AppIngestCredentialService`。普通应用查询只读取包名投影，不加载密文或摘要；上报鉴权只按 Key 摘要唯一索引读取 `appId + packageName` 投影，不执行解密。只有敏感凭据查询接口才加载密文并使用部署主密钥解密。

## Agent 查询身份与限流

应用查询 Token 的完整值只在创建时返回，持久化只保存 SHA-256 摘要和审计元数据。Agent 安全链逐请求查询 PostgreSQL，不接受 Session 或上报 X-App-Key 作为替代；Token 身份只携带绑定 appId 和只读权限。单实例内存限流按 Token、应用和无效来源 IP 分别实施频率与并发限制，429 携带 Retry-After，日志只记录 requestId、appId、tokenId、状态与耗时。APM_AGENT_QUERY_ENABLED 默认 false；关闭时拒绝外部查询和新 Token 创建，但列表与撤销仍由 Session 管理。详见 [Token API](../../../docs/api/query-token-api.md) 和 [Agent API](../../../docs/api/agent-query-api.md)。

## 网页登录与会话

手动登录在保存 SecurityContext 前显式调用共用 SessionAuthenticationStrategy，按顺序执行 ChangeSessionIdAuthenticationStrategy 与 CsrfAuthenticationStrategy，再立即生成并保存可用的新 CSRF Cookie。失败凭据不保存身份；退出销毁会话。

当前使用 spring-boot-starter-session-jdbc 提供 Boot 4 会话自动配置与 JdbcIndexedSessionRepository，仅声明底层 spring-session-jdbc 不足以装配。JDBC 表仍由 Flyway 管理，spring.session.timeout 与 Servlet 超时共用 APM_SESSION_TIMEOUT（默认 8h）。H2/MVC 测试排除 JdbcSessionAutoConfiguration，PostgreSQL 随机端口专项恢复自动配置并要求真实仓储 Bean。

旧会话拒绝、首个写请求与退出的自动化见[后端测试](06-测试与质量保障.md)，Cookie CSRF 历史值边界以[API](../../../docs/api/app-api.md#会话与-csrf)为准。

## 框架错误安全边界

ApiExceptionHandler 明确映射 MVC 正文、类型、缺失 query/header/part、Bean/方法校验及 405/415。字段错误采用固定说明并限为 50 条，不读取 rejectedValue 或解析器原文；未知 JSON 属性不回显。方法返回值违反约束仍为 500。框架响应保留 Allow/媒体协商头，未使用捕获全部 Exception 的 400 处理器；鉴权、CSRF、Agent 只读及领域错误沿用原处理器。契约及验证见[框架请求错误](../../../docs/api/request-errors.md)。

## 应用部分更新

AppUpdateRequest 的 setter 记录字段存在性并拒绝非字符串且非 null 的 JSON。事务先 requireEdit、读取应用，规范化全部已提交字段后才调用 update；省略字段取现值，规范化后相同则不更新时间。空对象仍执行权限。无乐观锁增量，并发写同字段仍为后写覆盖。契约见[应用 API](../../../docs/api/app-api.md#应用部分更新)。

## 单事件分析身份与宿主边界

Worker 凭据仅按应用授权，有期限、可撤销、摘要存储且完整值只展示一次；独立安全链不接受 Session、App Key 或查询 Token。当前 claim 仅含 requestId，报告绑定当前 Run 和证据；取消/租约/停止门禁及管理员实际核验仍有效。结构校验不能把 HOST_REPORTED 修改/测试变成独立鉴证。

Python 本地配置与状态须保持私有，不能读取/回传秘密；宿主按用户分析/明确修复范围执行。模型与终端不受 Python 的操作系统沙箱控制。任务、停止和恢复的唯一正文见[分析专题](local-analysis.md)，配置权限与注入规则见[Worker 说明](../../../agent-skills/apm-crash-analyze/worker/README.md#配置与开发)。
