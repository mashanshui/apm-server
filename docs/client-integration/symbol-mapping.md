# Android 符号文件接入

事件的 appVersion 和 buildId 保持原始必填值，不因上传 mapping 可省略 buildId 而更改 SDK 构建配置、队列或上报格式。Rhea SDK 与 processor 使用 1.0.4；不需要修改外部 btrace。完整 HTTP 字段、错误和预算见[符号表 API](../api/symbol-api.md)。

## 网页操作

先选择 mapping 或 SO 标签页，通过版本和对应身份筛选已有文件。需要上传时点击列表右上角“上传符号表”，在弹窗中选择文件并提交；从详情入口进入时自动打开并预填。取消或 Escape 关闭会清理所选文件与冲突，上传期间保持弹窗。列表中的“文件详情”可展开查看完整摘要和上传人。

## mapping 选择

上传文本 mapping 时填写与事件完全一致的应用版本。buildId 留空表示此版本默认 mapping；填写原构建值表示专用 mapping。服务端先找同版本构建专用，只有登记不存在才找版本默认；文件不可读或查询故障不会退回默认。其他版本或其他构建的唯一文件也不会被猜测使用。

从未成功 JVM 详情进入管理页，会预填版本与原 buildId。可以保留构建登记专用，也可以清空登记默认。默认文件必须适用于该版本没有专用登记的构建；同一版本若存在不同混淆产物，应为相应构建上传专用文件。应用版本、构建与文件修订号含义不同。

已有不同字节时需核对新旧 SHA-256 并明确确认替换。上传完成仅表示文件保存及版本工作已登记；查看“版本本轮还原”了解后台情况，计数涵盖此版本全部构建，不是当前文件独有数量。

JVM 主异常首次成功后，结果、实际来源、指纹及辅助线程状态固定；替换、删除、重传不修改已有成功事件。错误 mapping 造成的首次成功不能通过重新上传纠正。失败或未处理事件可在实际来源变化后重试。Jank 在 ZIP 上传时使用固定文件解析，已存事件、重复事件不回算。无 mapping 仍可保存未解混淆 Jank，注册表故障按可重试错误处理。

旧无版本登记保留在列表并明确提示“不匹配事件”，不能充当版本默认文件；需要指定版本重新上传建立新身份。旧身份和成功来源不变，旧记录可条件删除。

## SO 管理

Native 详情的模块入口只预填应用版本及可取得的 ABI、完整 ELF Build ID，不携带应用 buildId。身份未知时进入通用版本 SO 管理，不根据模块名声称匹配。页面只允许管理员上传 ZIP，SO 表单没有应用构建输入。

ZIP 可以包含多 ABI、多模块，每个 SO 必须具有完整 GNU Build ID 及函数符号或调试信息。服务端以实际 ELF 内容识别，不按归档目录推断 ABI。已知目标模块必须包含在 ZIP 中，否则整包拒绝。完整归档、单文件、实际解压和接收预算见 API 文档。

存在不同内容时，页面显示整批模块、新旧 SHA-256 及新建/替换动作，确认包括“预期不存在”项；任一身份变化均拒绝整批，不能只确认覆盖项。成功只表示 SO 文件已保存，本期未提供 Native 还原，不会改变 Native 原始现场或 JVM 工作。

## 失败、重试与删除

收到 `503 SYMBOL_STORE_UNAVAILABLE` 时，包括正文接收后校验超时、中断或磁盘读取故障，应遵守 `Retry-After` 等待后重传原文件；这类错误不代表文件损坏。422 内容错误或 413 超限应修正文件后再上传。

网络或提交确认未知时，保留原文件，按相同版本和登记身份执行普通重传对账。SO 应重传原 ZIP且不带过期确认快照；相同内容幂等，不增加修订或审计。409 后重新获取当前快照并确认，不能自动覆盖。

删除必须确认当前文件修订号。删除不移除历史成功结果；重新上传建立新 symbolId，旧请求不能删除新身份。应用、事件、类型切换或离页会取消请求并丢弃旧结果和冲突材料。普通只读成员可查看元数据，无上传、覆盖和删除权限。
