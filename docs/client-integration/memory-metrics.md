# Android 运行期内存峰值上传接入

正式字段与错误见[内存指标API](../api/memory-metrics-api.md)。Performance配套实现、采样频率实验及用户指定Pixel_6模拟器联合J1..J7已通过，证据只维护于[统一验收](../validation/memory-runtime-peaks/README.md)；本地现有服务和云端尚未部署此次变更。

## 运行边界与采集

主进程使用共享sessionId/processId标识一轮，SDK有效采集期间分别累计PSS、VSS、Java堆最大值。前后台变化、Activity重建及同进程SDK重建不分轮；不能把关闭期间或两次采样间的瞬时尖峰视为已覆盖。每项保留首次达到最大值时的时间、前后台和Activity，读取失败保留旧值，真实0有效。

## 快照与下次启动补报

运行中后台原子保存完整current快照，新高及时保存，并周期保存最新有效观测截止；不追加普通样本明细，不等退出回调。快照包含固定eventId和原版本/buildId/身份等元数据。突然被杀只保证成功持久化部分。

下一次新进程启动先可靠封存上一轮到events，再建立本轮；同进程恢复继续原轮。封存失败保留旧有效快照，不先覆盖。所有flush/网络恢复只发送已封存历史任务，不能发送当前轮。

## 确认、过期和安全

使用v2批量入口与memory_peak_summary/memoryPeakSummary；occurredAt等于原lastSampledAt，不能改成上传时间。严格检查HTTP200、requestId、计数和错误定位，accepted/duplicate才删除对应历史任务。可重试失败保留原内容并退避，永久错误/次数耗尽隔离。升级后的上传仍保留旧版本与旧身份。

峰值历史默认90天，以原lastSampledAt判断，封存/重试不续期；恰好90天及更早不上传。服务端窗口独立配置，客户端自定义TTL不自动放宽服务端限制。配额/尝试上限、清数据和卸载均可能造成无法补报；活动current不能被普通历史清理删除。旧memory_sample任务隔离，不伪造成完整运行峰值。

默认采样频率为前台10秒、后台30秒；完整采集/比较/可靠写盘与八段各10分钟候选实验见[客户端测试页](../../android/docs/knowledge-base/11-构建测试与本地发布.md#运行期内存峰值验证)。模拟器结果不证明真机功耗、绘制帧因果或瞬时尖峰全覆盖。App Key只经本地配置注入，不进入样例或日志。字段示例、查询时间与统计口径统一引用API，不在此重复维护。
