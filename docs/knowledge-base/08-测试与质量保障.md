# 测试与质量保障

## 测试分层

| 层次 | 工具 | 重点 |
|---|---|---|
| 单元测试 | JUnit 5 | 校验、脱敏、转换、指纹和权限判断 |
| 存储资源检查 | JUnit 5 + SQL/JSON 文本检查 | ClickHouse 脚本对象、排序键和 Dashboard 资源结构 |
| 接口测试 | Spring Boot Test + MockMvc | 状态码、项目 Key、开发期请求头、错误响应和 gzip |
| 数据库集成 | 待补充 Testcontainers 或固定 ClickHouse 环境 | 当前未自动启动 PostgreSQL/ClickHouse 容器 |
| 性能测试 | k6 或 Gatling | 上报吞吐、p95 延迟、写入与查询性能 |
| Dashboard 检查 | 固定数据 + 截图检查 | 分位数、筛选、粒度、无数据状态 |

## 必测场景

### 上报与协议

- 同一批次重复上报。
- 连接中断后的重复重试。
- gzip 内容损坏。
- 请求体或解压后内容过大。
- 必填字段缺失、字段类型非法、未知 Schema。
- 事件时间非法或客户端时钟明显偏差。
- 部分事件合法、部分事件非法时的响应计数。

### 存储与查询

- ClickHouse 暂时不可用、写入超时和恢复后的重试。
- 查询时间范围过大、返回行数过多和超时。
- 高基数设备、URL 和页面字段。
- p50、p95、p99 与固定样本的人工结果一致。
- 原始事件与聚合结果能够对应。
- Android 不同时区的数据在统一时间轴正确展示。

### 安全与隔离

- 无效、停用和轮换后的上报 Key。
- 不同项目间的数据隔离。
- 无权限用户枚举 `projectId`。
- 跨项目访问事件详情、制品和 Dashboard。
- 敏感字段被拒绝、移除或哈希，且不会写入日志。

## 阶段验收原则

- 使用固定且可重复的数据集验证统计口径。
- 验收记录必须包含执行命令、测试环境和结果。
- PostgreSQL 或 ClickHouse 集成测试应说明容器和初始化方式。
- Dashboard 需验证正常、无数据、错误和大时间范围等状态。
- 构建配置或依赖发生变化时运行完整 `./gradlew.bat clean build`；其他提交前至少运行 `./gradlew.bat test`。

## 数据质量指标

平台自身至少监控：

- 接收批次数、事件数、接受数和拒绝数。
- 各 SDK 版本与 Schema 版本分布。
- 事件发生时间到接收时间的延迟。
- 接收成功到 ClickHouse 可查询的延迟。
- 无效字段、超大批次和未知 Schema 的比例。
- 重复 `eventId` 的抽样比例。
- Crash 分母不足次数、上报可见延迟和存储临时失败次数。

## JVM Crash 验收

仓库已经加入固定数据集、协议校验、脱敏、指纹、重复上报、临时存储故障、项目隔离、分母不足、MockMvc gzip 联调和 Grafana JSON 结构检查。当前测试源码不依赖 Testcontainers，固定数据集主要在内存仓库中验证；`ClickHouseSchemaTests` 检查 SQL 资源内容，不等同于真实 ClickHouse 执行验证。固定数据集期望值见 [Crash 固定验收数据集](../crash-fixed-dataset.md)。

截至 2026-08-18，使用仓库内 `.gradle-local` 的 Gradle 9.5.1 分发运行 `./gradlew.bat test` 已通过（15 个测试）。真实 ClickHouse 容器和 Grafana 截图属于外部环境验收：截图材料已覆盖正常、无数据、分母不足和堆栈下钻，但尚未替代大规模查询、故障恢复和生产权限验收。
