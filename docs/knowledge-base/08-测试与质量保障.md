# 测试与质量保障

## 测试分层

| 层次 | 工具 | 重点 |
|---|---|---|
| 单元测试 | JUnit 5 | 校验、脱敏、转换、指纹和权限判断 |
| 存储资源检查 | JUnit 5 + SQL/JSON 文本检查 | ClickHouse 脚本对象、排序键和 Dashboard 资源结构 |
| 接口测试 | Spring Boot Test + MockMvc | 登录、CSRF、Session 失效、应用列表/创建/修改、角色授权、Crash/卡顿/指标查询和上报错误响应 |
| 数据库集成 | PostgreSQL Testcontainers + Flyway + JPA validate | Docker 可用时执行管理 schema 建表、约束和 JPA schema 校验；Docker 不可用时明确跳过 |
| 性能测试 | k6 或 Gatling | 上报吞吐、p95 延迟、写入与查询性能 |
| 前端测试 | 见[前端测试与质量保障](../../frontend/docs/knowledge-base/06-测试与质量保障.md) | 根知识库只保留端到端接口、权限和部署验收边界 |
| Dashboard 检查 | 固定数据 + 截图检查 | 分位数、筛选、粒度、无数据状态 |

## 必测场景

### 上报与协议

- 同一批次重复上报。
- 连接中断后的重复重试。
- gzip 内容损坏。
- 请求体或解压后内容过大。
- 必填字段缺失、字段类型非法、未知 Schema。
- 事件时间非法或客户端时钟明显偏差。
- 部分事件合法、部分事件非法时的响应计数。
- 三类卡顿载荷的算法版本、静止场景零刷新帧和挂起有效分母。

### 存储与查询

- ClickHouse 暂时不可用、写入超时和恢复后的重试。
- 查询时间范围过大、返回行数过多和超时。
- 高基数设备、URL 和页面字段。
- p50、p95、p99 与固定样本的人工结果一致。
- 原始事件与聚合结果能够对应。
- Android 不同时区的数据在统一时间轴正确展示。
- FPS 按算法版本隔离、UTC 小时/天分桶且分位数方向正确；挂起率按 UTC 设备日二阶段合并并只按天返回趋势。

### 安全与隔离

- 缺失、格式错误、未知的上报 Key，以及鉴权存储不可用和应用包名不匹配。
- 不存在、停用和密码错误的网页登录统一错误语义。
- 登录、退出、应用创建和应用修改缺少 CSRF Token 时被拒绝。
- Session 恢复、退出失效、成员角色读取/修改矩阵。
- 不同应用间的数据隔离。
- 无权限用户枚举 `appId`。
- 跨应用访问事件详情、制品和 Dashboard。
- 敏感字段被拒绝、移除或哈希，且不会写入日志。
- 压缩前/解压后请求限制、单事件大小、堆栈规模、场景长度和非法动态值脱敏。

## 阶段验收原则

- 使用固定且可重复的数据集验证统计口径。
- 验收记录必须包含执行命令、测试环境和结果。
- PostgreSQL 或 ClickHouse 集成测试应说明容器和初始化方式。
- Dashboard 需验证正常、无数据、错误和大时间范围等状态。
- Crash 与卡顿前端的页面状态、组件和构建验收由[前端测试与质量保障](../../frontend/docs/knowledge-base/06-测试与质量保障.md)维护；平台验收仍需覆盖真实 API、数据源、权限和生产代理链路。
- 构建配置或依赖发生变化时运行完整 `./gradlew.bat clean build`；其他提交前至少运行 `./gradlew.bat test`。

## 数据质量指标

平台自身至少监控：

- 接收批次数、事件数、接受数和拒绝数。
- 各 SDK 版本与 Schema 版本分布。
- 事件发生时间到接收时间的延迟。
- 接收成功到 ClickHouse 可查询的延迟。
- 无效字段、超大批次和未知 Schema 的比例。
- 重复 `eventId` 的抽样比例。
- Crash 分母不足次数、上报可见延迟和存储临时失败次数。
- 卡顿接收/接受/拒绝/重复数、Schema 与算法版本分布、事实/详情不一致数和卡顿可见延迟。
