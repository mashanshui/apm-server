# 测试与质量保障

本页维护跨端验收方法和证据入口。后端、前端的执行命令、条件专项与最近完整自动化基线分别由[后端测试](../../backend/docs/knowledge-base/06-测试与质量保障.md)和[前端测试](../../frontend/docs/knowledge-base/06-测试与质量保障.md)维护；环境状态见[当前边界](00-当前实现与验证边界.md)。

## 测试分层

| 层次 | 验收边界与入口 |
|---|---|
| 后端自动化 | [后端测试](../../backend/docs/knowledge-base/06-测试与质量保障.md)维护 JUnit、MockMvc、ArchUnit、资源与数据库测试 |
| 前端自动化 | [前端测试](../../frontend/docs/knowledge-base/06-测试与质量保障.md)维护页面、状态、类型检查与构建 |
| 跨端联调 | 真实 HTTP、Session、应用权限、上报确认和前端代理链路 |
| 性能测试 | k6 或 Gatling；上报吞吐、p95 延迟、写入与查询性能，JVM 专项基线不能代替生产容量 |
| Dashboard 检查 | 固定数据与截图；分位数、筛选、粒度、无数据状态 |

## 必测场景

### 上报与协议

- 同一批次重复上报。
- 连接中断后的重复重试。
- gzip 内容损坏。
- 请求体或解压后内容过大。
- 必填字段缺失、字段类型非法、未知 Schema。
- 事件时间非法或客户端时钟明显偏差。
- 部分事件合法、部分事件非法时的响应计数。
- 三类卡顿载荷的算法版本、静止场景零刷新帧和挂起有效分母。
- 内存 `memory_sample` 的 PSS/VSS/Java 堆整数范围、合法零值、缺失值、重复 eventId、混合批次和部分接受。

### 存储与查询

- ClickHouse 暂时不可用、写入超时和恢复后的重试。
- 查询时间范围过大、返回行数过多和超时。
- 高基数设备、URL 和页面字段。
- p50、p95、p99 与固定样本的人工结果一致。
- 原始事件与聚合结果能够对应。
- Android 不同时区的数据在统一时间轴正确展示。
- FPS 按算法版本隔离、UTC 小时/天分桶且分位数方向正确；挂起率按 UTC 设备日二阶段合并并只按天返回趋势。
- 内存概览和趋势按采样时间 UTC 小时/日分桶，三项指标独立排除缺失值，空桶返回 null；固定数据集期望见[内存固定验收数据集](../datasets/memory-fixed-dataset.md)。
- 符号表按 `appId + buildId` 隔离，重复字节幂等、不同摘要要求管理员确认替换，Crash 每次详情实时 Retrace 且不落库，卡顿替换只影响后续上传；真实 R8、旧版本租约与当前版本替换已有自动化/有限外部证据；仍需生产数据库并发与故障恢复验收。

### 安全与隔离

- 缺失、格式错误、未知的上报 Key，以及鉴权存储不可用和应用包名不匹配。
- 不存在、停用和密码错误的网页登录统一错误语义。
- 登录、退出、应用创建和应用修改缺少 CSRF Token 时被拒绝。
- Session 恢复、退出失效、成员角色读取/修改矩阵。
- 不同应用间的数据隔离。
- 无权限用户枚举 `appId`。
- 跨应用访问事件详情、制品和 Dashboard。
- 敏感字段被拒绝、移除或哈希，且不会写入日志。
- 压缩前/解压后请求限制、单事件大小、堆栈规模、场景长度和非法动态值脱敏。

## 阶段验收原则

- 使用固定且可重复的数据集验证统计口径。
- 验收记录必须包含执行命令、测试环境和结果。
- PostgreSQL 或 ClickHouse 集成测试应说明容器和初始化方式。
- Dashboard 需验证正常、无数据、错误和大时间范围等状态。
- Crash 与卡顿前端的页面状态、组件和构建验收由[前端测试与质量保障](../../frontend/docs/knowledge-base/06-测试与质量保障.md)维护；平台验收仍需覆盖真实 API、数据源、权限和生产代理链路。
- 构建配置或依赖发生变化时运行完整 `./backend/gradlew.bat -p backend clean build`；其他提交前至少运行 `./backend/gradlew.bat -p backend test`。

## 数据质量指标

平台自身至少监控：

- 接收批次数、事件数、接受数和拒绝数。
- 各 SDK 版本与 Schema 版本分布。
- 事件发生时间到接收时间的延迟。
- 接收成功到 ClickHouse 可查询的延迟。
- 无效字段、超大批次和未知 Schema 的比例。
- 重复 `eventId` 的抽样比例。
- Crash 分母不足次数、上报可见延迟和存储临时失败次数。
- 卡顿接收/接受/拒绝/重复数、Schema 与算法版本分布、事实/详情不一致数和卡顿可见延迟。
- 内存接收/接受/拒绝/重复数、指标缺失比例、采样延迟和存储临时失败次数。

## 浏览器与外部环境的独立边界

模拟 API 页面检查可证明布局、异常提示和交互，不证明正式后端、数据库或成员授权。真实 HTTP 又不能替代浏览器视觉和权限矩阵。前端[测试页](../../frontend/docs/knowledge-base/06-测试与质量保障.md)分别列出这两类证据。

验收数据应使用独立测试应用或 Testcontainers，不向正式资源写入固定夹具。运行共享脚本前核对目标连接、schema 和数据范围；ClickHouse 004 初始化需要空表，不能为复验默认清空已有业务。重复、失败和条件跳过如实记录，不用后续成功抹去未解决问题，也不把已解决的旧失败继续写成当前阻塞。
