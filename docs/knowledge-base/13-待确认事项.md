# 待确认事项

## Crash 存储与查询

- 当前 DDL 的原始 Crash TTL 为 30 天、聚合 TTL 为 365 天，需要结合事件量、堆栈体积和预算确定最终值。
- ClickHouse JSONEachRow 适配器的写入批大小、请求超时、重试退避和副本策略需要压测确认。
- Crash 查询已在 ClickHouse 内过滤、去重、聚合及分页，小时预聚合表尚未接入；现有合成基线中百万事件宽窗口被资源预算拒绝，仍需生产负载决定预算、预聚合和表设计。
- Grafana 实际部署必须确认 ClickHouse 插件版本、只读账号、应用级数据隔离和截图验收环境。
- 网页应用授权已切换为 Spring Security Session + PostgreSQL `app_member`；仍需在生产同源网关、HTTPS 和多租户运营环境完成外部安全验收。
- Android SDK 文件队列的最大磁盘占用、崩溃 Handler 同步落盘耗时和设备断电丢失边界需要真机验证。
- App Key 已改为创建应用时随机生成并永久有效，不再有全局开发默认值；生产发布前仍须确认 `APM_APP_KEY_ENCRYPTION_KEY` 的密钥服务注入、备份和恢复演练，以及设备哈希盐和 ClickHouse 密码的托管方式。
- ClickHouse 原始表与 Crash 明细表分开写入，跨表部分失败后的补偿和一致性需要故障演练。

## 卡顿协议与性能

- 当前 `004_application_identity_schema.sql` 中卡顿事实、采样详情、Issue 聚合、FPS 和挂起对象的生产 TTL、分区及磁盘预算需要结合真实事件量确认。
- `jank-v1` 指纹、`jank-artifact-v2` 证据、`fps-v1`、`suspension-v1` 的兼容窗口、升级/回放策略和跨算法版本是否允许对比，需要在生产灰度前冻结。
- ClickHouse 卡顿查询当前保留应用、时间、limit、timeoutMs 和白名单维度约束；当前 004 应用结构已有 2026-09-01 固定集和 2026-09-24 脚本复验，仍不能外推到大时间范围和生产并发的 p95/p99。
- 卡顿完整统计已有十万事件顺序查询证据；精确 groupArray 分位数仍消耗数据库内存，生产分布/并发和预算调整需要独立压测，见[资源证据](../../backend/docs/knowledge-base/backend-api-query-validation.md)。
- 事实表写入成功而卡顿详情写入失败时的补偿、告警阈值和可见延迟，需要在真实 ClickHouse 故障演练中确认。
- FPS 与设备日挂起率查询的分位数方向、重复区间合并和 `denominator_insufficient` 响应已在 JVM/内存和真实 ClickHouse 固定数据集路径验证；仍需确认大时间范围/并发下的 `FINAL` 合并开销、告警阈值和故障演练结果。

## 二进制堆栈解析

- 本地 Maven Local 和云端测试已确认 `rhea-trace-processor:1.0.2` 支持 manifest v3 UUID v4 `processId` 及主线程-only ZIP；正式构建应使用哪个受控制品仓库、版本发布和回滚流程仍待确认。
- mapping 生产持久卷的备份、保留期限、删除审批和跨环境同步流程尚未确定；首版已实现网页上传、当前版本审计替换和启动孤立文件清理，不提供下载/删除或构建自动上传。
- 需要用代表性真机产物确认压缩大小、解压大小、同步解析 p95/p99、单实例并发、JVM 堆、CPU 和临时磁盘目标，并据此确定 `APM_STACK_PARSER_MAX_ARTIFACT_BYTES` 与 `APM_STACK_PARSER_MAX_CONCURRENT_PARSES` 的生产值。
- 当前没有专用解析耗时、失败原因、繁忙拒绝和临时目录容量指标；指标名、告警阈值和 Dashboard 归属需要在生产灰度前确定。
- 需要确定从同步原始正文切换到预签名对象存储与异步解析的触发阈值，以及 ZIP/报告是否持久化、保留多久、由谁授权读取。
- 符号表列表目前按应用查出全部元数据后在 Java 筛选与分页，默认 50/最大 200 只限制响应页；构建数增长时需改为数据库过滤分页并验证索引。文件租约和退休计数只在单实例内有效，多实例共享卷的替换/清理协调尚未实现。

## 隐私处理与架构门禁

- Crash、卡顿和内存采样的设备哈希使用统一部署级盐，未包含 `appId`；内存异常报告直接保存 metadata 设备标识和受限 report。需确认是否按应用派生盐及报告脱敏范围，并按各信号实际处理同步隐私验收；现有长度/格式校验不代表完整脱敏。
- `attributes` 目前只检查键格式与数量，业务属性名白名单尚未实现；目标要求与当前实现应分别记录。
- `ArchitectureBaselineTests` 尚无依赖环断言；分层规则仍匹配旧 `service/repository` 包且允许空包，没有直接检查新 `internal.application/internal.persistence`。是否增加对应门禁和如何定义允许依赖仍需明确。
