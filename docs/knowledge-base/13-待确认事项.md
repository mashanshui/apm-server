# 待确认事项

## JVM Crash 新增待确认项

- 原始 Crash TTL 示例为 30 天、聚合 TTL 示例为 365 天，需要结合事件量、堆栈体积和预算确定最终值。
- ClickHouse JSONEachRow 适配器的写入批大小、请求超时、重试退避和副本策略需要压测确认。
- 当前查询服务读取原始事件并在 JVM 内计算，小时聚合表尚未接入；需要用容量数据决定聚合查询适配器和切换条件。
- Grafana 实际部署必须确认 ClickHouse 插件版本、只读账号、项目级数据隔离和截图验收环境。
- 开发期项目请求头必须在生产前替换为正式登录、Session/OIDC 和项目成员权限。
- Android SDK 文件队列的最大磁盘占用、崩溃 Handler 同步落盘耗时和设备断电丢失边界需要真机验证。
- `application.properties` 中的本地 fallback 凭据和盐值必须在生产发布前清理，确认只通过环境变量或密钥服务注入。
- ClickHouse 原始表与 Crash 明细表分开写入，跨表部分失败后的补偿和一致性需要故障演练。

以下事项不改变总体方向，但会直接影响协议、表结构、分区、容量、成本和可靠性。正式建表与压测前应给出答案并记录负责人、结论和日期。
