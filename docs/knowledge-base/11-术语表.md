# 术语表

| 术语 | 含义 |
|---|---|
| APM | Application Performance Monitoring，应用性能监测；本项目主要观察 Android 客户端性能。 |
| ANR | Application Not Responding，Android 应用无响应。 |
| App 冷/温/热启动 | 按进程与组件复用程度区分的启动类型，必须在 SDK 协议中明确判定口径。 |
| p50/p90/p95/p99 | 分位数。例如 p95 表示 95% 的样本不高于该值，比平均值更能体现长尾性能。 |
| TTFB | Time To First Byte，从请求开始到收到首字节的耗时。 |
| 事件信封 | 所有事件共享的外层字段集合，包括 Schema、事件 ID、时间、版本、设备环境等。 |
| `eventId` | 事件的全局唯一标识，用于重试场景中的重复识别和详情定位。 |
| `schemaVersion` | 事件结构版本，用于 SDK 与服务端的兼容演进。 |
| `buildId` | 构建标识，用于把事件与版本、mapping 或符号表关联。 |
| 原始事件 | SDK 上报后保留的明细记录，用于下钻和排障。 |
| 聚合数据 | 按时间和维度预计算的计数、分位数、错误率等结果，用于快速 Dashboard 查询。 |
| 高基数 | 某维度有大量不同值，如设备 ID、原始 URL；会显著影响存储与查询设计。 |
| TTL | Time To Live，数据到期后的自动保留/删除策略。 |
| 至少一次 | 数据可能因重试被传递多次，但目标是避免无声丢失；消费者需要容忍重复。 |
| 指数退避 | 重试间隔随失败次数增长，通常加入随机抖动以避免同时重试。 |
| 随机抖动 | 在重试等待时间中加入随机量，减少大量客户端同时请求形成的尖峰。 |
| 模块化单体 | 本项目指 Java 业务在单个 Spring Boot 进程内按领域划分模块；数据库、Web 和 TypeScript MCP 仍为独立容器。 |
| 下钻 | 从汇总趋势或排行进入具体原始样本。 |
| 数据质量 Dashboard | 观察延迟、拒绝、Schema、SDK 版本和断流等采集链路质量的看板。 |
| OTLP | OpenTelemetry Protocol，用于传输指标、日志和 Trace；本项目计划后期兼容。 |
| R8 mapping | Android 混淆映射文件，用于把混淆堆栈恢复为可读符号。 |
| 行级策略 | 在数据库层按行限制用户可见数据，可用于多租户隔离。 |
| JVM Crash | Java/Kotlin 虚拟机层面的致命崩溃；当前首期 `crash.kind=jvm` 且 `crash.fatal=true`。 |
| Crash 指纹 | 服务端根据应用、异常类型、规范化消息和堆栈生成的稳定问题标识；当前版本为 `v1`。 |
| `denominator_insufficient` | 查询范围内没有有效 `app_start` 会话分母，Crash 比率应返回空值而不是零。 |
| `raw_only` | Crash 尚未经过 mapping 符号化的状态；当前详情仍可查看脱敏后的原始异常链和堆栈。 |
| 部分接受 | 一个批次中合法事件入库、非法事件逐条返回错误；当前服务以 HTTP 200 返回批次统计。 |
| `APM_STORAGE_MODE` | 存储实现切换配置；`clickhouse` 使用 HTTP 持久化仓库，`memory` 用于测试和临时联调。 |
| 物化视图 | ClickHouse 根据原始事件自动写入聚合表的对象；当前 Crash SQL 已提供，但后端查询尚未使用聚合表。 |
| Crash 前端 | 位于 `frontend/` 的独立 Web 工程，详细内容见[前端知识库](../../frontend/docs/knowledge-base/README.md)。 |
| Vite 代理 | 本地开发时把浏览器 `/api` 请求转发到 Spring Boot 的能力；生产环境需由同源网关或 Web 服务器替代。 |
| 数据源标识 | 查询响应中的 `dataSource` 字段；页面将 `clickhouse` 显示为 ClickHouse，将 `memory` 显示为内存联调。 |
| 卡顿个例（`jank`） | 一次超过阈值的主线程消息，包含精确消息耗时和相对单调时钟采样证据。 |
| `jank-v1` | 服务端卡顿 Issue 指纹算法版本；从规范化关键应用调用路径生成，忽略行号、地址、数字动态值和采样次数。 |
| `jank-artifact-v2` | 服务端把 manifest v3 `.rheajank.zip` 归一化为卡顿事实、采样时间片和调用树的算法标识；它是证据算法版本，不是 manifest 版本。 |
| `parsedSampleCount` | `processId` 对应目标主线程中已解析且堆栈非空的有效 segment 数。 |
| `missingSampleCount` | 理论采样槽位与 parsed 的非负差；不是客户端确认的丢弃次数。 |
| 采样时间片 | 由相邻采样偏移和采样间隔推导的相对消息区间；只表示覆盖证据，不等同于精确方法执行时间。 |
| 覆盖/未覆盖时间 | 采样调用树能够解释的区间与样本间空洞区间；未覆盖区间不得被样本数量或消息总时长填充。 |
| 精确消息耗时 | 客户端测得的主线程消息起止耗时，字段为 `exactMessageDurationNs`；与采样估算字段分开。 |
| 估算堆栈耗时 | 依据采样时间片聚合的调用树耗时，字段带 `estimated` 前缀；不能称为 CPU 自耗时。 |
| 场景帧汇总 | `frame_scene_summary` 事件，按场景提交 UI 刷新帧数、活跃时长和 FPS 统计；静止场景的零刷新记录被拒绝。 |
| 前台挂起汇总 | `foreground_suspension_summary` 事件，记录前台时长、超过阈值的累计挂起时长和次数；服务端按匿名设备和 UTC 日期先合并，再计算设备日秒/小时挂起率。 |
| `memory_sample` | 一次进程级内存采样事件；`pssBytes`、`vssBytes` 和 `javaHeapUsedBytes` 使用原始字节整数，缺失值不参与对应指标统计。 |
| PSS | Proportional Set Size，按共享页比例分摊后的进程物理内存占用。 |
| VSS | Virtual Set Size，进程虚拟地址空间大小；不等同于实际物理驻留。 |
| Java 堆已使用量 | 客户端按 `Runtime.totalMemory() - Runtime.freeMemory()` 计算的已使用 Java 堆字节数。 |
| `appId` | 服务端生成的 UUID v4 应用隔离标识；Android 上报不直接提交，由 App Key 映射得到。 |
| `packageName` | 创建应用时绑定的全平台唯一、小写 Android application ID，不可修改。 |
| `appKey` | 服务端为应用生成的永久上报凭据；生成后不可轮换、撤销或过期。 |
| 查询 Token | 单应用 `apm:read` 的 Bearer 凭据，有效期 30/90/365 天，可撤销，完整值仅创建时展示；不能替代 App Key 或网页 Session。 |
| Agent HTTP / MCP | 已实现的 19 个只读 GET 入口及对应 TypeScript MCP 工具；Java 负责鉴权与业务查询，MCP 不直连数据库。 |
| `X-App-Key` | 携带 `appKey` 的上报请求头；映射唯一 `appId + packageName`，不是页面中的 `appId`。 |
| `JSON v2` | 公共事件协议版本；事件必须携带 `schemaVersion=2` 和 `packageName`。 |
| `manifest v3` | 卡顿 ZIP manifest 版本；必须携带 `schemaVersion=3` 和 `packageName`，不接受旧 `appId`。 |
