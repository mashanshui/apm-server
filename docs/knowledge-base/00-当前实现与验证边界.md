# 当前实现与验证边界

本文是知识库的状态入口，用于回答“仓库现在已经有什么、验证到哪一层、还有哪些能力不能对外承诺”。长期设计、协议细节和决策理由仍由各主题页维护。

当前实现基线：2026-09-15。

## 状态口径

| 标记 | 含义 |
|---|---|
| 已实现 | 仓库中存在对应代码、配置或资源，但不自动代表真实外部环境已验证 |
| 自动化已验证 | 已由后端或前端自动化测试覆盖；后端命令、数量和日期见[后端测试](../../backend/docs/knowledge-base/06-测试与质量保障.md)，跨端结果见[平台测试](08-测试与质量保障.md) |
| 外部环境已冒烟 | 已连接本地 PostgreSQL、ClickHouse 或浏览器环境完成有限规模验证，不能外推到生产容量和可用性 |
| 目标能力 | 技术方案或路线图中的目标，当前代码尚未完整实现 |
| 待确认 | 需要容量、业务、安全或运维决策，统一记录在[待确认事项](13-待确认事项.md) |

- 开放注册、OIDC、成员邀请/角色编辑、Key 轮换/撤销/过期和应用删除；构建后自动上传、历史事件回写、mapping 下载/删除、原生 SO 与 HPROF 符号化也不在首版。

- 移动端页面适配；当前前端设计基线仅覆盖宽度不小于 1280 像素的 PC。
- HPROF 解析、内存详情页、附件下载、retained size/泄漏字节推导和 Android 内存异常报告 SDK 队列尚未实现；当前只保存可选 HPROF 并展示 SDK 报告中的问题与引用链。

## 应用身份与 App Key 边界（2026-09-01）

创建应用时用户填写可选的 `name`、`description` 和唯一、不可变的小写 `packageName`，其中只有包名必填。服务端在一个事务中生成 UUID v4 `appId`、Owner 成员关系和永久 `appKey`；名称为空时默认等于包名，描述为空时保存为空，名称和描述之后可由 `OWNER`/`ADMIN` 修改。`appId` 是系统公开隔离标识，`packageName` 是 Android application ID，`appKey` 只用于上报鉴权，三者不互换。

PostgreSQL 只保存 App Key 的 SHA-256 摘要、AES-256-GCM 密文和 12 字节 nonce；`OWNER`/`ADMIN` 可通过独立禁止缓存接口随时查看同一完整 Key。JSON v2 和 manifest v3 在进入业务写入前校验 `packageName` 与 Key 绑定值，错误包名返回整请求 `403 PACKAGE_NAME_MISMATCH`。本期不实现旧项目迁移、Key 轮换/撤销/过期、应用删除或鉴权缓存。

历史验收数据清理时仅处理已确认的测试业务数据，不删除数据库卷、账号或未知数据；本次云端进程身份验收数据保留在受控应用中用于追溯。后端和前端自动化结果、真实数据库与浏览器外部验收结果统一以[测试与质量保障](08-测试与质量保障.md)为准；processor `1.0.1` 的数值 PID 失败记录仅是历史边界，当前 `1.0.2` 的客户端实际设备 ZIP 已完成本机解析和云端 HTTP/落库验收；完整 Android SDK 生命周期、生产制品仓库和生产容量仍不能由本地 HTTP 冒烟替代。
