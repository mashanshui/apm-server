# 产品目标与范围

本页描述产品目标和范围演进；仓库当前能力与验证层级统一见[当前实现与验证边界](00-当前实现与验证边界.md)。

## 背景

Android 端已经具备性能数据采集能力，平台下一步需要补齐数据上传、服务端处理、存储、聚合分析、Dashboard 展示和告警。当前团队更熟悉 Java/Kotlin，因此第一版强调低学习成本和端到端可验证。

## 建设目标

平台需要做到：

1. 弱网环境下可靠上传 Android 性能事件。
2. 在服务端完成应用识别、协议校验、脱敏、标准化和存储。
3. 支持按时间、版本、渠道、设备、系统、页面和接口等维度查询。
4. 提供 p50、p90、p95、p99 等分位数。
5. 识别版本退化、慢设备、慢页面和慢接口。
6. 对异常指标进行告警。
7. 为后续多租户和产品化演进保留边界。

## 第一版范围

### App 启动

- 冷启动、温启动、热启动。
- 总耗时以及 Application、Activity、首帧等阶段耗时。
- 版本、设备和 Android 系统分布。

### 网络性能

- 总耗时，以及 DNS、连接、TLS、TTFB、下载耗时。
- 请求方法、状态码、错误类型和请求/响应字节数。
- 标准化后的域名和接口路径。

### 卡顿或 ANR

- 卡顿次数、卡顿率、帧耗时分布。
- 页面、堆栈、受影响设备数。
- App 版本和 Android 系统版本分布。

除本页后续单独说明的 JVM Crash 子范围外，内存、CPU、耗电和完整 Trace 不属于第一条闭环的必要范围，应在上报、存储和分析链路稳定后增加。NDK/native Crash、非致命异常和 ANR 仍不在当前 Crash 首期范围。

## Dashboard 必须回答的问题

- 某版本冷启动的 p50、p90、p95、p99 是多少？
- 新版本相对旧版本是否退化？
- 哪些设备、系统、渠道、页面或接口最慢？
- 哪些接口错误率最高？
- 慢样本发生时的设备、会话、网络和阶段耗时是什么？
- 问题影响了多少用户或设备？
- 最近是否出现异常突增或数据中断？

## 最小可用闭环

```text
创建应用（填写可选名称/描述与唯一 packageName）→ 获取永久 App Key → Android 批量上报 → 服务端校验与脱敏
→ ClickHouse 入库 → Grafana 展示 p95 趋势 → 下钻慢样本 → 阈值告警
```

## 原始第一版范围控制

- 微服务拆分。
- Kubernetes 编排。
- Kafka 消息总线。
- Redis 基础设施。
- 自研 Vue Dashboard（原始计划；当前 Crash 与卡顿 PC 控制台已经落地）。

这一列表记录原方案的首期取舍，不代表当前仓库仍停留在该阶段。范围演进和扩展触发条件见[实施路线图](09-实施路线图.md)。

## 当前已落地子范围

当前已把 Java/Kotlin JVM 致命 Crash 与服务端卡顿监控纳入可运行闭环：客户端使用 `app_start` 去重会话作为 Crash 分母，服务端提供 Crash 查询、卡顿个例总览/趋势/Issue/详情，以及 FPS、设备日挂起率和白名单多维查询。当前服务端已接受 `app_start`、JVM fatal Crash、卡顿个例、场景帧汇总和前台挂起汇总；NDK/native、非致命异常、完整 ANR 采集、Issue 生命周期和完整产品管理能力仍未落地。

当前仓库已经实现 Spring Boot 接收 API、JSON/JSON+gzip 指标批次、事件校验、脱敏、服务端指纹、部分接受、`appId + eventId` 去重、内存仓库和 ClickHouse HTTP 适配器；公共 JSON 使用 v2 `packageName`，卡顿个例入口只接受 v3 manifest 边界。卡顿解析可按认证应用和 `buildId` 使用运维预置的 ProGuard/R8 mapping；processor 1.0.1 已使用用户提供的真实 v3 ZIP 完成解析、字节和报告关键字段验证，本地真实服务也已完成 HTTP 首次/重复、mapping、错误 Key/包名、v2 拒绝和重启验证。服务端不保存原始 ZIP，也不向客户端返回完整解析报告。默认事件存储使用 ClickHouse，测试或无外部依赖联调时可显式切换到 `APM_STORAGE_MODE=memory`。

这意味着当前交付是“协议到查询下钻 + 网页应用工作区”的开发闭环，不是完整 APM 产品：当前已实现 PostgreSQL 管理数据、邮箱密码登录、Session/CSRF、输入唯一包名后生成 UUID `appId` 和永久 App Key、成员关系授权、浅色 PC 控制台和运维预置 mapping 的同步堆栈解析；仍未实现开放注册、OIDC、成员邀请/角色编辑、Key 轮换/撤销、mapping 上传/注册中心、应用删除、Nginx/HTTPS 生产部署、客户端生产级文件队列、Protobuf、限流、告警规则和容量压测。

网页登录与应用管理接口、首次管理员配置和本地 PostgreSQL 步骤见[应用管理 API](../api/app-api.md)。

卡顿服务端协议、Schema、固定数据集、接收错误和查询接口见[卡顿监控服务端 API](../api/jank-server-api.md)。Android/btrace 生产采集端和移动端 UI 仍未实现；桌面端卡顿 Dashboard 页面已经落地，详见[前端知识库](../../frontend/docs/knowledge-base/README.md)。

btrace `.rheajank.zip` 的原始请求体、mapping、幂等落库和错误契约见[卡顿压缩包解析与落库 API](../api/stack-artifact-api.md)；它已替代批量入口中的结构化卡顿个例。
