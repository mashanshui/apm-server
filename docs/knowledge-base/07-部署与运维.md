## 当前小规模部署拓扑

```text
一台开发机或云主机（Compose 五容器）
├─ Web / Nginx：Vue 静态资源、HTTP 80、同源代理
├─ Spring Boot：接收、管理、领域查询、附件清理
├─ PostgreSQL：管理数据、Session、符号表元数据和查询 Token
├─ ClickHouse：遥测事实、详情和聚合对象
└─ TypeScript MCP：独立只读查询服务，外部查询默认关闭
```

mapping 和 HPROF 保存在后端持久卷；Grafana 可独立安装，不随当前 Compose 默认启动。MinIO 未接入；HTTPS 和生产限流属于后续部署目标。

本地和小规模内测使用 Docker Compose。正式对外后，优先把 PostgreSQL 与 ClickHouse 放到独立磁盘或托管服务，再根据负载横向扩容 Spring Boot。

仓库中的 `compose.yaml` 用于本地 PostgreSQL 16；`compose.cloud.yaml` 提供云服务器的小规模部署形态，包括 PostgreSQL、ClickHouse、Spring Boot、Nginx/Vue 和 TypeScript MCP 五个容器，其中 ClickHouse 容器内存上限为 `2 GiB`。内存异常报告的 ClickHouse 增量表为 `006_memory_leak_reports.sql`，事件进程身份增量表为 `007_event_process_identity.sql`，二者都必须按版本顺序执行；附件默认位于独立持久卷，不通过静态资源暴露。Spring Boot 正常启动需要 PostgreSQL，Crash 存储按云端配置使用 ClickHouse。当前云端入口为 HTTP 80，尚未配置域名、HTTPS 证书或生产监控，不能把本次部署表述为正式生产就绪。当前云端仅用于调试，Compose 另外将 PostgreSQL 5432 和 ClickHouse HTTP 8123 映射到公网，供本地后端直接连接；切换到正式环境前必须删除公网数据库映射或改用内网/VPN。前端本地端口、开发代理和数据准备见[前端本地开发与联调](../../frontend/docs/knowledge-base/05-本地开发与联调.md)。

macOS 本地全栈可在仓库根目录使用以下脚本：

```bash
./scripts/start-dev.sh
./scripts/stop-dev.sh
```

启动脚本使用 `.env.local` 配置本地 PostgreSQL、ClickHouse、Spring Boot、Nginx/Vue 和 MCP，基于 `compose.cloud.yaml` 和 `compose.local.yaml` 启动并等待五个容器健康；MCP 外部查询默认关闭。覆盖文件把 5432、8123 和 Web 端口限制在 `127.0.0.1`；默认 Web 端口为 8088，可由 `.env.local` 中的 `WEB_PORT` 覆盖。默认复用已有的 `backend/build/libs` 和 `frontend/dist`；缺少产物或传入 `--build` 时重新构建。后端构建使用 macOS 的 JDK 21 或 `APM_JAVA_HOME`，并通过 `bash` 调用 Gradle Wrapper，避免仓库文件缺少可执行位时报 `Permission denied`；前端无本机 npm 时使用 Docker Node 22。`stop-dev.sh` 执行 Compose `down`，保留数据库、附件和符号表卷。独立运行后端/Vite 的方式见[前端本地开发与联调](../../frontend/docs/knowledge-base/05-本地开发与联调.md)。

启动前必须在 `.env.local` 持久配置 `APM_APP_KEY_ENCRYPTION_KEY=<Base64 编码的 32 字节随机值>`。可用 `openssl rand -base64 32` 生成一次；不得每次启动重新生成，必须备份且不能提交。还需配置 PostgreSQL、ClickHouse 的库名/用户/密码、`APM_DEVICE_HASH_SALT` 和引导管理员邮箱/密码。启动脚本会在启动外部服务前校验必需值及密钥格式。服务启动后先在网页创建输入唯一 Android application ID 的应用，再到设置页获取该应用 App Key 用于 Android 联调。

首次管理员创建是显式配置驱动且幂等的：不配置邮箱/密码不会自动创建账号，已存在的邮箱不会覆盖密码。完整接口和安全配置见[登录与项目管理 API](../api/app-api.md)。

## 云服务器部署形态

云端部署文件如下：

- `compose.cloud.yaml`：Web 容器映射 80 端口，调试阶段同时映射 PostgreSQL 5432 和 ClickHouse HTTP 8123 到公网；Spring Boot 仍只加入内部 Docker 网络。云厂商安全组还必须放行本地调试机到这两个 TCP 端口的入站访问。正式环境不得沿用数据库公网映射。
- `scripts/deploy-cloud.sh`：在 macOS 本地完成 Boot JAR/前端构建、最小部署包打包、SCP 上传和云端 Compose 更新；更新后由 Compose 等待 PostgreSQL、ClickHouse、后端、MCP 和 Web 健康，最长等待 10 分钟，超时输出 Compose 状态并失败退出；不运行自动化测试或业务验收。
- `docker/backend-runtime.Dockerfile`：使用部署前构建的 Spring Boot JAR，以非 root 用户运行，并持久化内存泄漏报告附件。
- `docker/frontend-runtime.Dockerfile` 与 `docker/nginx.conf`：提供 Vue history fallback，并将 `/api`、`/ingest` 同源代理到后端；上传请求体上限与后端内存报告边界保持一致。

部署前需要在具备内部 `rhea-trace-processor:1.0.2` Maven 制品的环境执行 `bootJar`，并执行前端 `npm run build`。MCP 使用 Node.js 24.19.x，在镜像内按锁文件安装依赖并构建。将 JAR、`frontend/dist`、MCP 源码/包清单/锁文件、ClickHouse 初始化脚本和上述部署文件传到服务器后，在部署目录使用：

```bash
sudo docker compose --env-file .env.cloud -f compose.cloud.yaml up -d --build
sudo docker compose --env-file .env.cloud -f compose.cloud.yaml ps
curl -fsS http://127.0.0.1/healthz
```

上述手工命令也可以由本地脚本完成。脚本不会上传 `.env.cloud`，不会删除 Docker 数据卷；更新后等待全部五个 Compose 容器健康，最长等待 10 分钟，但不执行自动化测试或业务验收：

```bash
./scripts/deploy-cloud.sh
```

脚本默认使用[SSH 连接说明](../cloud-ssh.md)中的主机和用户，私钥查找 `$HOME/.ssh/apm_cloud`，部署目录为 `/home/ubuntu/apm-server`；可通过 `--remote-host`、`--remote-user`、`--remote-port`、`--identity-file` 和 `--remote-directory` 覆盖。默认会执行 `bootJar` 和前端构建，不运行测试；`--skip-build` 只在已有最新 JAR 和 `frontend/dist` 时使用，远端 MCP 镜像仍按上传的源码构建。脚本的容器健康检查不代替业务验收；如需更完整的验收，仍需检查云端入口和业务接口。

`.env.cloud` 必须只保存在服务器并设置为 `600` 权限；至少配置数据库密码、ClickHouse 密码、`APM_APP_KEY_ENCRYPTION_KEY`、`APM_DEVICE_HASH_SALT` 和引导管理员账号。数据库密码和应用主密钥不得复用本地开发值。首次以 HTTP 访问时 `APM_SESSION_COOKIE_SECURE=false`；切换到 HTTPS 后必须改为 `true`，并在网关上保留 `/api`、`/ingest` 和 `/mcp` 同源代理。Compose 数据卷逻辑键为 `apm-postgres-data`、`apm-clickhouse-data`、`apm-memory-report-artifacts` 和 `apm-symbols`；实际 Docker 卷名由 Compose 项目名加前缀生成（默认项目名 `apm-server`）。更新镜像不应删除这些卷，切换项目名会使用另一组卷。

当前调试环境允许本地后端直接使用云端两个数据库：`APM_DATABASE_URL=jdbc:postgresql://124.221.252.121:5432/apm`，ClickHouse 使用 `http://124.221.252.121:8123`。本地 `.env.local` 只保存被 Git 忽略的连接参数和密码，不能复制到仓库或日志；这些地址只适用于单独运行后端并显式注入远程连接参数的调试方式。当前 `start-dev.sh` 固定启动本机全栈，Compose 为后端设置容器内 PostgreSQL/ClickHouse 地址，不会根据 `.env.local` 的远程 JDBC 地址跳过本地数据库；早期 PowerShell 直连记录不代表当前 macOS 脚本行为。

## 扩容顺序

1. 优化 Android 批次、服务端批量写入和 ClickHouse 表设计。
2. 将数据库迁移到独立资源或托管服务。
3. 横向扩容 Spring Boot 接收节点。
4. 需要削峰、回放或多消费者时加入 Kafka。
5. 接收与查询互相影响时拆分 `apm-ingest` 和 `apm-query`。
6. 多服务需要独立扩缩容、频繁滚动发布和复杂治理时再评估 Kubernetes。

## 故障与恢复关注点

- ClickHouse 不可用时，客户端队列能否保留并重试数据。
- PostgreSQL 是否能从备份恢复，恢复点目标需明确。
- 磁盘接近满载前是否提前告警。
- 数据 TTL 和归档是否按计划执行。
- 发布失败是否有可验证的回滚路径。
- 无数据究竟来自业务低谷、SDK 故障、接收故障还是入库故障。

### 2026-10-03 Skill 配置与升级
