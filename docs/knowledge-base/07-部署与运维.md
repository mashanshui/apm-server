# 部署与运维

## 第一版拓扑

```text
一台开发机或云主机
├─ Nginx：HTTPS、反向代理、限流
├─ Spring Boot：接收、管理、查询、后台任务
├─ PostgreSQL：事务数据
├─ ClickHouse：APM 原始和聚合数据
├─ Grafana：Dashboard 与告警
└─ MinIO：mapping、符号表和附件（按需）
```

本地和小规模内测使用 Docker Compose。正式对外后，优先把 PostgreSQL 与 ClickHouse 放到独立磁盘或托管服务，再根据负载横向扩容 Spring Boot。

仓库已提交 `compose.yaml`，目前用于启动本地 PostgreSQL 16；Nginx、HTTPS、ClickHouse、MinIO 和生产监控仍是目标部署形态。Spring Boot 正常启动需要 PostgreSQL，Crash 存储可按配置选择 ClickHouse 或显式的内存联调模式。前端端口、代理和数据准备见[前端本地开发与联调](../../frontend/docs/knowledge-base/05-本地开发与联调.md)。

本地开发可在仓库根目录使用 PowerShell 脚本：

```powershell
.\scripts\start-dev.ps1
.\scripts\stop-dev.ps1
```

启动脚本先读取被 Git 忽略的 `.env.local`（显式进程环境变量优先），再检查 Docker 并启动 PostgreSQL，默认使用 ClickHouse 模式启动 Spring Boot 和 Vite 前端；ClickHouse 密码通过安全提示或 `CLICKHOUSE_PASSWORD` 环境变量取得。`-StorageMode memory` 可切换 Crash 内存模式（管理库仍使用 PostgreSQL），`-NoFrontend` 可只启动后端。首次管理员可用 `-BootstrapAdminEmail`、`-BootstrapAdminDisplayName` 配合 `APM_BOOTSTRAP_ADMIN_PASSWORD`，或使用 `-PromptForBootstrapAdmin` 安全输入邮箱和密码；`APM_DATABASE_URL`、`APM_DATABASE_USERNAME`、`APM_DATABASE_PASSWORD` 可覆盖数据库连接。脚本在本地默认显式启用 Flyway，并将 Session Cookie 设为非 Secure、SameSite=Lax；生产环境必须覆盖为 HTTPS 安全配置。脚本状态和日志保存在被 Git 忽略的 `build/dev-services/` 下，启动超时会自动清理本次启动的进程。

启动前必须在 `.env.local` 持久配置 `APM_APP_KEY_ENCRYPTION_KEY=<Base64 编码的 32 字节随机值>`。可以用 `[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))` 生成一次；不得每次启动重新生成，必须备份且不能提交。启动脚本会在启动外部服务前校验其格式和长度。服务启动后先在网页创建输入唯一 Android application ID 的应用，再到设置页获取该应用 App Key 用于 Android 联调。

首次管理员创建是显式配置驱动且幂等的：不配置邮箱/密码不会自动创建账号，已存在的邮箱不会覆盖密码。完整接口和安全配置见[登录与项目管理 API](../api/app-api.md)。

## 二进制堆栈解析配置

完整 btrace 产物通过原始请求体同步解析，配置如下：

| 环境变量 | 默认值 | 运维含义 |
|---|---:|---|
| `APM_STACK_PARSER_MAX_ARTIFACT_BYTES` | `67108864` | 原始 `.rheajank.zip` 请求体上限；调高前必须同时验证 processor 限制、堆和临时磁盘 |
| `APM_STACK_PARSER_MAX_CONCURRENT_PARSES` | `2` | 单实例同步解析许可数；满载返回 503 和 `Retry-After` |
| `APM_STACK_PARSER_MAPPING_ROOT` | 空 | 应用级 ProGuard/R8 mapping 根目录；空值只允许不带 mapping 解析 |
| `RHEA_PROCESSOR_REPOSITORY_URL` | 空 | 构建时可选的受控 Maven 仓库地址；运行时无效 |

mapping 目录结构固定为 `<mapping-root>/<appId>/<buildId>.txt`，应由发布流程预置并只读挂载；当前没有 mapping 上传、版本管理或清理 API。服务端解析时会使用系统临时目录，不保存原始 ZIP 和完整报告；解析后同步写入卡顿事实与详情。processor 1.0.1 和真实 v3 fixture 的解析门禁，以及本地真实 HTTP 的 mapping、首次接受、重复、错误 Key/包名、v2 拒绝和重启验证均已通过；生产仍需从受控制品仓库获取该版本，并单独验证解析耗时、503 比例、JVM 堆、临时磁盘、数据库写入和并发容量。接口契约见[卡顿压缩包解析与落库 API](../api/stack-artifact-api.md)。

初始化 ClickHouse 时必须按顺序执行 `001_crash_schema.sql`、`002_jank_schema.sql`、`003_jank_sampling_quality.sql` 和 `004_application_identity_schema.sql`；004 只允许在受影响业务表为空时执行，旧质量列与旧项目结构不自动迁移。

## 必备运维能力

- HTTPS 证书管理。
- 环境变量或密钥服务管理敏感配置。
- PostgreSQL 定期备份与恢复演练。
- ClickHouse TTL、磁盘容量和慢查询监控。
- Spring Boot Actuator、JVM 与进程监控。
- 上报错误率、写入延迟、拒绝率和端到端数据延迟监控。
- 二进制堆栈解析耗时、繁忙拒绝率、JVM 堆和临时目录容量监控。
- 开发、测试和生产环境隔离。
- CI/CD 流程。
- 日志轮转与错误追踪。

## 服务健康基线

当前已配置并可使用：

```http
GET /actuator/health
GET /actuator/info
GET /actuator/metrics
```

当前没有 `/api/v1/ping` 自定义接口，也没有把 ClickHouse 注册为 Actuator 健康贡献者；ClickHouse 访问失败会在上报或查询请求中体现为存储错误。正式部署前需要补齐依赖健康状态、就绪/存活探针和告警。

Crash 质量指标已经注册到 Micrometer，包括 `apm_ingest_events_received_total`、`apm_ingest_events_rejected_total`、`apm_ingest_events_duplicate_total`、`apm_ingest_retryable_failures_total`、`apm_crash_denominator_insufficient_total`，以及上报/可见延迟 Timer。

卡顿接收还注册了 `apm_jank_events_received_total`、`apm_jank_events_accepted_total`、`apm_jank_events_rejected_total`、`apm_jank_events_duplicate_total`、`apm_jank_events_schema_rejected_total`、`apm_jank_events_algorithm_rejected_total`、按版本标记的 `apm_jank_schema_version_total`/`apm_jank_algorithm_version_total`、`apm_jank_visible_delay` 和 `apm_jank_fact_detail_inconsistency_total`。其中事实/详情不一致计数表示卡顿事实写入成功但详情写入失败的可观测故障，不代表已经完成自动补偿；重复和可见延迟的生产告警阈值仍待确认。

## 扩容顺序

1. 优化 Android 批次、服务端批量写入和 ClickHouse 表设计。
2. 将数据库迁移到独立资源或托管服务。
3. 横向扩容 Spring Boot 接收节点。
4. 需要削峰、回放或多消费者时加入 Kafka。
5. 接收与查询互相影响时拆分 `apm-ingest` 和 `apm-query`。
6. 多服务需要独立扩缩容、频繁滚动发布和复杂治理时再评估 Kubernetes。

## 故障与恢复关注点

- ClickHouse 不可用时，客户端队列能否保留并重试数据。
- PostgreSQL 是否能从备份恢复，恢复点目标需明确。
- 磁盘接近满载前是否提前告警。
- 数据 TTL 和归档是否按计划执行。
- 发布失败是否有可验证的回滚路径。
- 无数据究竟来自业务低谷、SDK 故障、接收故障还是入库故障。

ClickHouse 应用账号需要 `SELECT` 和 `INSERT` 权限；Grafana 应使用独立只读账号。当前 `apm.clickhouse.read-only-user` 只是配置约定，代码实际使用 `apm.clickhouse.username/password` 发起读写请求，部署时必须按最小权限配置并通过环境变量注入密码。

存储实现的条件开关实际由 `apm.storage.mode=memory|clickhouse` 控制；当前 `apm.clickhouse.enabled` 没有参与仓库 Bean 的条件选择，不能仅依赖它关闭 ClickHouse 访问，发布前应统一配置并补充启动校验。
