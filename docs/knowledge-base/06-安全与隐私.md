## 平台身份

| 身份 | 推荐机制 | 关键控制 |
|---|---|---|
| Android 上报端 | App Key + HTTPS + 限流；可选 Play Integrity | 永久 Key 与包名绑定、配额、大小限制、时间窗口、异常设备/IP |
| 网页用户 | Spring Security + Session + HttpOnly Cookie | CSRF、Secure、SameSite、角色、应用权限 |
| Agent 查询端 | 应用查询 Token + Bearer；当前 HTTP 调试，后续 HTTPS | 单应用 `apm:read`、30/90/365 天期限、按应用撤销和逐请求数据库鉴权；管理契约见[查询 Token API](../api/query-token-api.md) |
| Grafana 用户 | 独立登录或统一 OIDC | 组织、文件夹、Dashboard、数据源权限 |

APK 中的 App Key 可以被逆向，只能作为应用识别与配额控制手段，不能视作绝对安全的客户端秘密。

Agent 查询 Token 由应用 `OWNER`/`ADMIN` 通过网页 Session 和 CSRF 创建，仅在创建响应中出现完整值，列表只显示前缀。Token 与创建者后续角色独立，始终只绑定本应用；撤销完成后新请求立即失效，已完成认证的在途请求允许完成。后端 Agent 查询已覆盖现有 Crash、卡顿和内存 API，TypeScript MCP 提供 19 个查询工具；本地双应用真实数据、Inspector 和网页创建/撤销闭环已验收。2026-09-29 云端部署与无凭据入口拒绝已验收，有效 Token 的云端工具查询尚未验收。查询 Token 不用于上报、网页管理或符号表写入。

## 网页登录与授权

2026-10-04 登录认证后策略已接入，成功时轮换已有会话 ID 并立即刷新 CSRF Cookie；旧 ID 不恢复新身份，新 Cookie 搭配旧请求头拒绝写入。真实 PostgreSQL/HTTP 测试确认原依赖缺少 Boot 4 会话自动配置，现已补齐 JDBC starter，使用既有表。验证范围及 Cookie CSRF 历史 Token 边界见[登录 API](../api/app-api.md#会话与-csrf)；本轮尚未部署云端。

当前仓库使用 Spring Security、Spring Session JDBC 和 PostgreSQL。网页认证采用服务端 Session、HttpOnly Cookie、可配置 Secure/SameSite Cookie，并通过 `XSRF-TOKEN` Cookie + `X-XSRF-TOKEN` 请求头启用 SPA CSRF 防护；生产应设置 `APM_SESSION_COOKIE_SECURE=true` 并通过同源网关部署。OIDC、开放注册和找回密码尚未实现。

建议角色：

```text
Owner → Admin → Developer → Viewer
```

每次访问应用资源都必须在服务端执行：

```text
当前用户 → 是否属于目标应用 → 当前角色 → 是否有资源操作权限
```

应用列表、详情/修改、Crash/卡顿/内存网页查询、符号表和查询 Token 管理均执行服务端成员/角色校验；Agent 入口另按 Token 绑定应用授权。不能把前端路由、`X-App-Id`、`X-User-App-Ids` 或 Grafana 变量当作身份/成员证明。多服务、第三方登录或开放 API 成为明确需求后，再引入 OIDC/JWT。

## 默认禁止采集

- 完整 URL 查询参数。
- Cookie、Authorization 等敏感请求头。
- 请求体和响应体。
- 用户输入内容。
- 手机号、邮箱和明文用户 ID。
- 可直接识别个人的设备标识。

## 脱敏与最小化原则

- URL 转为 `/users/{id}` 等路径模板。
- 用户与设备标识使用按应用加盐的哈希。
- 对属性名和字段名使用白名单。
- mapping 文件、符号表和堆栈信息实施访问控制。符号表网页列表要求应用查看权限，上传/替换要求 `OWNER`/`ADMIN`；mapping 内容不通过下载接口返回，Crash 还原响应设置 `Cache-Control: no-store`。
- 日志不得输出完整上报 Key 或完整事件体。
- 明确原始数据与聚合数据的保留、删除和归档策略。
- 只采集能回答产品、排障或合规问题的数据。

以上是隐私目标，不能全部视为现有实现。当前 Crash、卡顿和内存采样使用部署级盐，不按应用派生；公共事件字段有白名单，`attributes` 只校验键格式并限制数量。内存异常报告 parser 保留 metadata 设备标识和受限 report 原始 JSON，不执行相同的文本模式脱敏。当前边界见[后端安全实现](../../backend/docs/knowledge-base/04-认证授权与安全实现.md#载荷保护与凭据实现)，按应用派生盐与报告脱敏属于[待确认事项](13-待确认事项.md#隐私处理与架构门禁)。

`processId`、`sessionId` 和 `anonymousDeviceId` 是客户端生成的关联标识，不是鉴权凭据；它们不能携带账号、手机号或可逆设备信息。Crash、卡顿和内存采样只对 `anonymousDeviceId` 做部署级盐哈希，`processId` 按 UUID v4 原值保存用于事件上下文，不能通过它绕过 `appId`、Session 或 App Key 隔离，也不提供身份关联查询。

## 多租户注意事项

- PostgreSQL 的所有业务资源必须关联租户或应用边界。
- ClickHouse 查询必须强制注入并校验应用范围。
- Grafana 对外使用时需采用真实的数据隔离能力，而不是仅隐藏变量。
- 越权测试必须包含 `appId` 枚举和跨应用事件详情访问。

## JVM Crash 脱敏与访问实现状态

当前查询 API 已使用登录主体和 PostgreSQL `app_member` 成员关系授权：所有角色可读取，只有 `OWNER`/`ADMIN` 可修改应用名称和描述，`DEVELOPER`/`VIEWER` 修改返回 403，无成员关系按 404 返回。`X-App-Id` 和 `X-User-App-Ids` 被忽略，不能伪造跨应用访问。Android 上报仍使用独立的 `X-App-Key`，不会把网页 Session 带入上报端。

前端只调用 Spring Boot 管理/查询 API，不接触 ClickHouse URL、用户名或密码。前端通过同源 Cookie 携带 Session，状态变更请求附加 CSRF Token；收到 401 时清理用户和应用状态并回到登录页。密码仅用于登录提交；Session/CSRF 使用现有 Cookie 流程；密码、Session 标识、CSRF Token 和 Android App Key 不写入 Web Storage、URL 或日志。App Key 仅可在设置页组件局部内存中按需短暂展示，退出或切换应用时清空。

## 卡顿载荷的安全边界

卡顿场景、堆栈类名/方法名和属性沿用服务端长度、格式、规范化和哈希边界；场景、采样数、字典规模、堆栈深度、总帧数、单事件和请求解压体积均有配置上限。`anonymousDeviceId` 使用部署级盐哈希后存储，详情 API 不还原客户端设备标识；指纹只使用规范化关键路径和稳定上下文，不把客户端指纹作为授权或身份事实。日志只保留事件 ID、错误类别和计数，不输出完整卡顿载荷、堆栈或设备标识。

## 二进制堆栈产物的安全边界

完整 App Key 只由 `OWNER`/`ADMIN` 通过禁止缓存接口按需读取；普通应用响应和鉴权投影不包含密文、摘要或 nonce。前端只在应用设置组件局部内存短暂持有 Key，并在应用切换、请求失败、会话失效和组件卸载时清空。Key 永久有效且当前不可轮换或撤销，因此不能被描述为可快速处置的强客户端秘密；更强身份需要另行引入签名证明或 Play Integrity。

## 应用查询 Token

应用查询 Token 与永久上报 App Key 隔离：管理员创建 30/90/365 天有效、只读、应用绑定的 Token，完整值仅创建响应展示一次；后端只存摘要。每次 Agent HTTP 请求重新认证，MCP 在每次 HTTP 请求预检且业务查询再认证。默认关闭外部查询和新 Token 发放；关闭后列表、撤销仍可由网页 Session 管理。当前 MCP 允许 HTTP 调试接入，不因缺少 HTTPS 拒绝请求；Bearer 经 HTTP 明文传输，须限制在受控环境，受信 HTTPS 网关是后续生产化任务。Token 不能放进上报 SDK、URL、日志或版本库。详见 [Token 管理](../api/query-token-api.md)。

### 2026-10-03 Skill 本地配置

Python 默认从可信 Skill 根目录 config.local.json 读取平台根地址和应用 Worker 凭据，宿主无需读取内容；含凭据文件必须归当前用户所有且权限仅本人可访问。固定配置路径、有界 JSON、字段/地址/凭据格式及权限检查在网络、任务领取和材料采集前完成；拒绝链接和特殊文件。凭据只在 Python 内存及白名单后台环境传递，不加入公开诊断、CLI 参数或持久状态；宿主和引用核对不得读取 config.local.json；不再创建源码快照。

原环境两项须成对整组覆盖，不混合不同地址/凭据。Git 忽略配置，导出固定生成空模板而不读取实际文件；升级按排除配置的解压命令保留，任意覆盖式解压无法由 ZIP 保证保留。步骤见[Skill 配置](../../agent-skills/apm-crash-analyze/README.md#最小配置)，验证见[本地配置验收](../analysis-validation/current-code-validation.md#skill-本地配置增量验收)。本机权限不构成对整个宿主的沙箱；真实凭据仍须限定应用、期限和可撤销。
