# 安全与隐私

## 三类身份

| 身份 | 推荐机制 | 关键控制 |
|---|---|---|
| Android 上报端 | 项目 Key + HTTPS + 限流；可选 Play Integrity | 密钥轮换、配额、大小限制、时间窗口、异常设备/IP |
| 网页用户 | Spring Security + Session + HttpOnly Cookie | CSRF、Secure、SameSite、角色、项目权限 |
| Grafana 用户 | 独立登录或统一 OIDC | 组织、文件夹、Dashboard、数据源权限 |

APK 中的项目 Key 可以被逆向，只能作为项目识别与配额控制手段，不能视作绝对安全的客户端秘密。

## 网页登录与授权

目标架构使用服务端 Session、HttpOnly Cookie、Secure Cookie、SameSite Cookie，并让前端与 API 使用同一域名，同时启用 CSRF 防护。当前仓库没有 Spring Security、Session 或 OIDC 依赖。

建议角色：

```text
Owner → Admin → Developer → Viewer
```

每次访问项目资源都必须在服务端执行：

```text
当前用户 → 是否属于目标项目 → 当前角色 → 是否有资源操作权限
```

不能信任前端或 Grafana 传入的 `projectId`。多服务、第三方登录或开放 API 成为明确需求后，再引入 OIDC/JWT。

## 默认禁止采集

- 完整 URL 查询参数。
- Cookie、Authorization 等敏感请求头。
- 请求体和响应体。
- 用户输入内容。
- 手机号、邮箱和明文用户 ID。
- 可直接识别个人的设备标识。

## 脱敏与最小化原则

- URL 转为 `/users/{id}` 等路径模板。
- 用户与设备标识使用按项目加盐的哈希。
- 对属性名和字段名使用白名单。
- mapping 文件、符号表和堆栈信息实施访问控制。
- 日志不得输出完整上报 Key 或完整事件体。
- 明确原始数据与聚合数据的保留、删除和归档策略。
- 只采集能回答产品、排障或合规问题的数据。

## 多租户注意事项

- PostgreSQL 的所有业务资源必须关联租户或项目边界。
- ClickHouse 查询必须强制注入并校验项目范围。
- Grafana 对外使用时需采用真实的数据隔离能力，而不是仅隐藏变量。
- 越权测试必须包含项目 ID 枚举和跨项目事件详情访问。

## JVM Crash 脱敏与访问实现状态

服务端对异常消息替换邮箱、URL、用户路径、手机号和 UUID，并截断字段；`anonymousDeviceId` 使用项目盐 SHA-256 保存，属性名采用白名单，测量值只保留数字。应用日志不输出请求体、异常消息、堆栈或完整上报 Key。当前事件模型拒绝未知 JSON 字段，且 `attributes` 默认最多保留 32 项。

当前查询 API 的开发期隔离要求 `X-Project-Id` 与路径项目一致；若提供 `X-User-Project-Ids`，路径项目还必须出现在逗号分隔的成员列表中，失败统一返回 404。若未提供成员列表，代码会只校验项目请求头而放行，因此这组请求头不是可信身份来源。这是空项目联调边界，不是最终身份认证；生产上线前必须替换为 Spring Security Session/OIDC 或等效的服务端成员权限。

当前配置通过 `APM_PROJECT_KEY`、`APM_DEVICE_HASH_SALT`、`CLICKHOUSE_PASSWORD` 等环境变量提供覆盖入口，但 `application.properties` 仍包含本地开发 fallback 值。生产发布前必须移除或替换所有 fallback 凭据，并验证密钥不会进入日志、镜像或版本库。
