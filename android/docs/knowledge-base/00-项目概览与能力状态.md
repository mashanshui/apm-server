## 项目定位

Performance 是 Android 性能工具与采集上报项目。`app` 提供演示页面，九个 `performance-*` Library 按职责提供 SDK、事件队列、网络通信及 Kotlin/JNI 工具。应用通过 `PerformanceSdk.initialize(application, appKey, config)` 显式启动全量 SDK；调用成功后，SDK 会按配置自动创建各个功能组件，以及主进程可用时的 Activity 泄漏检测器和 KOOM 监控。

当前重点链路为 JVM/Native Crash、Rhea Jank ZIP、场景 FPS、主进程内存指标，以及独立的 Activity 泄漏检测与 KOOM OOM 触发。泄漏检测不产生 `memory_sample` 事件，也不复用 PSS/VSS/Java heap 的指标队列。库中还保留 Looper 消息历史、超时抓栈、CPU 空闲检测、线程池、绑核与 GC Hook 等工具；它们是否被调用，需要沿实际入口确认。

## 范围与平台边界

- SDK 编译与发布依赖、Kotlin 元数据及构建工具兼容边界见[构建指南](11-构建测试与本地发布.md#kotlin-兼容与本地依赖)；实际版本以构建配置为准，历史通过记录不代替当前环境验证。
- Android Gradle 当前声明 `:app` 和九个 `performance-*` Library；服务端位于同一平台仓库的 `backend/`，Rhea 处理器源码不在本仓库。当前 Rhea 与 Processor 依赖以各工程构建配置为准。
- 各 Android Library 的 `minSdk=21`，示例应用的 `minSdk=23`；这不表示每项能力从相应最低版本起都可用。
- Native Tools 仍限定 `arm64-v8a`；Crash 自有 JNI 和 dumper 分别构建四种 ABI，宿主必须解压原生库。
- FPS 需要 API 24+、主进程与硬件加速 Window，且受 `jank.enabled && jank.fps.enabled` 控制。
- Activity 泄漏检测与 KOOM 联动只接受 Android API 21..36 的主进程；它受 `memoryLeak.enabled` 控制，不依赖 `memory.enabled`，不使用指标 Reporter 的持久队列，而是使用独立 report 队列；HTTP 请求不包含 HPROF。
- Jank 是否可用由 Rhea 初始化结果决定；预期平台降级不等于整个 SDK 初始化失败。有效产物必须携带 UUID v4 `processId` 和 `threadScope=main`，成功上传只认 HTTP 200。
- Crash 包含 JVM 与 Native 致命事件；ANR 由独立模块采集并可显式上传；非致命异常尚未接入 Crash 链路。Native SO 服务端还原的跨端验证及本地/云端部署状态见[平台状态](../../../docs/knowledge-base/00-当前实现与验证边界.md#环境最近核验)。
- CPU、GC 工具没有接入统一指标上传；内存运行峰值当前轮保留本地，下次进程启动封存补报。联合验收结论见平台状态页，设备功耗、跨 Android 版本和长周期后台行为按独立证据判断。
